# 06 页面清单

整理日期：2026-09-30。本章只写页面：入口、区块、按钮、弹层、落点、空状态、接口、订阅。业务规则见 03 章，界面状态和组件外观见 02 章，接口、操作码和推送主题见 05 章，这里不复述。本章列的页面文案（空状态、报错、提示）在代码里统一放进 `shared/copy`，本章是它们的出处。

## 1. 约定

- 按钮只看后端 `actions`（00 章第 1 节、05 章第 1.5 节）。本文写「按钮 Y（`X`）」表示 `actions` 里有 `X` 时显示 Y：`enabled: false` 时显示禁用，下方写 `disabledReason`；点了以后要不要原因框看 `reasonRequired`。`lockedReason` 有值时在状态区显示。页面本地条件（没勾选、购物车为空）才由前端禁用。
- 金额、上限、库存只显示后端返回的 `xxxCents`、`maxQty`、`stockQty` 等；表单里的行金额、合计、差异是输入预览（00 章第 1 节）。
- 能进哪些模块、「我的」有哪些入口、登录落点，按当前账号的 `modules`、`menus`、`landing`（05 章第 2 节）。
- 层级：一级页面没有返回，底部标签用 `wx.reLaunch` 切换；二级页面左上角返回，回到上一页并恢复筛选和滚动位置。管理员和多模块员工的模块首页是二级。
- 加载、空、断网、报错、无权限、找不到、状态过期、放弃修改、提交中、实时提示都按 02 章第 5 节，本文每页只写本页的空状态文案和报错文案。总表「表单」列标了的页面有放弃修改确认。
- 推送主题和权限见 05 章第 12.2 节，收到变更后的界面处理见 02 章第 5.4 节。各页「订阅」只列主题。
- 状态码见 04 章，页面上用 `shared` 状态表里的中文名。

### 1.2 列表级按钮

列表级按钮由列表接口顶层的 `actions` 返回（05 章第 1.5 节「列表级操作码」），写法同第 1 节，例如「新建订单」（`create`）。新建售后（X5，`createAfter`）、申请售后（S7，`applyAfter`）也是列表级操作码，和订单详情里的同名操作码进同一个页面；从订单详情进时带上这张订单。

## 3. 主包

### M1 登录

- 入口：没有绑定账号时打开任何页面；退出登录后。
- 区块：品牌背景整屏（`hz-cover` `full`，下部渐亮到墙色）→ 上部 logo → 下部隐私协议勾选（「我已阅读并同意《花众小程序隐私保护指引》」，点书名号部分打开微信隐私保护指引）→「手机号快速验证登录」。没勾选时点按钮的表现见 03 章第 8.5 节，提示写在按钮上方的 `hz-error`。
- 小程序启动先进本页：已绑定就按 `landing` 直接 `reLaunch`，不显示登录区；账号停用显示 02 章第 5.3 节的停用状态（「退出登录」调解绑，之后回到登录区）。
- 落点：按 `landing`。从分享卡片进来的，登录后回 M2 继续。
- 报错：按 05 章 `POST /auth/bind-phone` 返回的 `message`；用户在微信授权框里点了拒绝，不报错，留在本页。
- 接口：手机号登录绑定、当前账号。

### M2 链接落地

- 入口：分享卡片（第 11 节）。供应商填报邀请：没登录先去 M1，登录后回来；解析成功后 `redirectTo` 目标页。
- 门店下单邀请不经过 M1，本页按 `GET /store-invites/:token` 依次判断：`binding` 为 `self` → 直接 `reLaunch` 到 S1（不管邀请是否已失效）；邀请不是待使用 → 失效（下一条）；`other` → 整页状态「这台微信已登录{boundLabel}，请先在「我的」退出登录再接受邀请」+「去我的」；`none` → 花众字标 +「邀请你在线订货」+ 门店名（`storeLabel`）+ 隐私勾选 +「手机号快速验证登录」（隐私没勾选同 M1），验证成功 `reLaunch` 到 S1。
- 失效：整页状态（02 章第 5.4 节「分享链接失效」），原因用后端返回的句子。
- 接口：解析分享链接。

### M3 花众首页

- 区块：花众字标 → 身份行（岗位 · 名字，右边日期）→ 两列入口卡（图标、模块名、箭头，按 `modules`；个数为单数时最后一张占整行）。不显示待办。
- 接口：当前账号。

### M4 我的（员工）

- 区块：身份 → 按 `menus` 列入口（库存查询、操作日志、员工与岗位）→ 个人资料（弹层，只读：名字、岗位、登录手机号）→ 退出登录（次按钮，弹层确认）。开发环境最下面多一个「组件总览」。
- 落点：退出登录后进 M1。
- 接口：当前账号、解绑微信。订阅 `account:<id>`。

### M5 库存查询

- 搜索（名称、编码）+ 分类筛选。一条一张卡：花材 + 库存数量和单位（关键数字，加粗；库存 0 照常次要色）；编码 · 分类；停用的标「已停用」。只读，不能点开（2026-10-03 确认）。
- 空状态：「暂无符合条件的库存」。
- 接口：库存列表。订阅 `stock`。

### M6 操作日志

- 员工只列自己做的非公共操作，调岗后仍能看自己的原模块历史日志；管理员列全部（2026-10-02 梳理确认，交叉审查补充）。
- 筛选：模块（`GET /logs` 返回的 `filterModules` 多于一项时才显示，不取当前岗位的 `GET /me.modules`）、日期。按天分组（组头「10-03 周六」，02 章第 7 节）；卡片：操作 · 单号或对象、模块（公共日志写「公共」）、时:分 · 操作人。点开弹层（2026-10-03 确认）：先写操作 · 对象和「时间 · 操作人 · 模块」→ 原因 →「改动」只列修改前后不一样的字段（「字段　旧 → 新」）；只有修改后的（新增类）列「修改后」全部字段，只有修改前的列「修改前」全部字段。
- 空状态：「暂无操作日志」。
- 接口：日志列表、日志详情。

### M7 员工与岗位

- 列表：名字、岗位（多个用「、」连）、启用状态。底栏「新增员工」（`create`）。
- 弹层（短表单，分三组、细线隔开，2026-10-03 确认）：名字、登录手机号 / 管理员开关、模块多选（管理员开关打开时隐藏）/ 启用、微信（这一组新增时不显示）。「微信」一行只在 `actions` 含 `unbindStaffWechat` 时出现：「已绑定」+ 文字按钮「解绑微信」（确认后解绑，弹层留着）。弹层底部只有「保存员工」。
- 报错：「请填写名字」「请填写 11 位登录手机号」「这个手机号已经被其他账号使用」「请至少选一个模块」「至少要保留一个启用的管理员」「没有修改内容」。
- 落点：保存后关弹层，留在列表。
- 接口：员工列表、新建员工、修改员工。

### M9 组件总览

- 只在开发环境，从 M4 进。按 02 章第 4 节把所有组件和状态排在一页。

## 4. 门店端（store）

底栏「首页 / 购物车 / 我的」，购物车标签显示件数（本地购物车：按账号存在这台手机上，退出登录清空；客户停用时照常显示）。订货、订单、售后、对账从门店首页进。

### S0 门店首页

- 入口：登录落点；底栏「首页」。
- 区块：花众字标 → 身份行（客户 · 门店 · 联系人，右边日期）→ 主卡「订货」（下面一行「今日可订 n 款」，n 为 `orderableCount`）→ 一排三张小卡：订单、售后、对账。不显示待办数。
- `lockedReason` 有值（客户停用）：身份行下面用 `hz-notice` 显示它，「订货」卡变灰不能点；订单、售后、对账照常。
- 落点：订货 → S1；订单 → S3；售后 → S7；对账 → S9。
- 接口：门店首页。订阅 `catalog:<customerId>`。

### S1 订货

- 入口：S0「订货」；S6「修改订单」进入改单模式（隐藏底部标签，只显示结算条，用单独一份购物车）。
- 区块：顶部「客户 · 门店」、下单日期（改单时是原订单日期）、可订款数、搜索（跨分类）→ 左侧订货分类（这个客户的，2026-10-03 确认）+ 右侧产品（图、名、客户产品编码、价、步进器）→ 购物车条（金额、件数、去结算；点图标弹出明细，可改数量、清空）。
- 去结算：购物车为空时禁用（改单时只剩已停用产品也能进）。
- 打开时购物车里有已不在目录里（停用）的产品：从购物车去掉，用 toast 提示一次「白绿清新花束已停用，已从购物车移除」（多个用「、」连）；改单模式不去掉，到结算页标「已停用」。
- 空状态：「暂无可订产品」；搜索没结果「暂无相关产品」。
- 落点：去结算 → S5；改单模式返回 → S6，原购物车不变。
- 接口：订货目录。订阅 `catalog:<customerId>`。

### S2 购物车

- 购物车行（改数量、删除）→「清空」→ 结算条。
- 打开时去掉停用的产品，提示同 S1。客户停用（`GET /store/home` 的 `lockedReason` 有值）：顶部 `hz-notice` 显示它，「去结算」禁用；购物车照常能改、能清空。
- 空状态：「暂无已选产品」。落点：去结算 → S5。
- 接口：门店首页、订货目录（核对停用）。订阅 `catalog:<customerId>`。

### S3 订单

- 入口：S0「订单」。筛选：状态、下单日期。三行卡片。
- 空状态：「暂无订单」。
- 接口：本店订单列表。订阅 `orders`。

### S4 我的（门店）

- 区块：身份卡（联系人、客户门店、登录手机号）→ 个人资料（弹层，只读）→ 退出登录。

### S5 结算（表单）

- 入口：S1、S2 去结算。
- 区块：状态区 → 下单日期、客户门店 → 备注 → 明细（`discontinued: true` 的行标「已停用」+ 垃圾桶）→ 订单金额。没有出货日期（由销售确认时定，阶段 3 确认），页面不写规则说明。
- 底栏：「提交订单」；改单时「确认修改」。
- 报错：「白绿清新花束已停用，请先删掉再提交」（按实际产品名）「销售已确认，门店不能再修改，请联系销售」「订单已被取消，不能再修改」「这个客户已停用，不能再下新单，请联系花众」「这个客户已停用，不能再修改订单，请联系花众」「请先选择产品」。
- 落点：提交后进 S6，购物车清空；改单提交后进 S6，原购物车恢复。放弃修改时备注不保留，购物车还在。
- 接口：提交订单、修改订单（门店）。改单时订阅 `order:<id>`。

### S6 订单详情

- 区块：状态区 → 单号、状态、下单日期、出货日期（只读，待确认时写「待销售安排」）、备注 → 明细（已发货的行标「少发」「多发」）→ 订单金额或发货金额 → 发货备注 → 收款核销（已发货时，每条「MM-DD 付款 ¥…」）→ 取消申请（有记录时：状态、门店原因、拒绝原因、时间；申请处理前已发货的写「已发货，取消申请未处理」）→ 变更记录 → 原因行（取消原因、作废原因）。
- 底部操作区：「取消订单」（`storeCancel`，次）、「申请取消」（`requestCancel`，次）、「撤回申请」（`withdrawCancel`，次）、「修改订单」（`storeEdit`）、「申请售后」（`applyAfter`）。禁用时下方写 `disabledReason`（客户停用、过了售后申请期限）；被拒绝后不出 `requestCancel`，下方写 `lockedReason`。
- 弹层：取消订单（原因弹层，按 `storeCancel` 的 `reasonRequired`）；申请取消（原因选填，底部「提交申请」）；撤回申请（确认弹层）。
- 落点：取消、申请、撤回后留在本页；修改 → S1 改单模式；申请售后 → S8。
- 接口：订单详情、取消订单（门店）、申请取消、撤回取消申请。订阅 `order:<id>`。

### S7 售后

- 从 S0 进。筛选：状态、提交日期。三行卡片：金额 `amountCents` 为 `null` 时，待处理写「待确认」，已关闭、已作废写「—」。
- 底栏「申请售后」：弹层只列 `actions` 含 `applyAfter` 且 `enabled: true` 的订单（过了申请期限的不列）→ S8。
- 弹层：售后详情（只读）：产品、问题原因、说明、图片、状态、售后金额、原因行。
- 空状态：「暂无售后」。
- 接口：本店售后列表、售后详情、可申请售后的订单。订阅 `afters`。

### S8 申请售后（表单）

- 入口：S6、S7。
- 区块：原订单、出货日期 → 明细（数量上限 `maxQty`，标「最多 n」；问题原因、问题说明、图片）→「添加产品」（这张单的产品）。
- 底栏「提交售后」。
- 问题原因选「花材损坏」「品质问题」时图片标必填（2026-10-02 梳理确认）。
- 报错：「请添加售后产品」「售后数量须大于 0，且不超过实发数量减去已申请的售后」「请填写每项产品的问题说明」「花材损坏、品质问题请至少上传 1 张图片」（写在对应行的图片下）。
- 落点：提交后进 S7，并打开这张售后的详情弹层。
- 接口：可申请数量、上传签名、提交售后（门店）。

### S9 对账

- 从 S0 进。筛选：出货日期（默认全部）。对账格：发货金额 `shippedCents`、售后 `afterCents`、已付 `paidCents`、待付 `unpaidCents`（按筛选区间）。
- 列表：本店发货单三行卡片（状态 `payStatus`；部分付写「未付 ¥…」）。点开 → S6（看核销记录）。不显示预收。
- 空状态：「暂无发货单」。
- 接口：门店对账。订阅 `ar:<customerId>`。

## 5. 供应商端（supplier）

底栏「首页 / 填报 / 我的」，填报标签显示待填报数。采购单、对账从供应商首页进。

### P0 供应商首页

- 入口：登录落点；底栏「首页」。
- 区块：花众字标 → 身份行（供应商 · 联系人，右边日期）→ 主卡「填报」（右上角待填报数，下面一行「n 份邀请待填报」，没有待填报时只写「填报」）→ 一排两张小卡：采购单、对账。
- 落点：填报 → P1；采购单 → P2；对账 → P5。
- 接口：底栏角标（待填报数）。订阅 `todo:*`。

### P1 填报

- 筛选：状态。三行卡片：邀请日期 + 状态；花材 + 需求合计；采购员，已提交的写生成的采购单号和它现在的状态。
- 点开 → P4。
- 空状态：「暂无邀请」。
- 接口：本家邀请列表。订阅 `supplier:<supplierId>`。

### P2 采购单

- 筛选：状态。三行卡片同 C3。
- 弹层：采购单详情：下单日期、采购员、来源（我的填报 · 邀请号 / 花众采购下单）、明细（采购数量、实收、退货）、付款记录（每条「MM-DD 付款 ¥…」）、变更记录、改价记录、退货记录、原因行（取消、作废原因）、收货时间；不显示 `lockedReason` 等仓库 / 财务内部提示（阶段 4 确认）。本家填报生成、待收货的单底部有「取消采购单」（`supplierCancelPo`，次，原因弹层）、「修改采购单」（`supplierEditPo` → P6）（2026-10-02 梳理确认）。
- 空状态：「暂无采购单」。
- 接口：本家采购单列表、采购单详情（供应商）、供应商取消采购单。订阅 `supplier:<supplierId>`。

### P6 修改采购单（供应商，表单）

- 入口：P2 详情「修改采购单」。2026-10-02 梳理确认。
- 区块：状态区 → 单号、来源邀请 → 明细（花材、数量、单价，右侧垃圾桶）→「另报花材」（启用的）→ 多行才显示合计 → 修改原因（选填）。
- 底栏「保存修改」。
- 报错：「请至少保留一种花材」「数量须为大于 0 的整数」「请填写单价，赠送的花材填 0」「没有修改内容」「仓库已收货，不能再修改」（`STALE`，刷新后变只读）。
- 落点：保存后回 P2 并打开这张单的详情弹层。放弃修改按 02 章第 5 节。
- 接口：采购单详情（供应商）、启用花材、供应商改单。订阅 `po:<id>`。

### P3 我的（供应商）

- 区块：身份卡（联系人、供应商、登录手机号）→ 个人资料（弹层，只读）→ 退出登录。

### P4 填报表单

- 入口：P1、分享卡片（经 M2）。
- `actions` 含 `submitSupply` 时是表单：邀请号、采购员、日期 → 明细（需求量只读；供货量默认等于需求量；单价）→「另报花材」→ 多行才显示「合计 ¥… · 共 n 枝」。已停用行标警告「已停用」，数量与单价只读，只能删行；供应商删除即可提交（阶段 4 确认）。底栏「提交填报」（`submitSupply`）。
- 否则只读：已提交时需求与供货合成一张「花材明细」，每行①名称 + 次要色「需求 n 枝」+ 金额靠右，②「供 n 枝 × ¥…」；邀请里没供的行写「未供」，另报行标「另报」。头部一行可点「采购单 PO-… · 采购单状态」，不另列「状态」或底部重复链接。已取消时原因行显示取消原因 / 自动取消说明、取消时间（阶段 4 确认）。
- 报错：「供货量须为大于 0 的整数，不供的花材请删掉这一行」「请填写单价，赠送的花材填 0」「请至少保留一种花材；全部不供请联系采购取消邀请」。
- 落点：提交后留在本页，变成只读，成功提示「已提交」。
- 接口：邀请详情（供应商）、启用花材、提交填报。订阅 `invite:<id>`。

### P5 对账

- 从 P0 进。筛选：付款状态、收货日期（默认全部）。列表保留应付大于 0 的有效单据，包括未付、部分付、已付；不等同于待付款列表。对账格：应付 `payableCents`、已付 `paidCents`、待付 `unpaidCents` 随单据筛选，下面单独一行「预付 ¥…」（大于 0 才显示，始终是本供应商当前全账余额）；有退款记录时列「退款记录」（退款号、日期、金额、状态），已作废的明确标记，不计入余额。退款历史不被单据收货日期筛选截掉。阶段 4 列表只显示采购单；手工入库单详情阶段 5 接入（阶段 4 确认）。
- 点采购单 → P2 的采购单详情弹层；手工入库单入口阶段 5 接入。
- 空状态：「暂无应付单据」。
- 接口：供应商对账（只含采购单）；入库单详情（供应商）阶段 5 接入。订阅 `ap:<supplierId>`。

## 6. 销售（sales）

### X1 销售首页

- 模块首页。入口：销售订单、客户门店、产品管理、订货目录、客户售后。待办：待确认订单、待处理售后。空状态「暂无待办」。订阅 `todo:sales`。

### X2 销售订单

- 搜索（单号、客户、门店）+ 筛选：状态（含「申请取消」，带数量）、客户、下单日期。三行卡片；有待处理取消申请的卡片标「申请取消」（不进首页待办，2026-10-02 梳理确认）。
- 底栏「新建订单」（`create`）。
- 空状态：「暂无订单」。
- 接口：订单列表。订阅 `orders`。

### X3 订单详情

- 区块：状态区（有待处理的取消申请时 `hz-notice`「门店申请取消：原因…」）→ 单号、状态、来源 → 客户门店、下单日期、出货日期（待确认时写「待销售安排」）、备注 → 明细（`discontinued: true` 的行标「已停用」；已发货的行标「少发」「多发」）→ 金额 → 发货人、发货时间、发货备注 → 取消申请记录 → 变更记录 → 原因行（取消、作废原因）。
- 底部操作区：「取消订单」（`cancel`，次）、「拒绝取消」（`rejectCancel`，次）、「同意取消」（`approveCancel`）、「修改并确认」（`editAndConfirm`，次）、「确认订单」（`confirm`）、「修改订单」（`edit`）、「作废订单」（`voidOrder`，次）、「新建售后」（`createAfter`）。禁用时下方写 `disabledReason`（例如不是归属人「这张单由 … 经办，请找管理员」、有核销「已有收款核销，请先由财务撤回」）。
- 弹层：
  - 确认订单：出货日期（`hz-picker` 日期，默认今天往后 `SHIP_DATE_DEFAULT_OFFSET_DAYS` 天，可以选以前）→「确认订单」。报错「请选择出货日期」。
  - 取消订单，按 `cancel` 的 `reasonRequired`：false 时一句确认，true 时原因框。弹层开着时订单被确认，提交返回 `STALE`，按 `latest` 里 `cancel` 的 `reasonRequired` 换成原因框。
  - 同意取消：一句确认「同意后订单变成已取消」；拒绝取消、作废订单：原因弹层（报错「请填写拒绝原因」「请填写作废原因」）。
- 落点：确认、同意、拒绝、作废后留在本页；修改、修改并确认 → X4；新建售后 → X7。
- 接口：订单详情、确认订单、取消订单、同意 / 拒绝取消申请、作废订单。订阅 `order:<id>`。

### X4 订单表单

- 三种模式：新建（从 X2）、修改（`edit`）、修改并确认（`editAndConfirm`）。
- 区块：状态区 → 客户、门店（只在新建时可选，只列启用的）→ 出货日期（新建、修改并确认时默认今天往后 `SHIP_DATE_DEFAULT_OFFSET_DAYS` 天，可以选以前）→ 备注 → 明细（新加的行单价默认 `listPriceCents`，原有行保持原单价；`discontinued: true` 的行标「已停用」+ 垃圾桶）→「添加产品」（只列这个客户目录里启用的产品）→ 订单金额 → 修改原因（修改、修改并确认时显示）。
- 底栏：新建「确认订单」；修改「保存修改」；修改并确认「修改并确认」。
- 报错：「请选择客户和门店」「请选择出货日期」「请添加产品并填写有效数量」「请填写修改原因」「白绿清新花束已停用，请先删掉再保存」（按实际产品名）。
- 落点：新建后回 X2；修改、修改并确认后回 X3。
- 接口：客户门店、订货目录、新建订单、修改订单。修改时订阅 `order:<id>`。

### X5 客户售后

- 筛选：状态、客户、提交日期。三行卡片：金额 `amountCents` 为 `null` 时写「—」。
- 底栏「新建售后」：弹层只列 `actions` 含 `createAfter` 的订单 → X7。
- 空状态：「暂无售后」。
- 接口：售后列表。订阅 `afters`。

### X6 售后详情

- 区块：状态区（已处理时 `notice`「发货单应收已减去售后金额」）→ 单号、状态、来源 → 客户门店、原订单 → 售后产品（原因、说明、图片直接展开）→ 售后金额 `amountCents` → 处理说明 → 原因行。
- 底部操作区：「关闭售后」（`closeAfter`，次）、「处理售后」（`processAfter`）、「作废售后」（`voidAfter`，次；只有处理它的销售可点，其他人禁用并写 `disabledReason`）。
- 弹层：关闭售后、作废售后（原因弹层；作废报错「请填写作废原因」）。
- 落点：关闭、作废后留在本页；处理 → X7。
- 接口：售后详情、关闭售后、作废售后。订阅 `after:<id>`。

### X7 售后表单

- 两种模式：处理（`processAfter`，从 X6）、新建（从 X3、X5）。
- 区块：原订单、客户门店 → 明细（数量上限 `maxQty`；单价默认 `shipPriceCents`）→ 售后金额合计 → 处理说明（选填）。新建模式有「添加产品」和垃圾桶；处理模式（门店提交的售后）不能增删行，只改数量和单价，门店填的原因、说明、图片只读（阶段 3 确认：销售新建的售后建好就是已处理，不能再改）。新建模式每行：数量、单价、问题原因（必选）、问题说明（选填），没有图片。
- 底栏「保存售后」。

- `actions` 含 `receive` 时是表单：状态区 → 供应商、采购员、下单日期 → 变更记录 → 明细（采购数量、实收（默认等于采购数量）、单价；和采购数量、原单价不同时标「少收 n」「多收 n」「改价 ¥a → ¥b」）→ 多行显示「合计 ¥… · 共 n 枝」（单行不重复金额）→ 改价原因（改了单价时显示）→ 备注。底栏「确认收货」（`receive`）。
- 否则：状态区 → 明细（采购数量、实收、退货）→ 采购金额 `amountCents`、应付金额 `payableCents`（相等也都显示）→ 财务状态 `apStatus`（未付 / 部分付 / 已付 / 无需付款）→ 变更记录、改价记录、退货记录 → 原因行（取消、作废原因）。
- 底部操作区：「作废」（`voidPo`，次）、「退货」（`return`，次）、「改单价」（`reprice`）。付款后照常能退货、改价（2026-10-02 梳理确认）。
- 弹层：退货（每行名称同列「可退 n 枝」，数量上限 `maxReturnQty`，底部「确认退货」）；改单价（逐行改单价 + 原因，底部「确认改价」）；作废（原因弹层，说明「库存按净实收扣回」；报错「请填写作废原因」「已有付款核销，请先由财务撤回」「库存不够，不能作废」）。字段校验只在字段下显示，不在页面或弹层顶部重复，不带重试（阶段 4 确认）。
- 报错：「改了单价，请填写改价原因」「请填写改价原因」。
- 落点：确认后留在本页，成功提示「已收货」或「已拒收」；退货、改价后关弹层。
- 接口：采购单详情（仓库）、确认收货、退货、改单价。订阅 `po:<id>`。

## 10. 财务（finance）

### F1 财务首页

- 模块首页。入口：客户对账、供应商对账、收付款记录、收付款方式。待办：待付款单据、预收待核销的客户。空状态「暂无待办」。订阅 `todo:finance`。

### F2 客户对账 / F3 客户对账详情

- F2：客户卡片：客户名 + 未收 `unpaidCents`；发货金额 `shippedCents` · 已收 `receivedCents`；`prepaidCents` 大于 0 时写「预收 ¥…」。空状态「暂无客户」。
- F3：筛选：收款状态、出货日期（默认全部）。对账格（`shippedCents`、`afterCents`、`receivedCents`、`unpaidCents` 按筛选区间，另行「预收（未核销）」`prepaidCents` 是当前余额）→ 发货单三行卡片（状态 `payStatus`）。空状态「暂无已发货订单」。
- 底部操作区：「核销预收」（`allocate`，次）、「登记收款」（`registerReceipt`）→ F4。
- 弹层（同一个弹层里切换，左上角返回上一层）：
  - 发货单：发货金额、每条售后（可点）、应收、已收、未收 → 核销记录（收款号可点）。标题「SO-… · 部分收」，售后抵扣的加「（售后抵扣）」。
  - 售后详情：通过专用 `GET /finance/afters/:id` 读取同 X6 的只读内容，`actions: []`；兼有销售权限或管理员也没有操作按钮，操作要回销售模块（2026-10-02 梳理确认，交叉审查补充）。
  - 收款详情：金额、方式、日期、备注、状态 → 核销明细（每行发货单号、登记核销金额 `registeredCents`、当前有效金额 `effectiveCents`、有效 / 已撤回状态；金额为 0 的有效核销也保留。右侧「撤回」只由该记录的 `revokeAllocation` 控制，已撤回的写原因、操作人、时间，不再有撤回按钮）→ 预收 → 退款记录（完整 `refunds` DTO，含退款号、日期、金额、方式、备注、状态、版本；点开由 `voidRefund` 控制「作废退款」，提交版本和原因；已作废的保留原因、操作人、时间）；底部「登记退款」（`refundReceipt`，次）、「作废收款」（`voidReceipt`）→ 原因弹层（报错「请填写作废原因」「请先作废这笔的退款」）。作废后写「已作废，核销已撤回。」，保留原核销及撤回历史。
  - 登记退款：退款日期（默认今天，不能选以后）、金额（上限这笔预收，「全部」填入）、付款方式、备注 →「确认退款」。报错「这笔最多可退 ¥…」「退款日期不能晚于今天」。退款方式、登记收款、登记付款的方式都从同一份收付款方式里选启用的（2026-10-03 确认：收付款方式合并成一份）。
- 对账格下面有退款记录时列「退款记录」，有效、已作废都保留并标状态；余额仅算有效退款，不被发货单日期筛选截掉。
- 接口：客户对账列表、客户对账详情、发货单应收、收款详情、作废收款、撤回核销、登记退款、作废退款。订阅 `ar:<customerId>`、`receipt:<id>`。

### F4 登记收款 / 核销预收（表单）

- 入口：F3（默认这个客户）。
- 登记收款：客户、收款日期（默认今天，能选以前，不能选以后）、金额、收款方式、备注 → 核销明细（每张未收发货单按出货日期从早到晚：`unpaidCents`、本次核销、「填入」）→ 汇总「本次核销 ¥… / 转为预收 ¥…」。填好金额后按出货日期从早到晚自动填入核销（每张取 `unpaidCents` 和剩余金额较小的一个），财务可以改；「填入」取 `unpaidCents` 和「收款金额 − 已填核销」中较小的一个（2026-10-02 梳理确认）。
- 核销预收：客户 →「可用预收 ¥…」（`prepaidCents`）→ 核销明细，同样默认自动填入，可改。
- 底栏：「确认收款」/「确认核销」。
- 首次读取未收清单时保存全账 `ledgerToken` 和所有候选单据的 `expected`（类型、ID、版本、当时未收），提交带上；纯预收登记可不选单据。实时通知只提示变化，不覆盖编辑。`STALE` 时保留客户、收款日期、金额、方式、备注，读取最新未收与令牌，失效的核销分配先撤下；展示新旧差异，由用户重新填入或调整后再次确认，不静默重试。
- 报错：「SO-0927-026 最多核销 ¥2,100.00」（按实际单号和未收）「可用预收只有 ¥548.00」（按实际）「请填写收款金额」「请选择收款方式」「收款日期不能晚于今天」；`STALE` 提示「发货单金额有变化，已刷新，请核对后再确认」。
- 落点：保存后回 F3。
- 接口：未收发货单、可用预收、登记收款、核销预收。订阅 `ar:<customerId>`。

### F5 供应商对账 / F6 供应商对账详情

## 11. 分享卡片

用 `onShareAppMessage` 发小程序卡片，只在弹层里的分享按钮触发，不开右上角菜单分享。有效期、作废、失效条件见 03 章第 8.1、8.2 节。

| 卡片 | 从哪发 | 路径 | 打开后 | 标题 |
|---|---|---|---|---|
| 供应商填报邀请 | C6「填报链接」 | `pages/link/index?t=invite&id={邀请号}&sig={签名}` | 供应商登录后进 P4 | 花众采购邀请你填报供货 |

- 打开失败时按 M2。邀请已提交的，M2 多一个「查看填报」进 P4 只读。
