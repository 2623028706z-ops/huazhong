# 06 页面清单

整理日期：2026-09-30。本章只写页面：入口、区块、按钮、弹层、落点、空状态、接口、订阅。业务规则见 03 章，界面状态和组件外观见 02 章，接口、操作码和推送主题见 05 章，这里不复述。本章列的页面文案（空状态、报错、提示）在代码里统一放进 `shared/copy`，本章是它们的出处。

## 1. 约定

- 按钮只看后端 `actions`（00 章第 1 节、05 章第 1.5 节）。本文写「按钮 Y（`X`）」表示 `actions` 里有 `X` 时显示 Y：`enabled: false` 时显示禁用，下方写 `disabledReason`；点了以后要不要原因框看 `reasonRequired`。`lockedReason` 有值时在状态区显示。页面本地条件（没勾选、购物车为空）才由前端禁用。
- 金额、上限、库存只显示后端返回的 `xxxCents`、`maxQty`、`stockQty` 等；表单里的行金额、合计、差异是输入预览（00 章第 1 节）。
- 能进哪些模块、「我的」有哪些入口、登录落点，按当前账号的 `modules`、`menus`、`landing`（05 章第 2 节）。
- 层级：一级页面没有返回，底部标签用 `wx.reLaunch` 切换；二级页面左上角返回，回到上一页并恢复筛选和滚动位置。管理员和多模块员工的模块首页是二级。
- 加载、空、断网、报错、无权限、找不到、状态过期、放弃修改、提交中、实时提示都按 02 章第 5 节，本文每页只写本页的空状态文案和报错文案。总表「表单」列标了的页面有放弃修改确认。
- 推送主题和权限见 05 章第 12.2 节，收到变更后的界面处理见 02 章第 5.4 节。各页「订阅」只列主题。
- 状态码见 04 章，页面上用 `shared` 状态表里的中文名。

### 1.1 公共区块

外观见 02 章第 4 节，各页只写区块名。

### 1.2 列表级按钮

列表级按钮由列表接口顶层的 `actions` 返回（05 章第 1.5 节「列表级操作码」），写法同第 1 节，例如「新建订单」（`create`）。新建售后（X5，`createAfter`）、申请售后（S7，`applyAfter`）也是列表级操作码，和订单详情里的同名操作码进同一个页面；从订单详情进时带上这张订单。

## 3. 主包

### M1 登录

- 入口：没有绑定账号时打开任何页面；退出登录后。
- 区块：品牌背景整屏（`hz-cover` `full`，下部渐亮到墙色）→ 上部 logo → 下部隐私协议勾选（「我已阅读并同意《花众小程序隐私保护指引》」，点书名号部分打开微信隐私保护指引）→「手机号快速验证登录」。没勾选时点按钮的表现见 03 章第 8.5 节，提示写在按钮上方的 `hz-error`。
- 小程序启动先进本页：已绑定就按 `landing` 直接 `reLaunch`，不显示登录区；账号停用显示 02 章第 5.3 节的停用状态（「退出登录」调解绑，之后回到登录区）。
- 落点：按 `landing`。从分享卡片进来的，登录后回 M2 继续。
- 报错：按 05 章 `POST /auth/bind-phone` 返回的 `message`；用户在微信授权框里点了拒绝，不报错，留在本页。
- 接口：手机号登录绑定、当前账号。

### M2 链接落地

- 入口：分享卡片（第 11 节）。供应商填报邀请：没登录先去 M1，登录后回来；解析成功后 `redirectTo` 目标页。
- 门店下单邀请不经过 M1，本页按 `GET /store-invites/:token` 依次判断：`binding` 为 `self` → 直接 `reLaunch` 到 S1（不管邀请是否已失效）；邀请不是待使用 → 失效（下一条）；`other` → 整页状态「这台微信已登录{boundLabel}，请先在「我的」退出登录再接受邀请」+「去我的」；`none` → 花众字标 +「邀请你在线订货」+ 门店名（`storeLabel`）+ 隐私勾选 +「手机号快速验证登录」（隐私没勾选同 M1），验证成功 `reLaunch` 到 S1。
- 失效：整页状态（02 章第 5.4 节「分享链接失效」），原因用后端返回的句子。
- 接口：解析分享链接。

### M3 花众首页

- 区块：花众字标 → 身份行（岗位 · 名字，右边日期）→ 两列入口卡（图标、模块名、箭头，按 `modules`；个数为单数时最后一张占整行）。不显示待办。
- 接口：当前账号。

### M4 我的（员工）

- 区块：身份 → 按 `menus` 列入口（库存查询、操作日志、员工与岗位）→ 个人资料（弹层，只读：名字、岗位、登录手机号）→ 退出登录（次按钮，弹层确认）。开发环境最下面多一个「组件总览」。
- 落点：退出登录后进 M1。
- 接口：当前账号、解绑微信。订阅 `account:<id>`。

### M5 库存查询

- 搜索（名称、编码）+ 分类筛选。一条一张卡：花材 + 库存数量和单位（关键数字，加粗；库存 0 照常次要色）；编码 · 分类；停用的标「已停用」。只读，不能点开（2026-10-03 确认）。
- 空状态：「暂无符合条件的库存」。
- 接口：库存列表。订阅 `stock`。

### M6 操作日志

- 筛选：模块（`GET /me` 的 `modules` 多于一项时才显示）、日期。按天分组（组头「10-03 周六」，02 章第 6 节）；卡片：操作 · 单号或对象、模块（公共日志写「公共」）、时:分 · 操作人。点开弹层（2026-10-03 确认）：先写操作 · 对象和「时间 · 操作人 · 模块」→ 原因 →「改动」只列修改前后不一样的字段（「字段　旧 → 新」）；只有修改后的（新增类）列「修改后」全部字段，只有修改前的列「修改前」全部字段。
- 空状态：「暂无操作日志」。
- 接口：日志列表、日志详情。

### M7 员工与岗位

- 列表：名字、岗位（多个用「、」连）、启用状态。底栏「新增员工」（`create`）。
- 弹层（短表单，分三组、细线隔开，2026-10-03 确认）：名字、登录手机号 / 管理员开关、模块多选（管理员开关打开时隐藏）/ 启用、微信（这一组新增时不显示）。「微信」一行只在 `actions` 含 `unbindStaffWechat` 时出现：「已绑定」+ 文字按钮「解绑微信」（确认后解绑，弹层留着）。弹层底部只有「保存」。
- 报错：「请填写名字」「请填写 11 位登录手机号」「这个手机号已经被其他账号使用」「请至少选一个模块」「至少要保留一个启用的管理员」「没有修改内容」。
- 落点：保存后关弹层，留在列表。
- 接口：员工列表、新建员工、修改员工。

### M9 组件总览

- 只在开发环境，从 M4 进。按 02 章第 4 节把所有组件和状态排在一页。

## 4. 门店端（store）

底栏「首页 / 购物车 / 我的」，购物车标签显示件数（本地购物车：按账号存在这台手机上，退出登录清空；客户停用时照常显示）。订货、订单、售后、对账从门店首页进。

### S0 门店首页

- 入口：登录落点；底栏「首页」。
- 区块：花众字标 → 身份行（客户 · 门店 · 联系人，右边日期）→ 主卡「订货」（下面一行「今日可订 n 款」，n 为 `orderableCount`）→ 一排三张小卡：订单、售后、对账。不显示待办数。
- `lockedReason` 有值（客户停用）：身份行下面用 `hz-notice` 显示它，「订货」卡变灰不能点；订单、售后、对账照常。
- 落点：订货 → S1；订单 → S3；售后 → S7；对账 → S9。
- 接口：门店首页。订阅 `catalog:<customerId>`。

### S1 订货

- 入口：S0「订货」；S6「修改订单」进入改单模式（隐藏底部标签，只显示结算条，用单独一份购物车）。
- 区块：顶部「客户 · 门店」、下单日期（改单时是原订单日期）、可订款数、搜索（跨分类）→ 左侧分类 + 右侧产品（图、名、价、步进器）→ 购物车条（金额、件数、去结算；点图标弹出明细，可改数量、清空）。
- 去结算：购物车为空时禁用（改单时只剩已停订产品也能进）。
- 打开时购物车里有已不在目录里（停订或停用）的产品：从购物车去掉，用 toast 提示一次「白绿清新花束已停订，已从购物车移除」（多个用「、」连）；改单模式不去掉，到结算页标「已停订」。
- 空状态：「暂无可订产品」；搜索没结果「暂无相关产品」。
- 落点：去结算 → S5；改单模式返回 → S6，原购物车不变。
- 接口：订货目录。订阅 `catalog:<customerId>`。

### S2 购物车

- 购物车行（改数量、删除）→「清空」→ 结算条。
- 打开时去掉停订、停用的产品，提示同 S1。客户停用（`GET /store/home` 的 `lockedReason` 有值）：顶部 `hz-notice` 显示它，「去结算」禁用；购物车照常能改、能清空。
- 空状态：「暂无已选产品」。落点：去结算 → S5。
- 接口：门店首页、订货目录（核对停订）。订阅 `catalog:<customerId>`。

### S3 订单

- 入口：S0「订单」。筛选：状态、下单日期。三行卡片。
- 空状态：「暂无订单」。
- 接口：本店订单列表。订阅 `orders`。

### S4 我的（门店）

- 区块：身份卡（联系人、客户门店、登录手机号）→ 个人资料（弹层，只读）→ 退出登录。

### S5 结算（表单）

- 入口：S1、S2 去结算。
- 区块：状态区 → 下单日期、客户门店 → 备注 → 明细（`discontinued: true` 的行标「已停订」+ 垃圾桶）→ 订单金额。没有出货日期（由销售确认时定，阶段 3 确认），页面不写规则说明。
- 底栏：「提交订单」；改单时「确认修改」。
- 报错：「白绿清新花束已停订，请先删掉再提交」（按实际产品名）「销售已确认，门店不能再修改，请联系销售」「订单已被取消，不能再修改」「这个客户已停用，不能再下新单，请联系花众」「这个客户已停用，不能再修改订单，请联系花众」「请先选择产品」。
- 落点：提交后进 S6，购物车清空；改单提交后进 S6，原购物车恢复。放弃修改时备注不保留，购物车还在。
- 接口：提交订单、修改订单（门店）。改单时订阅 `order:<id>`。

### S6 订单详情

- 区块：状态区 → 单号、状态、下单日期、出货日期（只读，待确认时写「待销售安排」）、备注 → 明细 → 订单金额或发货金额 → 发货备注 → 变更记录 → 原因行。
- 底部操作区：「取消订单」（`storeCancel`，次）、「修改订单」（`storeEdit`）、「申请售后」（`applyAfter`）。禁用时下方写 `disabledReason`（客户停用、过了售后申请期限）。
- 弹层：取消订单（原因弹层，按 `storeCancel` 的 `reasonRequired`）。
- 落点：取消后留在本页；修改 → S1 改单模式；申请售后 → S8。
- 接口：订单详情、取消订单（门店）。订阅 `order:<id>`。

### S7 售后

- 从 S0 进。筛选：状态、提交日期。三行卡片：金额 `amountCents` 为 `null` 时，待处理写「待确认」，已关闭、已作废写「—」。
- 底栏「申请售后」：弹层只列 `actions` 含 `applyAfter` 且 `enabled: true` 的订单（过了申请期限的不列）→ S8。
- 弹层：售后详情（只读）：产品、问题原因、说明、图片、状态、售后金额、原因行。
- 空状态：「暂无售后」。
- 接口：本店售后列表、售后详情、可申请售后的订单。订阅 `afters`。

### S8 申请售后（表单）

- 入口：S6、S7。
- 区块：原订单、出货日期 → 明细（数量上限 `maxQty`，标「最多 n」；问题原因、问题说明、图片）→「添加产品」（这张单的产品）。
- 底栏「提交售后」。
- 报错：「请添加售后产品」「售后数量须大于 0，且不超过实发数量减去已申请的售后」「请填写每项产品的问题说明」。
- 落点：提交后进 S7，并打开这张售后的详情弹层。
- 接口：可申请数量、上传签名、提交售后（门店）。

### S9 对账

- 从 S0 进。筛选：出货日期（默认全部）。对账格：发货金额 `shippedCents`、售后 `afterCents`、已付 `paidCents`、待付 `unpaidCents`（按筛选区间）。
- 列表：本店发货单三行卡片（状态 `payStatus`；部分付写「未付 ¥…」）。点开 → S6。
- 空状态：「暂无发货单」。
- 接口：门店对账。订阅 `ar:<customerId>`。

## 6. 销售（sales）

### X1 销售首页

- 模块首页。入口：销售订单、客户门店、产品管理、订货目录、客户售后。待办：待确认订单、待处理售后。空状态「暂无待办」。订阅 `todo:sales`。

### X2 销售订单

- 搜索（单号、客户、门店）+ 筛选：状态、客户、下单日期。三行卡片。
- 底栏「新建订单」（`create`）。
- 空状态：「暂无订单」。
- 接口：订单列表。订阅 `orders`。

### X3 订单详情

- 区块：状态区 → 单号、状态、来源 → 客户门店、下单日期、出货日期（待确认时写「待销售安排」）、备注 → 明细（`discontinued: true` 的行标「已停订」）→ 金额 → 发货人、发货时间、发货备注 → 变更记录 → 原因行。
- 底部操作区：「取消订单」（`cancel`，次）、「修改并确认」（`editAndConfirm`，次）、「确认订单」（`confirm`）、「修改订单」（`edit`）、「新建售后」（`createAfter`）。
- 弹层：
  - 确认订单：出货日期（`hz-picker` 日期，默认今天往后 `SHIP_DATE_DEFAULT_OFFSET_DAYS` 天，可以选以前）→「确认订单」。报错「请选择出货日期」。
  - 取消订单，按 `cancel` 的 `reasonRequired`：false 时一句确认，true 时原因框。弹层开着时订单被确认，提交返回 `STALE`，按 `latest` 里 `cancel` 的 `reasonRequired` 换成原因框。
- 落点：确认后留在本页，成功提示「订单已确认」；修改、修改并确认 → X4；新建售后 → X7。
- 接口：订单详情、确认订单、取消订单。订阅 `order:<id>`。

### X4 订单表单

- 三种模式：新建（从 X2）、修改（`edit`）、修改并确认（`editAndConfirm`）。
- 区块：状态区 → 客户、门店（只在新建时可选，只列启用的）→ 出货日期（新建、修改并确认时默认今天往后 `SHIP_DATE_DEFAULT_OFFSET_DAYS` 天，可以选以前）→ 备注 → 明细（新加的行单价默认 `listPriceCents`，原有行保持原单价；`discontinued: true` 的行标「已停订」+ 垃圾桶）→「添加产品」（只列这个客户目录里启用的产品）→ 订单金额 → 修改原因（修改、修改并确认时显示）。
- 底栏：新建「确认订单」；修改「保存修改」；修改并确认「修改并确认」。
- 报错：「请选择客户和门店」「请选择出货日期」「请添加产品并填写有效数量」「请填写修改原因」「白绿清新花束已停订，请先删掉再保存」（按实际产品名）。
- 落点：新建后回 X2；修改、修改并确认后回 X3。
- 接口：客户门店、订货目录、新建订单、修改订单。修改时订阅 `order:<id>`。

### X5 客户售后

- 筛选：状态、客户、提交日期。三行卡片：金额 `amountCents` 为 `null` 时写「—」。
- 底栏「新建售后」：弹层只列 `actions` 含 `createAfter` 的订单 → X7。
- 空状态：「暂无售后」。
- 接口：售后列表。订阅 `afters`。

### X6 售后详情

- 区块：状态区（已处理时 `notice`「发货单应收已减去售后金额」）→ 单号、状态、来源 → 客户门店、原订单 → 售后产品（原因、说明、图片直接展开）→ 售后金额 `amountCents` → 处理说明 → 原因行。
- 底部操作区：「关闭售后」（`closeAfter`，次）、「处理售后」（`processAfter`）、「作废售后」（`voidAfter`，次）。
- 弹层：关闭售后、作废售后（原因弹层；作废报错「请填写作废原因」）。
- 落点：关闭、作废后留在本页；处理 → X7。
- 接口：售后详情、关闭售后、作废售后。订阅 `after:<id>`。

### X7 售后表单

- 两种模式：处理（`processAfter`，从 X6）、新建（从 X3、X5）。
- 区块：原订单、客户门店 → 明细（数量上限 `maxQty`；单价默认 `shipPriceCents`）→ 售后金额合计 → 处理说明（选填）。新建模式有「添加产品」和垃圾桶；处理模式（门店提交的售后）不能增删行，只改数量和单价，门店填的原因、说明、图片只读（阶段 3 确认：销售新建的售后建好就是已处理，不能再改）。新建模式每行：数量、单价、问题原因（必选）、问题说明（选填），没有图片。
- 底栏「保存」。
- 报错：「请选择售后原因」（新建时）「售后数量须为 0 或正整数，不给的填 0」「数量都是 0，整张不处理请关闭售后并写原因」「售后数量不能超过实发数量减去已申请的售后」「粉玫瑰日常花束的售后单价不能高于发货单价 ¥68.00」（按实际产品和价格）「请添加售后产品并填写有效数量」。
- 落点：保存后回 X6。
- 接口：可申请数量、处理售后、新建售后。处理时订阅 `after:<id>`。

### X8 客户门店

- 左侧客户（停用的标「已停用」）、右侧门店（名称、联系人、启用状态）。右侧顶部一行当前客户名 + 文字按钮「编辑客户」。底栏「新建客户」（`createCustomer`，次）、「新建门店」（`create`）。
- 弹层（短表单）：
  - 客户资料（新建、编辑客户）：名称、启用。
  - 门店资料：客户、名称、联系人、电话、地址、门店账号登录手机号、启用。
    - 「邀请下单」（`inviteStore`）→「生成邀请」→ 分享卡片（第 11 节）。
    - 「解绑微信」（`unbindStoreWechat`，次，弹层确认）。
- 报错：「请填写客户名称」「已有同名客户」「请填写门店名称」「这个客户下已有同名门店」「开通门店账号请填写联系人」「没有修改内容」。
- 落点：保存后关弹层，留在列表；新建客户后左侧选中这个客户。
- 接口：客户门店列表、新建客户、修改客户、新建门店、修改门店、生成下单邀请、解绑微信。订阅 `store_invites:<storeId>`。

### X9 产品管理 / X10 产品表单

### X11 订货目录

- 筛选：出货日期起、止（默认值见 05 章第 1.6 节）。报错「结束日期不能早于开始日期」。
- 区块：「n 张订单」→ 花材卡片（左侧勾选框）：①出货日期区间 + 缺货 / 够用 ②花材 + 需求 `needQty` ③库存 `stockQty` · 在途 `inTransitQty` + 缺 / 余 `leftQty`。`enabled: false` 标「已停用」、不能勾选；`invited: true` 标「已邀请」。配方关联完整性在保存校验和数据库外键处保证，不显示旧原型的花材名称匹配失败列表。
- 底栏：「邀请供应商（n）」（`inviteSupplier`，次）、「生成采购单（n）」（`createPo`），没勾选时禁用。
- 弹层：
  - 来源：需求、库存、在途、余量 → 已邀请（邀请号、供应商、数量）→ 按出货日期列订单（单号、客户门店、产品 × 用量 = 花材数）。
  - 邀请供应商：单选后端返回的可邀请供应商 →「下一步」→ C7。没有可选的写「暂无已开通供应商端账号的供应商」；报错「请选择一家供应商」。
- 落点：生成采购单 → C5（数量带缺口：`shared/domain` 的 `gapOf(leftQty)`，够用为 0）；C5、C7 保存后回本页，勾选清空。
- 空状态：「暂无待发货订单」。
- 接口：采购需求计算、需求来源。订阅 `demand`。

### C3 采购单

- 筛选：状态、供应商、下单日期。三行卡片（金额收货前 `amountCents`、收货后 `payableCents`）。
- 底栏「新建采购单」（`create`）。空状态「暂无采购单」。
- 接口：采购单列表。订阅 `pos`。

### C4 采购单详情

- 区块：状态区 → 单号、状态、供应商、采购员、下单日期、来源 → 明细（采购数量；收货后实收、退货，少收标「少收 n」）→ 采购金额 `amountCents`、应付金额 `payableCents` → 变更记录、改价记录、退货记录 → 原因行。
- 底部操作区：「取消采购单」（`cancelPo`，次）、「修改采购单」（`editPo`）。
- 弹层：取消采购单（原因弹层；报错「请填写取消原因」）。
- 落点：取消后留在本页；修改 → C5。
- 接口：采购单详情、取消采购单。订阅 `po:<id>`。

### C5 采购单表单

- 区块：状态区 → 供应商（`actions` 有 `changeSupplier` 时可选，否则只读）→ 备注 → 明细（花材、采购数量、单价）→「添加花材」→ 采购金额 → 修改原因（修改时显示）。
- 底栏：新建「确认下单」；修改「保存修改」。
- 报错：「请选择供应商」「采购数量须为大于 0 的整数」「请填写单价，赠送的花材填 0」「没有修改内容」「请填写修改原因」。
- 落点：新建后回 C3（从 C2 进的回 C2）；修改后回 C4。
- 接口：启用供应商、启用花材、新建采购单、修改采购单。修改时订阅 `po:<id>`。

### C6 供应商填报

- 筛选：状态、供应商。三行卡片：邀请日期 + 状态；供应商 + 花材；采购员，已提交的写采购单号和它现在的状态。
- 弹层：填报详情：邀请号、供应商、状态、需求花材；已提交的列供货明细和采购单号（点采购单号先关弹层再进 C4）。
  - 「取消邀请」（`cancelInvite`，次）：弹层内切换成原因弹层。
  - 「填报链接」（`shareInvite`，次）：弹层内切换，分享卡片按钮（第 11 节）+「复制链接」。
  - 「修改」（`editInvite`）：关弹层进 C7。
- 空状态：「暂无邀请」。
- 接口：邀请列表、邀请详情、取消邀请、生成填报分享。订阅 `invites`。

### C7 邀请表单

- 两种模式：从 C2 新建（供应商已选定）、修改（`editInvite`，从 C6）。
- 区块：状态区 → 供应商（只读）→ 明细（花材、库存、需求量）→「添加花材」（都加过了写「暂无可添加花材」）。
- 底栏：新建「发出邀请」；修改「保存修改」。
- 报错：「请添加花材」「需求量须为大于 0 的整数」「没有修改内容」。
- 落点：新建后回 C2，提示「已邀请春禾花材填报，可以发送填报链接提醒对方」（按实际供应商）；修改后回 C6 并重新打开这张邀请的详情，提示「邀请已修改，供应商看到的是最新内容」。
- 接口：启用花材、发出邀请、修改邀请。修改时订阅 `invite:<id>`。

### C8 供应商

- 列表：名称、联系人、启用状态；停用的写「已停用 · 待收货 n 单」（`openPoCount`）。底栏「新建供应商」（`create`）。空状态「暂无供应商」。
- 弹层（短表单）：名称、联系人、电话、地址、启用、开通供应商端账号、登录手机号。
- 报错：「请填写供应商名称」「已有同名供应商」「开通供应商端账号请填写 11 位登录手机号」「这个手机号已经被其他供应商使用」「没有修改内容」。
- 接口：供应商列表、新建供应商、修改供应商。

## 9. 仓库（warehouse）

### W1 仓库首页

- 模块首页。入口：待收（→ W2）、手工入库（→ W4）、手工出库（→ W15）、报损（→ W7）、盘点（→ W8）、库存（→ W11）、花材（→ W14）。待办：待收货的采购单，空状态「暂无待收货」。订阅 `todo:warehouse`。

### W2 待收

- 筛选：状态（默认待收货）、供应商、下单日期。三行卡片同 C3。
- 空状态：「暂无采购单」。
- 接口：采购单列表（仓库）。订阅 `pos`。

### W3 收货

- 入口：W1、W2、W13。
- `actions` 含 `receive` 时是表单：状态区 → 供应商、采购员、下单日期 → 变更记录 → 明细（采购数量、实收（默认等于采购数量）、单价；和采购数量、原单价不同时标「少收 n」「多收 n」「改价 ¥a → ¥b」）→ 应付合计 → 改价原因（改了单价时显示）→ 备注。底栏「确认收货」（`receive`）。
- 否则：状态区 → 明细（采购数量、实收、退货）→ 采购金额 `amountCents`、应付金额 `payableCents` → 财务状态 `apStatus` → 变更记录、改价记录、退货记录 → 原因行。
- 底部操作区：「退货」（`return`，次）、「改单价」（`reprice`）。
- 弹层：退货（逐行填数量，上限 `maxReturnQty`）；改单价（逐行改单价 + 原因）。
- 报错：「改了单价，请填写改价原因」「请填写改价原因」。
- 落点：确认后留在本页，成功提示「已收货」或「已拒收」；退货、改价后关弹层。
- 接口：采购单详情（仓库）、确认收货、退货、改单价。订阅 `po:<id>`。

### W4 手工入库单

- 筛选：状态、供应商、入库日期。三行卡片（入库金额 `amountCents`）。
- 底栏「新建入库」（`create`）→ W5（入库）。点开 → W6。
- 空状态：「暂无入库单」。
- 接口：手工入库单列表。订阅 `wh_docs`。

### W5 出入库表单

- 三种：入库（从 W4）、出库（从 W15，或 W12 带上这种花材）、报损（从 W7）。
- 区块：
  - 入库：供应商 → 明细（花材、数量、单价）→「添加花材」→ 入库合计 → 原因（选填）。
  - 出库：出库分类（文字按钮「管理分类」）→ 明细（花材、数量，旁边显示 `stockQty`）→ 原因（选填）。
  - 报损：明细 → 原因。
- 弹层：选花材（都加过了写「暂无可添加花材」）；管理分类（改名、新增、启用 / 停用；维护完回到表单，草稿还在）。
- 报错：「请选择供应商」「请选择出库分类」「请填写报损原因」「数量须为大于 0 的整数」「请添加花材」。
- 落点：入库回 W4；出库回 W15；报损回 W7。
- 接口：启用供应商、花材、出库分类、保存出库分类、新建手工入库、新建手工出库、新建报损。

### W6 单据详情

- 入口：W4、W7、W13、W15。
- 手工入库单：状态区 → 单号、状态、供应商、入库日期、经办人、原因 → 明细 → 入库金额 `amountCents` → 财务状态 `apStatus` → 改价记录 → 原因行。底部操作区：「作废」（`void`，次）、「改单价」（`reprice`）。
- 手工出库单、报损单：只读，出库单显示出库分类。
- 弹层：作废（原因弹层）、改单价（逐行改单价 + 原因）。
- 报错：「请填写作废原因」「请填写改价原因」。
- 落点：作废、改价后关弹层。
- 接口：单据详情、作废手工入库单、改单价（手工入库单）。订阅 `wh_doc:<id>`。

### W7 报损

- 三行卡片：报损日期 + 已报损；花材 + 数量；单号 + 经办人。底栏「新建报损」（`create`）→ W5（报损）。点开 → W6。
- 空状态：「暂无报损记录」。
- 接口：报损列表。订阅 `wh_docs`。

### W8 盘点 / W9 盘点表单 / W10 盘点详情

- W8：三行卡片：盘点日期 + 已盘点；分类 + 花材数；有差异 n 项 / 无差异。底栏「新建盘点」（`create`）：弹层多选花材分类（报错「请选择分类」）→「开始盘点」→ W9。空状态「暂无盘点记录」。
- W9（表单）：分类 → 花材行：账面数 `bookQty`、实盘数、差异 → 差异原因。底栏「确认盘点」。报错「有差异时请填写差异原因」；确认时库存变了按 03 章第 8.3 节。
- 落点：确认后进 W10（只读）。
- 接口：花材分类、账面库存、新建盘点、盘点列表、盘点详情。W9 订阅 `stock`。

### W11 库存

- 搜索 + 左侧分类。行：花材、编码、库存数量和单位；停用的标「已停用」。点开 → W12。
- 空状态：「暂无花材」。
- 接口：库存列表。订阅 `stock`。

### W12 花材详情

- 区块：花材资料（编码、名称、分类、单位、状态）→ 当前库存 `stockQty` → 批次（入库日期、剩余数量）→ 最近出入库记录（查看全部 → W13，带上这种花材）。
- 底栏：「手工出库」（`stockOut`，次）、「手工入库」（`stockIn`），都进 W5 并带上这种花材。
- 接口：花材详情、批次、出入库记录。订阅 `stock`。

### W13 出入库记录

- 筛选：类型、花材、日期。卡片：时间 + 类型；花材 + 数量变化（入库绿色、出库红色）；单号 · 批次 · 经办人。点单号 → W6 或 W3。
- 空状态：「暂无出入库记录」。
- 接口：出入库记录。

### W14 花材

- 搜索（名称、编码）+ 筛选：分类、状态。行：名称、编码、分类、单位、启用状态。底栏「新建花材」（`create`），文字按钮「管理分类」。
- 弹层（短表单）：编码（默认后端生成）、名称、单位、分类、启用。管理分类：新增、改名。
- 报错：「请填写花材名称」「编码已被其他花材使用」「没有修改内容」。
- 落点：保存后关弹层，留在列表。空状态「暂无花材」。
- 接口：花材列表、新建花材、修改花材、花材分类、保存花材分类。

### W15 手工出库单

- 入口：W1。筛选：出库分类、出库日期。三行卡片：出库日期 + 已出库；出库分类 + 花材数量；单号 + 经办人。
- 底栏「新建出库」（`create`）→ W5（出库），保存后回本页。点开 → W6（只读）。
- 空状态：「暂无出库单」。
- 接口：手工出库单列表、出库分类。订阅 `wh_docs`。

## 10. 财务（finance）

### F1 财务首页

- 模块首页。入口：客户对账、供应商对账、收付款记录、收付款方式。待办：待付款单据、预收待核销的客户。空状态「暂无待办」。订阅 `todo:finance`。

### F2 客户对账 / F3 客户对账详情

- F2：客户卡片：客户名 + 未收 `unpaidCents`；发货金额 `shippedCents` · 已收 `receivedCents`；`prepaidCents` 大于 0 时写「预收 ¥…」。空状态「暂无客户」。
- F3：筛选：收款状态、出货日期（默认全部）。对账格（`shippedCents`、`afterCents`、`receivedCents`、`unpaidCents` 按筛选区间，另行「预收（未核销）」`prepaidCents` 是当前余额）→ 发货单三行卡片（状态 `payStatus`）。空状态「暂无已发货订单」。
- 底部操作区：「核销预收」（`allocate`，次）、「登记收款」（`registerReceipt`）→ F4。
- 弹层（同一个弹层里切换，左上角返回上一层）：
  - 发货单：发货金额、每条售后（可点）、应收、已收、未收 → 核销记录（收款号可点）。标题「SO-… · 部分收」，售后抵扣的加「（售后抵扣）」。
  - 售后详情：同 X6 只读内容；「作废售后」（`voidAfter`，次）→ 原因弹层。
  - 收款详情：金额、方式、日期、备注、状态、核销明细；「作废收款」（`voidReceipt`）→ 原因弹层（报错「请填写作废原因」）。作废后写「已作废，核销已撤回。」。
- 接口：客户对账列表、客户对账详情、发货单应收、收款详情、作废收款、作废售后。订阅 `ar:<customerId>`、`receipt:<id>`。

### F4 登记收款 / 核销预收（表单）

- 入口：F3（默认这个客户）。
- 登记收款：客户、收款日期（默认今天，能选以前，不能选以后）、金额、收款方式、备注 → 核销明细（每张未收发货单：`unpaidCents`、本次核销、「填入」）→ 汇总「本次核销 ¥… / 转为预收 ¥…」。「填入」取 `unpaidCents` 和「收款金额 − 已填核销」中较小的一个。
- 核销预收：客户 →「可用预收 ¥…」（`prepaidCents`）→ 核销明细（「填入」取 `unpaidCents` 和「`prepaidCents` − 已填核销」中较小的一个）。
- 底栏：「确认收款」/「确认核销」。
- 报错：「SO-0927-026 最多核销 ¥2,100.00」（按实际单号和未收）「可用预收只有 ¥548.00」（按实际）「请填写收款金额」「请选择收款方式」「收款日期不能晚于今天」。
- 落点：保存后回 F3。
- 接口：未收发货单、可用预收、登记收款、核销预收。订阅 `ar:<customerId>`。

### F5 供应商对账 / F6 供应商对账详情

- F5：供应商卡片：供应商名 +「待付 ¥…」`unpaidCents`；应付 `payableCents` · 已付 `paidCents`。空状态「暂无供应商」。
- F6：对账格（`payableCents`、`paidCents`、`unpaidCents`）→ 应付单据三行卡片（状态 `apStatus`）。点开 → F7。空状态「暂无应付单据」。
- 接口：供应商对账列表、供应商对账详情。订阅 `ap:<supplierId>`。

### F7 单据付款

- 入口：F1、F6。
- 区块：状态区（`notice`）→ 单号、状态 → 采购单：供应商、下单日期、收货人和时间；手工入库单：供应商、来源、入库人和时间、原因 → 明细（实收、退货、改价）→ 应付金额 `payableCents` → 改价记录、退货记录。
- 底部操作区：「登记付款」（`pay`）；`payment` 不是 `null` 时「查看付款」。
- 弹层：
  - 登记付款：付款日期（默认今天，能选以前，不能选以后）、付款方式、备注、付款金额（`payableCents`，只读）→「确认付款」。报错「应付已变为 ¥…，请核对后再付款」「付款日期不能晚于今天」。
  - 付款详情：金额、方式、日期、状态；「作废付款」（`voidPayment`）→ 原因弹层（弹层内切换）。
- 单据已不需要付款时整页写「这张单已不需要付款」。
- 落点：付款、作废后留在本页，成功提示「已付款」「付款已作废」。
- 接口：应付单据详情、登记付款、付款详情、作废付款。订阅 `payable:po:<id>` 或 `payable:wh:<id>`、`ap:<supplierId>`。

### F8 收付款记录

- 筛选：类型（收款、付款）、状态、日期。三行卡片：日期 + 状态；客户或供应商 + 方式；单号 + 金额。
- 弹层：收款详情、付款详情（同 F3、F7），直接打开时左上角是关闭。
- 空状态：「暂无收付款记录」。
- 接口：收付款记录、收款详情、付款详情、作废收款、作废付款。

### F9 收付款方式

- 两个分区：收款方式、付款方式。每行名称 + 启用开关（最后一种启用的开关不能关）；每份下面「新增」输入框 +「添加」。
- 报错（写在对应分区里）：「请填写名称」「已有同名方式」。
- 接口：收付款方式、保存收付款方式。
