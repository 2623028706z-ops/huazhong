# 08 开发顺序

整理日期：2026-09-30。代码按本规格书从零写，不参考老小程序代码。每个阶段结束时：相关的 07 章验收用例全部通过，给用户看效果（体验版或截图），确认后再进下一阶段。

## 阶段 0：骨架

- pnpm monorepo：`miniapp`、`server`、`shared`；ESLint、Prettier、Stylelint、TypeScript 严格模式、knip（未使用的文件和导出）、jscpd（重复代码）；GitHub Actions 跑检查。
- `shared`：接口契约（`contract`）、枚举和状态表、字段规则、错误码（`errors`）、业务参数（`config`）、文案（`copy`）、格式化（`format`）。先写契约，前后端都从它生成类型（00 章）。
- 接口契约按阶段增长（2026-09-30 确认）：每个阶段先把本阶段的接口写进契约，再写实现；还没开始做的接口不进契约，所以「契约里有、后端没实现就失败」的检查每个阶段都能全绿。阶段 0 的契约只有 `GET /me`，用它把身份守卫、请求层、实时握手从头到尾跑通；事务、幂等、`STALE`、分页这些公共层能力用接口测试里的专用接口验证。
- 后端：NestJS 骨架，统一响应和错误码、身份守卫（`X-WX-OPENID`）、权限两层、事务、幂等、日志拦截、分页；Drizzle 连本地 Docker PostgreSQL；Testcontainers 接口测试跑通。
- 发号表、操作日志表、账号表、员工模块权限表、幂等表；账号外键要用的客户、门店、供应商表先只建名称、归属、启用列，其余列在阶段 3、4 加。pg-boss 每天清理过期的幂等键。
- 实时同步底座：WebSocket 网关、`NOTIFY` / `LISTEN`、订阅和按权限过滤；前端 `core/realtime` 自动重连。
- 小程序：`core/request`（错误码转界面状态、超时、读请求重试、防重复提交）、`styles/tokens.wxss`、`utils.wxss`、WXS 格式化工具、思源宋体子集加载、Lucide iconfont。
- 版本号锁定，填进 01 章第 9 节。

## 阶段 3：订单 → 发货 → 售后 → 收款

- 开工前定的 21 条业务取舍（出货日期归销售、目录调价同步待确认订单、售后申请期限、只能发到期的单、对账按出货日期筛选等）已写进 03–07 章，标「阶段 3 确认」。
- 主数据：客户（新建、改名、停用）、门店和门店账号、产品分类（新增、改名、排序、删除）、产品和配方、订货目录、收款方式。
- 门店端：订货、购物车、结算、订单、改单、取消、售后申请、对账。
- 销售：订单（新建、确认、修改并确认、修改、取消、变更记录）、售后（处理、关闭、新建、作废）。
- 发货：待发货、确认发货（少发）、发货记录。
- 财务收款部分：客户对账、登记收款、核销、预收、作废收款、作废售后。
- 这条链的实时同步和互斥全部做完。

## 阶段 4：采购 → 填报 → 收货 → 付款

- 开工条件（2026-10-06 确认）：阶段 3 在微信里验收通过后再开始；验收反馈先修好、单独提交。
- 主数据：花材和分类、供应商和供应商端账号、付款方式。出库分类挪到阶段 5（2026-10-06 确认）。
- 采购：采购需求、采购单（新建、修改、换供应商、取消、改单记录）、填报邀请（发出、修改、取消、分享卡片）。
- 供应商端：填报、采购单、对账。入库单详情随手工入库在阶段 5 做。
- 仓库收货部分：待收、收货、拒收、退货、改单价；库存批次。仓库首页只放本阶段做好的入口（待收、库存、花材），其余入口阶段 5 再加（2026-10-06 确认，同阶段 2 做法）。
- 财务付款部分：供应商对账、登记付款、作废付款、付款前复核应付。待付款、供应商对账（含供应商端对账）本阶段只算采购单；接口按 `docType` 留好位置，手工入库单在阶段 5 接进来（2026-10-06 确认）。
