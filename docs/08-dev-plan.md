整理日期：2026-09-30；2026-10-04 按重新设计清单同步。代码按本规格书从零写，不参考老小程序代码。每个阶段结束时：相关的 07 章验收用例全部通过，给用户看效果（体验版或截图），确认后再进下一阶段。

## 阶段 0：骨架

- pnpm monorepo：`miniapp`、`server`、`shared`；ESLint、Prettier、Stylelint、TypeScript 严格模式、knip（未使用的文件和导出）、jscpd（重复代码）；GitHub Actions 跑检查。
- `shared`：接口契约（`contract`）、枚举和状态表、字段规则、错误码（`errors`）、业务参数（`config`）、文案（`copy`）、格式化（`format`）。先写契约，前后端都从它生成类型（00 章）。
- 接口契约按阶段增长（2026-09-30 确认）：每个阶段先把本阶段的接口写进契约，再写实现；还没开始做的接口不进契约，所以「契约里有、后端没实现就失败」的检查每个阶段都能全绿。阶段 0 的契约只有 `GET /me`，用它把身份守卫、请求层、实时握手从头到尾跑通；事务、幂等、`STALE`、分页这些公共层能力用接口测试里的专用接口验证。
- 后端：NestJS 骨架，统一响应和错误码、身份守卫（`X-WX-OPENID`）、权限两层、事务、幂等、日志拦截、分页；Drizzle 连本地 Docker PostgreSQL；Testcontainers 接口测试跑通。
- 发号表、操作日志表、账号表、员工模块权限表、幂等表；账号外键要用的客户、门店、供应商表先只建名称、归属、启用列，其余列在阶段 3、4 加。pg-boss 每天清理过期的幂等键。
- 实时同步底座：WebSocket 网关、`NOTIFY` / `LISTEN`、订阅和按权限过滤；前端 `core/realtime` 自动重连。
- 小程序：`core/request`（错误码转界面状态、超时、读请求重试、防重复提交）、`styles/tokens.wxss`、`utils.wxss`、WXS 格式化工具、思源宋体子集加载、Lucide iconfont。
- 版本号锁定，填进 01 章第 9 节。

### 实现顺序

1. **契约与模型。** 统一对账单 `statements`、明细 `statement_lines`、整单结清关联 `settlement_links`、余额使用 `credit_uses`；收付款加优惠、优惠原因和多收 / 多付，退款只退余额，客户 / 供应商加账期和期初欠款。移除 `allocations` / `payment_allocations`、按单核销算法、`ledgerToken` 全账复核和旧付款升级脚本；不保留旧流程兼容分支。
2. **财务后端。** 往来方锁后稳定锁定来源 / 对账单，事务内验证版本、来源归属和金额；开单占用来源、作废释放来源。收付勾选的对账单全部结清，允许未勾单先到钱；优惠不能超勾单合计，有优惠必须有原因，多出来的钱成为余额。资金作废必须先释放其后续对账抵扣 / 退款，只有有效结清关联阻止作废对账单。通知相关资金、对账单、来源业务单和外部往来方。
3. **业务接入。** 订单 / 售后 / 采购单 / 手工入库有效进入对账单后，后端 actions 与写入校验共同锁定影响金额的改动、退货和作废；内部业务岗位通过所属对账单只读查看，发货投影继续无金额。客户逾期只提醒不阻断；批量确认 / 发货逐单返回原因和成功结果。
4. **页面与公共组件。** 按 02 / 06 和 v33 统一窗格 / 卡片、字段左右排列、完整日期、可编辑表格、底栏至多两按钮、列表筛选和关键节点进度；模块首页去掉今日数字。门店 / 供应商取消首页和付款进度，改为对账单；财务客户 / 供应商往来、开单、收付、余额退回、设置和分享整张图片均接新契约。
5. **种子与验收。** 按 07 §12 重建本项目新种子：晨曦 DZ-260929-001 应收 ¥3,588、拾光 DZ-260929-002 已结清，拾光 SK-260929-001 ¥1,000 多收 ¥64；删除晨曦旧收款和旧核销。空库迁移、契约、权限 / 并发、财务与业务接口、页面交互分别验证，再做全量本地检查。更新过时用例，不为了旧断言增加兼容。

### 数据库与验证边界

当前采用从零重写，不迁移旧业务数据。新增 Drizzle 迁移和 snapshot，已应用的历史 SQL / journal 保持原样；验证当前新模型从空库建库、重复迁移不重复写入、约束 / 索引有效以及新种子口径。枚举扩展需要先提交事务再使用时，实际验证迁移边界，不能仅靠拆成 SQL 文件推定安全。

自动化接口测试仅连接隔离 Testcontainers PostgreSQL：每例复制独立测试数据库。空库迁移测试覆盖旧核销表已移除、有效来源不能重复占用、结清关联 / 余额使用的单来源单目标约束、优惠原因、退款合法和对账单不能抵扣自身。`db:reset` 不在本轮执行，不接现有本地业务库或云端数据库。

当前旧付款回填、旧结构兼容、`ruirui-010` 升级和历史幂等响应兼容方案已作废，不作为本轮实现或验收要求。需要上线时再另行核实环境与授权，不能把本地测试结果当作云端或发布验收。

**阶段 5 / 6 边界：** 手工出入库、报损、盘点及图片 / 作废按 03～07 当前规则实现；是否已完成以实际验收记录为准。规格同步和本地检查通过不代表截图获确认，更不代表 iOS / 安卓真机、微信云环境或发布通过。阶段 6 的外部配置、真机视觉和提审仍单独验收。
