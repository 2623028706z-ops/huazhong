# 08 开发顺序

整理日期：2026-09-30。代码按本规格书从零写，不参考老小程序代码。每个阶段结束时：相关的 07 章验收用例全部通过，给用户看效果（体验版或截图），确认后再进下一阶段。

## 阶段 0：骨架

- pnpm monorepo：`miniapp`、`server`、`shared`；ESLint、Prettier、Stylelint、TypeScript 严格模式、knip（未使用的文件和导出）、jscpd（重复代码）；GitHub Actions 跑检查。
- `shared`：接口契约（`contract`）、枚举和状态表、错误码（`errors`）、业务参数（`config`）、文案（`copy`）、格式化（`format`）。先写契约，前后端都从它生成类型（00 章）。
- 后端：NestJS 骨架，统一响应和错误码、身份守卫（`X-WX-OPENID`）、权限两层、事务、幂等、日志拦截、分页；Drizzle 连本地 Docker PostgreSQL；Testcontainers 接口测试跑通。
- 发号表、操作日志表、账号表、员工模块权限表。
- 实时同步底座：WebSocket 网关、`NOTIFY` / `LISTEN`、订阅和按权限过滤；前端 `core/realtime` 自动重连。
- 小程序：`core/request`（错误码转界面状态、超时、读请求重试、防重复提交）、`styles/tokens.wxss`、`utils.wxss`、WXS 格式化工具、思源宋体子集加载、Lucide iconfont。
- 版本号锁定，填进 01 章第 9 节。

## 阶段 1：组件和视觉

- 02 章第 4 节全部 `hz-*` 组件，以及「组件总览」页。
- 第 5 节的统一状态：骨架屏、空、断网、出错、提交中、不可操作、放弃修改、实时提示。
- 用户逐个组件对照原型确认视觉，**确认后再写业务页面**。

## 阶段 2：登录和公共

- 手机号快速验证绑定、登录落点、账号停用。
- 花众首页、模块首页框架、我的、员工与岗位、品牌封面上传和裁切、日志、库存查询（只读）。
- 隐私保护指引的同意流程。

## 阶段 3：订单 → 发货 → 售后 → 收款

- 主数据：客户、门店和门店账号、产品和配方、订货目录、收款方式。
- 门店端：订货、购物车、结算、订单、改单、取消、售后申请、对账。
- 销售：订单（新建、确认、修改并确认、修改、取消、变更记录）、售后（处理、关闭、新建、作废）。
- 发货：待发货、确认发货（少发）、发货记录。
- 财务收款部分：客户对账、登记收款、核销、预收、作废收款、作废售后。
- 这条链的实时同步和互斥全部做完。

## 阶段 4：采购 → 填报 → 收货 → 付款

- 主数据：花材和分类、供应商和供应商端账号、付款方式、出库分类。
- 采购：采购需求、采购单（新建、修改、换供应商、取消、改单记录）、填报邀请（发出、修改、取消、分享卡片）。
- 供应商端：填报、采购单、对账、入库单详情。
- 仓库收货部分：待收、收货、拒收、退货、改单价；库存批次。
- 财务付款部分：供应商对账、登记付款、作废付款、付款前复核应付。

## 阶段 5：仓库其余

- 手工入库单列表、新建、改单价、作废；手工出库、报损、盘点；库存、出入库记录。

## 阶段 6：上线准备
