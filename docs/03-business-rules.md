## 1. 范围

- 模块：销售、发货、采购、仓库、财务；外部端：门店端、供应商端；公共：登录、花众首页、我的、库存查询、日志、员工与岗位。
- 不做：生产模块、成品库存、订阅消息、老系统数据迁移、电脑版和 iPad 适配。
- 库存只管花材。发货不扣库存，库存靠仓库手工出库。
- 各模块是独立业务，数据实时同步，不做跨模块自动关联（例如采购需求不关联仓库出库）。

## 2. 角色与落点

| 角色 | 能看 | 能新建、修改 | 能取消、关闭、作废 |
|---|---|---|---|
| 门店账号 | 本店订单（含变更记录、取消申请）、售后（含取消原因）、本店对账单（不含收款记录和抵扣多收） | 下单；改待确认的单；申请售后；对待发货订单申请取消、撤回申请 | 取消待确认的单 |
| 销售 | 全部订单、售后、客户门店、产品、订货目录 | 新建订单、确认订单（定出货日期，确认页可修改）、批量确认待确认订单、改待发货订单；同意、拒绝门店的取消申请；新建、处理售后；客户、门店、产品和产品内部分类、订货目录和订货分类 | 取消订单；作废已发货订单；关闭售后；作废已处理售后；删除没有产品的产品内部分类、没有目录项的订货分类 |
| 发货 | 待发货、已发货订单（含变更记录），不显示单价和金额 | 确认发货（可少发、多发）；批量确认发货；生成送货单图片 | — |
| 采购 | 采购需求、采购单、邀请、供应商 | 新建、修改采购单；发出、修改邀请；供应商资料和供应商账号 | 取消采购单；取消邀请；停用供应商 |
| 仓库 | 收货（含已取消）、库存、花材、出入库记录、盘点 | 收货、拒收、退货、改价；手工入库、出库、报损、盘点；花材和分类、出库分类 | 作废已收货采购单、手工入库单、手工出库、报损 |
| 财务 | 客户对账、供应商对账、收付款记录、已处理售后金额 | 新建对账单、登记收款和付款、多收退回和多付退回、往来设置、收付款方式 | 作废对账单、收款、付款、退款 |
| 供应商账号 | 本家的邀请、采购单（含变更记录和取消原因）、本家对账单（含收款记录和抵扣多付）、入库单详情 | 提交填报；修改自己填报生成的待收货采购单 | 取消自己填报生成的待收货采购单 |
| 管理员 | 全部模块和全部日志 | 全部员工操作；员工与岗位 | 全部，含别人录的单据 |
| 所有员工 | 我的 → 库存查询（只读，只给没有仓库模块权限的普通员工；有仓库权限的员工和管理员直接用仓库「库存」，2026-10-05 体验改版第 1 批）、自己做的操作的日志 | — | — |

- 多模块员工的权限是各模块的并集。
- 页面视图不等于账号权限（2026-10-02 交叉审查确认）：管理员、多模块员工进入发货页面也不显示单价、金额；有销售、财务权限的，到对应模块查看金额。财务售后弹层一律只读；兼有销售权限的人到销售模块处理，不能在财务弹层作废。
- 取消、作废的归属（2026-10-02 梳理确认）：
  - 员工录的单据：本人做错了可以取消、作废（满足第 5 节前提）；同模块别人录的，找管理员。
  - 门店的单据（门店下的订单、门店申请的售后）：只有销售能取消、作废，其他模块不能。待确认订单任何销售都能处理；确认以后归确认它的销售，售后归处理它的销售。
  - 供应商的单据（填报生成的采购单）：只有采购和仓库能取消、作废，其他模块不能。收货前由采购取消，归发邀请的采购员；收货后由仓库作废，归收货的人。供应商自己也能在收货前修改、取消。
  - 财务的对账单、收款、付款、退款归登记的人。
- 每个接口都按角色和数据归属校验：门店只读写本店，供应商只读写本家。
- 登录落点：门店账号进订货；供应商账号进填报；只有一个模块的员工直接进模块首页；管理员和多模块员工进花众首页。门店、供应商不设首页。只有单独仓库岗位员工有「首页 / 库存 / 我的」底栏；其他单模块员工没有模块底栏，子页左上返回模块首页。
- 账号：员工、门店、供应商的手机号由管理员（门店由销售、供应商由采购）预先录入，首次进入用手机号快速验证绑定微信。员工、门店账号、供应商账号都有「登录手机号」字段，启用的账号里不能重复。账号停用后不能登录；门店停用后，这家门店的账号也不能登录，提示「这家门店已停用，请联系花众」（和供应商一致）。一个门店一个账号，不做门店切换。退出登录就是解绑这台微信，下次进入要重新用手机号验证。

## 3. 单据与状态

| 单据 | 状态 | 谁改变状态 |
|---|---|---|
| 订单 | 待确认 → 待发货 → 已发货 → 已作废；待确认、待发货 → 已取消 | 门店下单是待确认（没有出货日期），销售确认时定出货日期、变成待发货；销售新建直接是待发货；发货在出货日期当天或以后确认发货；门店（待确认时）或销售取消，销售同意门店的取消申请也变成已取消；销售作废已发货订单 |
| 订单取消申请 | 待处理 → 已同意 / 已拒绝 / 已撤回 / 已失效 | 门店对待发货订单提交、撤回；销售同意或拒绝；处理前确认发货，申请自动失效 |
| 售后 | 待处理 → 已处理 / 已关闭；销售新建直接是已处理；已处理 → 已作废 | 门店提交，销售处理或关闭；销售作废 |
| 收款、付款 | 有效 → 已作废 | 财务登记、作废 |
| 对账单 | 未结清 / 已结清 / 已作废 | 财务开单；收付款整张结清；零或负金额生成即结清；未收过款可作废 |
| 多收退回、多付退回 | 有效 → 已作废 | 财务 |
| 填报邀请 | 待填报 → 已提交 / 已取消 | 采购发出、修改、取消；供应商提交；停用供应商或关闭账号时自动取消 |
| 采购单 | 待收货 → 已收货 / 已拒收；待收货 → 已取消；已收货 → 已作废 | 采购新建或供应商提交生成；仓库收货；采购或供应商取消；仓库作废 |
| 手工入库单 | 已入库 → 已作废 | 仓库 |
| 手工出库、报损 | 已出库 / 已报损 → 已作废 | 仓库，不能修改 |
| 盘点 | 已盘点 | 仓库，不能修改或作废 |

卡片标记：订单「改单」「申请取消」；采购单「改单」「改价」「已全部退货」；手工入库单「改价」；对账单「逾期 n 天」。

外部端（门店、供应商）不出现「已作废」（2026-10-03 改版）：订单、采购单的已作废在门店端、供应商端显示成「已取消」，原因写「取消原因」，筛选「已取消」同时包含两者；数据里的状态不变，员工端照常显示已作废。售后同样：已作废的售后门店端显示成「已取消」，原因写「取消原因」（2026-10-03 用户确认）。

## 4. 金额与库存计算

名称全站统一，不换叫法。金额在后端按「分」算，四舍五入到分。

| 名称 | 算法 |
|---|---|
| 订单金额 | Σ 数量 × 单价（发货前显示） |
| 发货金额 | Σ 实发 × 单价 |
| 售后金额 | Σ 售后数量 × 售后单价；单价默认发货单价，只能改低 |
| 客户对账单应收 | max(0, 发货金额 − 售后金额 − 抵扣多收 + 期初欠款) |
| 采购金额 | Σ 采购数量 × 单价；已收货后 Σ 净实收 × 当前单价 |
| 净实收 | 实收 − 退货 |
| 供应商对账单应付 | max(0, 收货金额 − 退货金额 − 抵扣多付 + 期初欠款) |
| 未对账 | 还未进有效对账单的业务单据净金额；负数售后和退货也包含 |
| 未结清 | 有效未结清对账单的应收 / 应付合计 |
| 多收 / 多付 | 有效资金来源金额 − 已抵扣金额 − 有效退回；资金来源包括收付款超额及负额对账单生成的差额 |
| 未收 / 未付 | max(0, 未结清 + 未对账 + 尚未入单的期初欠款 − 当前多收 / 多付余额) |

### 4.0 对账单与收付款（2026-10-04）

- 客户对账单按客户开，包含旗下门店并按门店分组；供应商对账单按供应商开。单号前缀 DZ；对账期间默认「上一张有效对账单截止日的次日 ~ 今天」（上一张截止日已是今天或更晚时，起点取今天），这家第一次对账默认从最早一笔未对账单据日期开始（没有可对账单据就是今天），都可改；开单日期为今天。保存期间、开单人、备注、付款截止、结清日期和作废留痕。
- 客户来源：实际发货日期在期间内、未作废且未进有效对账单的订单，以及按处理日期选取的已处理售后（负数）。期间开始前仍未对账的也列出，标「上期未对账」、默认勾选。售后可晚于原发货单进入下一张对账单。
- 供应商来源：按实际收货日期选已收货采购单、按入库日期选手工入库单。采购单主行保存开单时净实收现价金额（已含退货和改价）；退货负数及改价差额作为展示凭据，标不参与再次合计。不得把净额再减退货或再加改价。拒收不进对账。每一来源只能占用一张有效对账单。
- 原始单据金额不可变更后再改已开对账单金额。订单、售后、采购单、手工入库单进入有效对账单后，其作废、退货、改价均禁用并返回「已进对账单 DZ-…，请先由财务作废对账单」。
- 应收 / 应付为发货 / 收货减售后 / 退货，自动抵扣这家现有多收 / 多付，第一张有效对账单加入期初欠款。抵扣最多到本张待收 / 未付的正金额，剩余余额保留；原始净额为负时应收 / 应付记 0，差额生成可追溯的多收 / 多付。0 元、负额生成即已结清，无部分结清。
- 账期选填非负整数天；付款截止 = 开单日期 + 账期。未设时为空且不算逾期。按上海业务日期，截止当天不逾期，次日逾期 1 天；只算未结清对账单。
- 只有没有有效收付款关联的对账单能作废，原因必填。作废单留在财务历史，来源回到未对账、抵扣余额退回；门店、供应商隐藏作废单。负额单生成的多收已抵扣或退回时，先作废下游单据再作废来源。
- 登记收款 / 付款：选客户 / 供应商，可以勾多张未结清对账单，也可以一张不勾。默认金额为所勾应收 / 应付之和；日期不晚于今天；方式为启用的收付款方式；优惠金额和优惠原因都选填（2026-10-05 用户确认：必填原因只留作废、取消等，优惠原因不再必填）；方式默认本账号上次用的，没有就手选；从客户 / 供应商往来进入默认勾选全部未结清对账单，可取消。
- 勾了单时，实际金额 + 优惠金额必须不少于所勾合计，否则提示「还差 ¥x，填优惠或少勾一张」。勾选单全部结清，超额记为多收 / 多付；一张不勾时实际金额整笔记余额，不能无对应欠款登记优惠。优惠不能凭空生成现金余额。
- 作废收付款仅本人或管理员可做，必填原因；有关对账单恢复未结清、该笔多收扣回。此笔余额已抵进后续 DZ 对账单时必须先作废那张对账单；有有效退回也要先作废退回。
- 多收 / 多付退回从往来详情登记，金额不超过当前余额，按来源登记时间、id 先后取用并保存来源去向，不能超退；退回作废恢复原余额。
- 往来设置可改账期，期初欠款只在从未开过对账单时可改；都记日志。作废首张且无其他有效对账单后，期初欠款释放回首张待入单状态，但设置仍锁定，不能再改。
- 不做按业务单据核销、预收预付核销、撤回核销及全账历史重新分配。并发只复核当前所选对账单版本、归属、未结清状态与余额，不使用 ledgerToken。
- 售后可申请数量 = 实发 − 同一订单同一产品已处理和待处理售后；关闭、作废后恢复。售后金额不能超过对应实发金额。

- 库存：每次入库（采购收货、手工入库）生成一个批次。出库按入库时间先进先出；采购退货、作废已收货采购单、作废手工入库单先扣这张单入库的批次，不够再先进先出；作废手工出库、报损按原来扣的批次加回。库存不够不能出库、报损、退货、作废入库类单据。
- 在途 = 待收货采购单的采购数量，不分到货日期；待填报的邀请不算。采购需求余量 = 实际库存 + 在途 − 出货日期区间内待发货订单按配方拆出的花材合计，负数是缺口。待确认订单没有出货日期，不算。

## 5. 修改、取消、作废条件

- 已发货订单的实发、已处理的售后不能修改，填错了走反向单据：实发记多了（实际少发），销售新建售后冲减，原因选「数量不符」；实发记少了（实际多发），销售补建一张订单；整张记错了，满足前提时销售作废已发货订单再重建；售后记多了，先作废再按正确数量新建。
- 作废的记录保留、标「已作废」，不能恢复。
- 主数据（客户、门店、产品、花材、供应商、收付款方式、出库分类）只停用不删除，历史单据照常显示。停用的客户不能再下新单（旗下门店也不能下单），但门店账号照常登录，能看订单、售后、对账（2026-09-30 确认）；订货页顶部提示「这个客户已停用，不能再下新单，请联系花众」，订货页仍可查看产品；购物车和「订货」标签角标保留，「去下单」禁用并写同一句提示，重新启用后可以接着下单。这个客户已有的待确认订单和门店停用时一样处理：门店不能改、能取消；销售不能确认，能取消；待发货的照常发货（阶段 3 确认）。停用的产品不能加进订货目录和新订单，已有的待发货订单不改就照常发货。
- 产品分类不属于上面的主数据：没有产品（含停用的产品）时可以删除，有产品时要先把产品移到别的分类（阶段 3 确认，照原型）。
- 产品管理和订货目录分开（2026-10-03 确认）：产品本身（名称、单位、图片、内部分类、配方）所有客户共用；订货目录（订货价、可订、客户产品编码、订货分类）每个客户一份。
- 产品分类是内部分类（初始「单品」「花束」，可新建、改名、排序、删除），只在产品管理里用，门店订货页不用它（2026-10-03 确认）。
- 订货分类（2026-10-03 确认）：每个客户一套，在订货目录里维护；产品加进目录必须选一个订货分类。规则同产品分类：同一客户内不重名、新增排最后、上移整组提交、分类下有目录产品（含停用的）不能删（「分类中仍有目录产品，请先换分类」）。新客户目录为空，先建分类再加产品，或者「从其他客户复制」（2026-10-02 梳理确认）：只在这个客户目录为空时可用；只复制来源客户启用且可订的目录项，带订货分类、订货价、可订，不带客户产品编码；复制前提示「将复制 N 个产品，跳过 M 个已停用或不可订的」；复制后两边各自独立。门店订货页左侧按这个客户的订货分类排，只列有可订产品的分类。
- 客户产品编码（2026-10-03 确认）：选填，同一客户内不重复（「这个客户下已有相同的产品编码」），不同客户可以重复。显示在订货目录、门店订货页、订单明细（对账点进订单也能看到）。下单时和名称、单位一起快照进订单行，之后改编码旧单不变；销售改单原有行保留原编码，新加的行取当前编码。
- 订货目录里改配方（2026-10-03 确认）：目录弹层里改的是产品本身的配方，所有客户跟着变；和这个客户的目录产品一起保存、同一事务，保存前确认「配方所有客户共用，改后所有客户的这个产品都会变」。
- 每次确认、保存、取消、作废前后端都按当前状态和版本号复查；变了就拒绝并返回最新内容。
- 复制目录的「空」按没有任何目录产品判断，停用项也算已有项；已有空分类不影响复制。同名分类复用，只带来源中有可复制产品的分类，按来源顺序添加新分类，已有分类原顺序不动；来源没有可复制产品时提示「没有可复制的产品」，不写入。预览后来源或目标变了先重新预览，不按旧预览复制（2026-10-02 交叉审查确认）。

## 6. 必须互斥的操作

后端在事务里加锁或按版本号条件更新，保证下面每一对不会同时成功：

- 确认发货 ↔ 取消订单、修改订单、同意取消申请
- 门店申请取消、撤回 ↔ 销售修改订单、取消订单、同意或拒绝申请
- 确认订单 ↔ 门店改单、门店取消
- 订货目录调价（同步待确认订单的单价）↔ 确认订单
- 新建对账单 ↔ 作废其订单 / 售后、采购退货 / 改价 / 作废、手工入库改价 / 作废
- 作废已发货订单 ↔ 申请售后、新建售后
- 收货 ↔ 采购改单、采购取消、供应商改单、供应商取消
- 采购改单、采购取消 ↔ 供应商改单、供应商取消
- 登记收付款 ↔ 同一对账单收付款、作废对账单
- 抵扣余额新开对账单 ↔ 作废余额来源收付款、登记退回、其他开单抵扣
- 修改期初欠款 ↔ 开第一张对账单
- 作废收付款 / 退回 ↔ 同一来源的抵扣和退回
- 处理售后 ↔ 关闭售后
- 库存变动（出库、报损、退货、作废入库类单据、作废出库和报损、盘点）之间：锁住批次后按先进先出扣、按原批次加回，不能超扣
- 花材改单位与首次库存、业务记录、配方引用互斥：先引用则拒绝改单位，先修改则后续引用使用新单位。
- 盘点与作废旧库存单据共用花材锁；取得锁后再次核对盘点边界，不能仅凭锁前读取的按钮状态作废。

订货目录调价和门店改单按客户目录排队执行，先后顺序不影响结果：待确认订单的单价最终都等于新的目录价；门店拿调价前的版本提交会提示内容已变，刷新后重新提交（阶段 3 确认）。

上述互斥指不能基于同一份过期状态同时写成功；按正确先后重新核对后仍各自合法的操作可以依次成功，业务单据进入有效对账单后必须锁定。所有影响同一客户、供应商账本的开单、收付款、退回、作废和来源变更统一用往来方行锁串行复核；来源占用、整单结清、余额抵扣、日志和通知在同一事务内完成。批量确认 / 发货每张单独事务，成功的保留，失败的返回单号与原因。取消申请每次流转都提升订单版本，旧请求不能误处理撤回后重新发起的申请。

## 8. 各模块规则

### 8.1 销售、发货、门店端

- 订单状态五种：待确认、待发货、已发货、已取消、已作废。发货后订单结束，门店不确认收货；已发货订单整张记错了由销售作废（第 5 节）。
- 下单单价默认取订货目录价，销售可以改，改过的标「改价」。
- 待确认订单的单价始终等于目录价（阶段 3 确认）：销售改订货目录价时，这个客户待确认订单里这种产品的单价同时更新，只记在「修改订货目录」的日志里（写明改了哪些订单），不写变更记录、不标「改单」。销售改单时原有行保持原单价，新加的行默认目录价。
- 出货日期由销售定（阶段 3 确认）：门店下单、改单不选出货日期，待确认时没有出货日期，显示「待定」；销售「确认订单」时选出货日期（默认明天），新建、修改订单在表单里填，都可以选今天以前（补录）。门店能看到出货日期，只读。第一次定出货日期不写变更记录、不算改单，以后再改才写。
- 下单日期是录入那天，门店和销售都不能改；补录只补出货日期（阶段 3 确认）。
- 销售处理门店的待确认订单：取消、确认（弹层只选出货日期）或「修改后确认」（整页可修改产品、数量、单价、备注，修改原因选填，2026-10-05 用户确认）。
- 订单变更记录：门店改待确认的单、销售改单都写（改了什么、原因、谁、什么时候；门店改单没有原因）。销售、门店、发货的订单详情都显示，卡片标「改单」。内容没变的修改不写。
- 原单里有已停用的产品：门店改单的确认订单页、销售的订单表单都标「已停用」，拦住保存，提示先删掉，不悄悄去掉；这样的待确认订单可以进「确认订单」删掉停用产品后提交，也可取消；批量确认不能含停用产品。待发货订单不改就照常发货（阶段 3 确认）。门店改单把产品全删光（例如只剩已停用产品、都删掉了）提交时提示「请先选择产品」，整单不要了用「取消订单」（阶段 3 确认）。
- 门店取消待发货订单（2026-10-02 梳理确认）：订单确认后门店不能直接取消，可以「申请取消」，原因选填。处理前门店可以撤回，撤回后还能再申请；被拒绝后这张单不能再申请，要找销售。同一时间只有一条待处理。销售在订单详情「同意取消」（订单变已取消，取消原因自动写「门店申请取消」加门店原因）或「拒绝」（原因选填，填了门店能看到；不填时门店只看到「取消申请被拒绝」，不带冒号后面的内容，2026-10-05 用户确认）；有待处理的申请时销售不能改单、不能直接取消，只能同意或拒绝。待处理的申请进销售首页待办「取消申请」（2026-10-03 改版），订单卡片标「申请取消」，订单列表可以按「申请取消」筛选。发货照常能发，发了申请自动失效，门店看到「已发货，取消申请未处理」。
- 发货默认按订单数量，可以少发、多发（实发不设上限）；实发和订单数量不一致可以写发货备注（选填，2026-10-05 用户确认），明细和卡片标「少发」「多发」，未对账金额按实发算。整单不发要由销售取消订单。出货日期到了（不晚于今天）才能确认发货；要提前发，由销售把出货日期改早（阶段 3 确认）。一张订单一次发完，不分批。
- 发货端（发货单列表、发货表单、发货详情）不显示单价和金额（2026-10-02 梳理确认）。
- 售后：门店只从已发货订单详情申请，每行选四种原因之一；问题说明选填；原因是「数量不符」（少发、漏发）时图片选填，其余三种原因至少 1 张图片（2026-10-05 用户确认，覆盖 2026-10-04 v33 的四种原因都必填说明和图片）；销售在客户售后确认数量和单价；售后金额 = 数量 × 单价，没有单独的金额框，处理说明选填。门店提交后不能撤回、修改。一次售后只针对一张订单。
- 门店申请售后的期限：实际发货那天起 `AFTER_APPLY_DAYS` 天（第 5 节）；过了期限门店不能再申请，提示联系花众销售，由销售新建（不限时间）。销售新建售后每行选原因，说明选填，不带图片（阶段 3 确认）。
- 销售处理门店提交的售后：门店填的原因、说明、图片只读，只改数量和单价。门店原来申请的数量另外保存，不被覆盖；售后详情（销售、门店两端）同时显示「申请数量」和「处理数量」。
- 作废售后：只有销售能做（售后详情，归处理它的销售）；财务在发货单弹层里只能查看售后详情（2026-10-02 梳理确认）。门店看到「已取消」和取消原因（外部端显示见第 3 节），不显示金额。
- 售后关联原订单，但按处理日期进入下一张对账单；不会改变已开对账单的内容和金额。
- 门店底栏「订货 / 订单 / 我的」，订单页顶部「订单 / 售后 / 对账」；无门店首页。订货页未加产品只显示红色＋，加过后才是步进器；改单独立购物车、门店名下写「修改订单　下单日期 …」。提交订单页只读门店名、下单日期和明细，可写备注，无出货日期。
- 门店改单用单独的一份购物车，改单时隐藏底部标签；放弃或提交后，原来的购物车还在。
- 购物车按账号存在这台手机上，关掉小程序还在，退出登录时清空。里面的产品停用了，打开订货页时自动去掉，提示一次「白绿清新花束已停用，已从购物车移除」（阶段 3 确认）。
- 门店对账按对账单查看本店金额，列表显示未结清、本店未对账与开单日期筛选；详情只列本店发货、售后和本店金额，不显示客户抵扣多收及收款记录，不需要确认。
- 销售待确认列表可多选一起确认，统一选出货日期（默认明天）、不改明细；客户 / 门店停用不可勾。逐单复核状态和版本，失败返回原因，其余成功。单张确认、新建订单、一起确认返回该客户逾期未结清金额和最早逾期天数，只提醒不拦截。
- 发货列表可多选确认，出货日期未到不可勾，实发按订单数量；逐单成功或失败。配货勾选只存这台手机，按订单及产品记录，发货后清除，不算服务器单据状态。发货详情提供联系人电话、地址，地址空写「未填」；已发货可生成无价格送货单图片，带收货人签字与签收日期。
- 销售「客户门店」与「订货目录」合成「客户」页，客户下切门店 / 订货目录；产品资料仍独立。
- 客户、门店、产品资料（阶段 3 确认）：客户名称必填、不重复，在客户门店页新建、改名、启用 / 停用。门店名称必填、同一客户下不重复；联系人、联系电话、地址选填，填了登录手机号（开通门店账号）时联系人必填，门店账号的名字就是联系人。改门店的登录手机号时，原来绑定的微信同时解绑，日志原因写「同时解绑微信」，和员工一致（阶段 3 确认）。产品名称必填、不重复；分类、单位必填；配方至少一种花材；启用开关在产品表单里。产品分类在产品管理里新增、改名、排序、删除（第 5 节）。
- 邀请订货：销售在门店资料或客户页底栏「邀请订货」（2026-10-05 体验改版第 1 批从销售订单列表挪来）把小程序卡片分享给门店，门店打开后用手机号快速验证，绑定到这家门店的账号（手机号要和门店账号的登录手机号一致）。链接有效期 `STORE_INVITE_TTL_DAYS`，绑定成功后失效；过期或已失效时显示「邀请已失效」和原因。同一家门店重新生成邀请时，旧的未使用邀请自动作废，同一时间只有一条有效。门店账号已经绑了一台微信，要先由销售或管理员在门店资料里解绑，才能用新邀请绑另一台。已经绑了别的账号的微信打开邀请：提示先在「我的」退出登录再接受邀请，不自动解绑，邀请不失效；已经是这家门店的账号，直接进订货（阶段 3 确认）。「门店接受邀请」的日志记在销售模块（阶段 3 确认）。
- 发货首页待办行「今日应发」只算出货日期不晚于今天的待发货订单，点进发货单只看到期的；入口只有「发货单」，不另设发货记录。发货单待发货里也能看到以后的单（不能确认发货）。

### 8.2 采购、供应商端

- 采购单状态：待收货、已收货、已拒收、已取消、已作废；没有草稿和预计到货日期。
- 待收货的单采购可以修改（包括换供应商）或取消，修改原因选填，取消必须写原因（2026-10-05 用户确认）。供应商填报生成的单不能换供应商。换了供应商后，原供应商端看不到这张单。收货后采购不能再改；已收货的单整张记错了由仓库作废（第 5 节）。
- 供应商改单、取消（2026-10-02 梳理确认）：供应商自己填报生成、还没收货的采购单，供应商可以修改（数量、单价、删行、另报启用的花材，至少一行、每行大于 0，原因选填），也可以取消（必写原因）。采购直接新建的单供应商只能看。改单写变更记录，采购、仓库、供应商三端都显示；取消后采购、仓库看到已取消和原因，邀请卡片显示已取消。
- 变更记录（改了什么、原因、谁、什么时候）采购、仓库收货页、供应商端都显示，卡片标「改单」。取消原因三端都能看到。
- 单价手填，可以是 0（赠送）。采购金额按净实收与单价计算，未开对账单前不叫应付。
- 采购需求：出货日期区间默认今天起 `DEMAND_DEFAULT_DAYS` 天，只算待发货订单，按配方拆成花材合计。停用花材照常计算、标「已停用」、不能勾选；配方通过 `materialId` 外键关联花材，保存时拒绝不存在的花材，不保留旧原型按名称匹配、找不到则跳过的逻辑。已邀请、还没提交的花材标「已邀请」，不算在途、缺口不变；来源里列出按出货日期和订单的明细，以及哪家、哪张邀请、邀请了多少。待确认订单不算（没有出货日期，确认后才进需求）。需求卡片的日期写这种花材实际涉及订单的出货日期区间（最早到最晚，例如「出货日期 2026-09-29 ~ 2026-10-03」，只有一天写「出货日期 2026-09-29」），不写筛选区间（2026-10-02 梳理确认）。不设安全库存。
- 采购需求自动同步（2026-10-02 采购优化确认）：订单确认、销售直接建单后自动纳入；待发货改单（数量、产品、出货日期）、取消或同意取消、确认发货后重新计算；配方、库存、在途变化也重新计算。事务提交后采购需求页自动刷新，回滚不发变化通知。这里是更新计算结果，不自动建采购单、发邀请或出库，不改变模块独立边界。
- 采购需求只看缺货花材（余量为负），不再分「全部 / 缺货 / 待填报」标签；填报邀请并入采购单页的「填报邀请」段（2026-10-05 体验改版第 1 批）。日期筛选今天、明天、未来 7 天、自定义，默认未来 7 天。同组按最早实际出货日期、花材编码、id 排列。逾期待发货订单另行提示「有 N 张逾期待发货订单，查看需求」，点击查看对应过去日期；不自动混进当前区间（2026-10-02 采购优化确认）。
- 在途可展开看采购单（供应商、采购数量、状态），提示「在途不代表已到库」；仍不分到货日期，不新增到货日期、安全库存或自动分配。未提交邀请单独列供应商、邀请单号、需求量，仍不算在途（2026-10-02 采购优化确认）。
- 再次邀请或下单前，有包含这些花材的待填报邀请就提示已有邀请，可点开原邀请，只提醒、不禁止。需求带入表单后，确认前复核最新需求、库存、在途；缺口变化先提示核对，保留已填数量、供应商、价格，采购员确认后可以按原数量继续。允许主动买得比缺口多，不自动改数量，不以超缺口为错误；复核与确认之间再次变化则重新提示（2026-10-02 采购优化确认）。
- 「新建采购单」：数量带入缺口（够用带 0，要改成大于 0），供应商、单价手填，完成后回到需求页，勾选清空。「邀请供应商」：一次只邀请一家已开通供应商账号的供应商，需求量默认缺口、可改；发出后跳到采购单页的「填报邀请」段（2026-10-05 体验改版第 1 批），回到需求页时勾选清空。
- 采购单页顶部宋体两段「采购单 / 填报邀请」（同门店订单页的分段做法）；填报邀请段标签「全部 / 待填报 / 已提交」，已取消在筛选里；底栏「新建采购单」两段都显示（2026-10-05 体验改版第 1 批）。
- 供应商填报邀请：待填报的可以修改（需求量、增减花材）、取消，不用原因。可以把邀请分享给供应商（小程序卡片），打开前要先登录，只有这家供应商的账号能打开。分享链接不另设有效期，跟着邀请走：邀请已提交或已取消，链接就失效，显示「邀请已失效」和原因。
- 供应商资料：名称必填不重复；联系人、联系电话、地址、启用；开通供应商账号要填 11 位登录手机号（不能和别家重复）。停用供应商或关闭账号后不能登录，这家待填报的邀请自动取消并记日志；已下的单照常收货和付款。
- 停用供应商或关闭供应商账号时保留微信绑定（`openid`、`bound_at`），关闭实时连接并显示账号停用状态；供应商和账号都重新启用后，原微信可直接恢复使用，无须重新验证手机号。改登录手机号仍按下一条解绑（阶段 4 确认）。
- 供应商账号修改登录手机号时同时解绑微信，清空 `openid`、`bound_at`，关闭该账号的实时连接；日志原因「同时解绑微信」。下次须用新手机号重新验证绑定（阶段 4 确认）。
- 供应商底栏「填报 / 采购单 / 我的」，无首页；待填报数放填报标签角标。采购单页顶部「采购单 / 对账」。填报时每行实际供货量大于 0（不供的行删掉，可多可少）、单价（赠送填 0），可以另报启用的花材；邀请中已停用的花材标「已停用」，数量和单价只读，只能删行；供应商自己删掉就能提交，不用等采购修改邀请。提交行（邀请行和另报行）含停用花材 → `BUSINESS_RULE`「花材已停用，请删掉这一行再提交」；未提交的邀请行算「未供」，需求快照保留，不影响生成采购单（阶段 4 确认）；提交就生成待收货采购单，采购员是发邀请的人。采购单详情不放货款进度，显示所属对账单 / 未对账。对账只看本家有效对账单，供应商角度叫「应收」，显示收货、退货、抵扣多付与收款记录，不需确认。

### 8.3 仓库

- 仓库首页待办「待收货 / 放久了 n 种」；常用「收货 / 出库 / 报损 / 盘点」和整行「手工入库」。取消手工入库单、手工出库单、报损单三个独立列表；历史从花材详情 → 本花材出入库记录 → 单据详情查看和作废。盘点入口进「盘点记录」。
- 收货点行填实收（默认采购数量）和单价，差异标少收 / 多收 / 改价；改价原因选填（2026-10-05 用户确认，只有作废、取消的原因必填）。实收全 0 为拒收，拒收不进对账；也可以只拒收其中几行（行小窗口「拒收此行」，实收记 0，该行不计入库存和对账，整单仍按其余行收货）（2026-10-05 用户确认）。收货 / 拒收做完回到待收货列表。采购途中改单或取消，收货页实时刷新。
- 收货后未进有效对账单可退货、改价和满足库存 / 盘点边界时作废；进有效对账单后上述操作均禁用，必须先由财务作废对账单。一张采购单一次收完，不分批；全部退货后净额为 0，不再退货或改价。
- 停用的花材：已下单的采购单照常收货；不能入库，也不能加进采购单、邀请、填报和配方；还能出库、报损、盘点。
- 花材：名称（可以重复）、编码（自动生成：前缀 `MATERIAL_CODE_PREFIX` + 四位序号，新建表单预填下一个编号，可改，不能重复；留空提交时服务端在同一事务里取下一个，保证唯一）、单位、分类（从分类列表选，分类可新建、改名）、启用。只有没有库存批次、流水、盘点、出入库单、采购单、邀请或填报记录、配方引用的花材能改单位；已有记录即使剩余库存为 0、单据取消或作废也不能改。需要另一单位时新建花材，不自动换算；不改单位时仍能改其他资料（2026-10-03 ERP 审查后确认）。
- 手工入库直接新建，供应商必选启用项，数量和单价（可 0），原因选填。未进有效对账单时可改价（原因选填）、作废（必填原因，并校验归属、库存与盘点边界）；进单后锁定。花材详情灰字「手工入库」带入本花材，保存后进详情。
- 手工出库直接新建；历史从花材出入库记录查，保存后进详情；花材详情可带本花材开始出库。
- 手工出库必须选出库分类，原因选填。出库分类阶段 5 实现，可改名、新建、启用 / 停用，至少保留一个启用的；初始分类：生产领用、门店零售、样品、其他（生产模块不做，「生产领用」照样保留，用于领花材做花束）。
- 报损原因选填，图片选填（2026-10-02 梳理确认；2026-10-05 原因改选填，全系统只有作废和取消的原因必填）。
- 手工出库、报损录错了，录的人可以作废（必写原因），库存按原来扣的批次加回；盘点不能作废，填错了再盘一次（2026-10-02 梳理确认）。
- 盘点先选花材分类（可多选），只列这些分类的花材（停用的也列）；账面默认等于当前库存，差异原因选填（2026-10-05 起），确认后直接调整库存；新建盘点选分类时默认全选，可取消勾选。确认时后端复查账面数：打开盘点后库存又变了（例如有人出库），拦住并提示「库存已变化，已刷新账面数，请核对后再确认」，已填的实盘数保留。
- 库龄按批次入库时间对应的上海日期与今天之差算已放天数，只算剩余量大于 0 的批次；最早剩余批次满 3 天归「放久了 · 先用」，待办按花材种数去重，琥珀色提醒。只读库存查询不显示库龄、不分组。
- 批次按入库时间先进先出。阶段 4 在花材详情显示入库日期和剩余数量，不编批次单号；出入库记录显示完整年月日，并按带周几的日期组头分组。
- 盘点确认后（含无差异盘点），不能再作废原库存流水已被该次盘点覆盖的采购收货、手工入库、出库或报损单；整单任一花材被覆盖即拒绝，不能重复冲回盘点已确认的数量。按花材锁内的库存流水顺序判断，不按单据日期、交易开始时间或是否盘盈盘亏判断。其他花材的盘点、新盘点后的库存单据不受影响；正常实际退货和改价不受此限制。需要纠正时按实物登记新的出入库或重新盘点，不能凭空加减（2026-10-03 ERP 审查后确认）。
- 明细编辑统一表格点行改，添加后打开同一个编辑小窗口；删除和确定在窗口底部，见 02 章第 6 节。

### 8.4 财务

- 内部来源详情的「对账单」链接可打开只读 DZ：销售仅客户对账单，采购 / 仓库仅供应商对账单，管理员均可；actions 为空。发货岗位不读取金额，不因此扩展财务写权限。

- 首页待办只放财务该动手的事（2026-10-05 体验改版第 1 批）：「逾期未收」（过了付款截止仍未结清的客户对账单张数）；「客户可开对账」（有已发货订单还没进有效对账单的客户家数）；「供应商可开对账」（有已收货采购单或手工入库还没进有效对账单的供应商家数）；只有售后、退货、改价凭据的不算。不再放「待收款」「待付款」（在等对方付钱）。常用客户对账、供应商对账、收付款记录；收付款方式从我的进入，财务首页不加资料格，不显示今日数字。
- 客户对账、供应商对账列表标签「全部 / 有未收（有未付）/ 有逾期 / 有未对账」；「有未对账」只列有已发货 / 已收货来源还没进有效对账单的往来单位，按未对账金额从大到小排；首页「客户可开对账」进客户对账、「供应商可开对账」进供应商对账的这个标签（2026-10-05 体验改版第 1 批）。
- 财务往来列表显示未收 / 未付、未对账、对账截止、最近收付款、多收 / 多付及逾期；往来详情总账显示未收 / 未付、未结清、未对账，余额有退回入口；账期与期初欠款通过往来设置修改。
- 往来详情切「对账单 / 未对账」，作废对账单保留灰色历史；未对账来源按门店分组（供应商不分门店）。底栏新建对账单、登记收付款。
- 收付款、抵扣、退回、锁定与作废规则统一见第 4.0 节；取消所有单据核销入口，不单独开财务业务单据详情页。
- 对账单分享生成整张图片：往来方、单号、开单日期、付款截止、对账期间、按门店列发货单 / 供应商收货来源、发货 / 收货与售后 / 退货、抵扣、期初欠款、应收 / 应付、已收 / 已付、状态及生成时间。保存图片、发给微信好友，对方无需登录。
- 收付款记录顶部收款 / 付款，搜索、全部 / 已作废、日期筛选；每笔显示单号、业务日期、方式、金额及对账单（多张摘要）。收付款详情展示优惠、多收 / 多付、登记人、登记时间、备注及所收付对账单。
- 收付款方式只有一份启用列表，同一种方式用于收款、付款、退回；名称不重复，至少保留一种启用。

### 8.5 公共

- 花众首页是品牌形象：用窗格放本人有权限的模块，墙面背景和底栏不变，不加「待我处理」清单、不显示身份行；格子右上角红色角标是该模块待办数（只算「该我动手」的事）；门店、供应商无首页。
- 模块首页待办并排小卡（大数字，0 也显示，点进筛好的列表）→ 常用大窗格 → 可选资料小格，不写今日数字、不写身份行，不加待处理单据清单和批量底栏。待办只放「该我动手」的事，「在等对方」的（等供应商填报、等仓库收货、等客户付款、等门店确认等）不进待办和角标（2026-10-05 体验改版第 1 批）：销售待确认订单 / 取消申请 / 待处理售后；发货今日应发；采购「缺货花材 n 种」（采购需求默认区间——今天起 `DEMAND_DEFAULT_DAYS` 天——内余量为负的花材种数，含停用花材，点进采购需求）；仓库待收货 / 放久了；财务见第 8.4 节。
- 仓库单岗位员工底栏「首页 / 库存 / 我的」；其他单岗位员工没有模块底栏，其他员工遵循 06 章导航。无仓库权限员工从我的只读查询全部花材（含 0 库存），有仓库权限用仓库库存。
- 「我的」：身份格写姓名，下面带字段名写「岗位 …　登录手机号 …」（门店写「门店 客户 · 门店」，供应商写「供应商 …」），不再有「个人资料」；财务和管理员加「收付款方式」；管理员没有库存查询；门店、供应商账号加「联系花众」，点了拨打花众客服电话（2026-10-03 改版）。组件总览只在开发版出现，体验版、正式版都没有。
- 门店「我的」加对账卡：每张本店有份的未结清对账单一行，写本店未付（这张对账单里本店的金额），下面一行小字写整张对账单的合计和覆盖几家店（例如「整张合计 ¥3,588.00（晨曦花艺 2 家店）」），再写付款截止（未设账期写开单日期）、对账单号，点进对账单详情；没有时写「没有未结清的对账单」。供应商「我的」同样做法，写未收货款（这张对账单的应收）、付款截止、对账单号（2026-10-05 体验改版第 1 批）。
- 我的和员工列表的岗位：管理员写「管理员」，员工写模块名，多个用「、」连（例如「销售、仓库」），员工与岗位列表同一写法（2026-10-03 确认）。
- 管理员看全部日志，员工只看自己做的操作的日志（2026-10-02 梳理确认，取代「看自己模块的日志」）。日志记操作人、时间、动作、对象、原因、修改前后，前端不能改。账号类操作（绑定微信、解绑微信、新建员工、修改员工）不属于任何模块，记为「公共」，只有管理员能看（2026-10-03 确认）。
- 员工调岗后仍能看自己在原模块做过的非公共历史操作；列表、详情、模块筛选都按本人历史范围，不用当前岗位把历史操作裁掉。不能借选原模块看到别人的日志（2026-10-02 交叉审查确认）。
- 员工与岗位（2026-10-03 确认）：打开「管理员」开关后不再选模块（管理员默认全部模块），「请至少选一个模块」只对普通员工；关掉开关恢复原来选的模块。管理员改了员工的登录手机号或停用员工，原来绑定的微信自动解绑，日志写明；员工已绑定微信时，管理员可以在员工弹层里「解绑微信」，对方下次打开要重新手机号验证。
- 登录页的隐私保护指引没勾选时，「手机号快速验证登录」照常可点，点了提示「请先阅读并同意隐私保护指引」、勾选框轻微抖动，不弹手机号授权（2026-10-03 确认）。
- 列表卡片按字段完整排布，不为三行限制省略字段名；筛选最多三项：状态是列表上方的标签行，等待类状态显示数量（门店、供应商端在等花众处理的状态——门店订单待确认 / 待发货、门店售后待处理、供应商采购单待收货——不显示数量，2026-10-05 体验改版第 1 批）；日期、对象放进筛选按钮的弹层，改了立即生效，设了条件在列表上方显示可去掉的胶囊（外观见 02 章第 4 节 `hz-filter-bar`）；状态标签一行最多 4 个，结束类状态放进筛选弹层；新建、邀请类操作固定在列表页底栏。
