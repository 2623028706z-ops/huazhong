# 03 业务规则

整理日期：2026-09-30。来源是冻结原型的 README、INFORMATION-ARCHITECTURE、MIGRATION-SPEC（含第 9 节 P1–P13 确认记录），这里只保留「系统应该怎样」，去掉原型的实现细节。规则有冲突时以本章为准，改规则先确认。

2026-10-02 交叉审查确认：本轮接受的业务边界、采购优化已并入正文；已有「2026-10-03 / 10-06 确认」标记仅保留原记录，不据此推断实际确认日期。

## 1. 范围

- 模块：销售、发货、采购、仓库、财务；外部端：门店端、供应商端；公共：登录、花众首页、我的、库存查询、日志、员工与岗位。
- 不做：生产模块、成品库存、订阅消息、老系统数据迁移、电脑版和 iPad 适配。
- 库存只管花材。发货不扣库存，库存靠仓库手工出库。
- 各模块是独立业务，数据实时同步，不做跨模块自动关联（例如采购需求不关联仓库出库）。

## 2. 角色与落点

| 角色 | 能看 | 能新建、修改 | 能取消、关闭、作废 |
|---|---|---|---|
| 门店账号 | 本店订单（含变更记录、取消申请）、售后（含作废原因）、对账（含每张发货单的核销记录） | 下单；改待确认的单；申请售后；对待发货订单申请取消、撤回申请 | 取消待确认的单 |
| 销售 | 全部订单、售后、客户门店、产品、订货目录 | 新建订单、确认订单（定出货日期）、修改并确认待确认订单、改待发货订单；同意、拒绝门店的取消申请；新建、处理售后；客户、门店、产品和产品内部分类、订货目录和订货分类 | 取消订单；作废已发货订单；关闭售后；作废已处理售后；删除没有产品的产品内部分类、没有目录项的订货分类 |
| 发货 | 待发货、已发货订单（含变更记录），不显示单价和金额 | 确认发货（可少发、多发） | — |
| 采购 | 采购需求、采购单、邀请、供应商 | 新建、修改采购单；发出、修改邀请；供应商资料和供应商端账号 | 取消采购单；取消邀请；停用供应商 |
| 仓库 | 待收（含已取消）、手工入库单列表、库存、花材、出入库记录、盘点 | 收货、拒收、退货、改单价；手工入库、出库、报损、盘点；花材和分类、出库分类 | 作废已收货采购单、手工入库单、手工出库、报损 |
| 财务 | 客户对账、供应商对账、收付款记录、已处理售后金额 | 登记收款、付款；核销预收、预付；登记预收退款、预付退款；收付款方式 | 作废收款、付款、退款；撤回单条核销 |
| 供应商账号 | 本家的邀请、采购单（含改单记录和取消原因）、对账（含付款记录和预付）、入库单详情 | 提交填报；修改自己填报生成的待收货采购单 | 取消自己填报生成的待收货采购单 |
| 管理员 | 全部模块和全部日志 | 全部员工操作；员工与岗位 | 全部，含别人录的单据 |
| 所有员工 | 我的 → 库存查询（只读，有仓库模块权限的员工不显示，直接用仓库「库存」）、自己做的操作的日志 | — | — |

- 多模块员工的权限是各模块的并集。
- 页面视图不等于账号权限（2026-10-02 交叉审查确认）：管理员、多模块员工进入发货页面也不显示单价、金额；有销售、财务权限的，到对应模块查看金额。财务售后弹层一律只读；兼有销售权限的人到销售模块处理，不能在财务弹层作废。
- 取消、作废的归属（2026-10-02 梳理确认）：
  - 员工录的单据：本人做错了可以取消、作废（满足第 5 节前提）；同模块别人录的，找管理员。
  - 门店的单据（门店下的订单、门店申请的售后）：只有销售能取消、作废，其他模块不能。待确认订单任何销售都能处理；确认以后归确认它的销售，售后归处理它的销售。
  - 供应商的单据（填报生成的采购单）：只有采购和仓库能取消、作废，其他模块不能。收货前由采购取消，归发邀请的采购员；收货后由仓库作废，归收货的人。供应商自己也能在收货前修改、取消。
  - 财务的收款、付款、核销、退款归登记的人。
- 每个接口都按角色和数据归属校验：门店只读写本店，供应商只读写本家。
- 登录落点：门店账号进门店首页；供应商账号进供应商首页；只有一个模块的员工直接进模块首页（没有返回）；管理员和多模块员工进花众首页（2026-09-30 确认门店、供应商也有首页）。
- 账号：员工、门店、供应商的手机号由管理员（门店由销售、供应商由采购）预先录入，首次进入用手机号快速验证绑定微信。员工、门店账号、供应商账号都有「登录手机号」字段，启用的账号里不能重复。账号停用后不能登录；门店停用后，这家门店的账号也不能登录，提示「这家门店已停用，请联系花众」（和供应商一致）。一个门店一个账号，不做门店切换。退出登录就是解绑这台微信，下次进入要重新用手机号验证。

## 3. 单据与状态

| 单据 | 状态 | 谁改变状态 |
|---|---|---|
| 订单 | 待确认 → 待发货 → 已发货 → 已作废；待确认、待发货 → 已取消 | 门店下单是待确认（没有出货日期），销售确认时定出货日期、变成待发货；销售新建直接是待发货；发货在出货日期当天或以后确认发货；门店（待确认时）或销售取消，销售同意门店的取消申请也变成已取消；销售作废已发货订单 |
| 订单取消申请 | 待处理 → 已同意 / 已拒绝 / 已撤回 / 已失效 | 门店对待发货订单提交、撤回；销售同意或拒绝；处理前确认发货，申请自动失效 |
| 发货单收款 | 未收 → 部分收 → 已收（门店端：未付 / 部分付 / 已付） | 由有效核销算出，不单独存 |
| 售后 | 待处理 → 已处理 / 已关闭；销售新建直接是已处理；已处理 → 已作废 | 门店提交，销售处理或关闭；销售作废 |
| 收款、付款 | 有效 → 已作废 | 财务登记、作废 |
| 核销 | 有效 → 已撤回 | 财务登记收款、付款或核销预收、预付时生成；财务撤回单条；作废收款、付款时全部撤回 |
| 预收退款、预付退款 | 有效 → 已作废 | 财务 |
| 填报邀请 | 待填报 → 已提交 / 已取消 | 采购发出、修改、取消；供应商提交；停用供应商或关闭账号时自动取消 |
| 采购单 | 待收货 → 已收货 / 已拒收；待收货 → 已取消；已收货 → 已作废 | 采购新建或供应商提交生成；仓库收货；采购或供应商取消；仓库作废 |
| 采购单、手工入库单付款 | 未付 → 部分付 → 已付；应付 0 显示「无需付款」 | 由有效核销算出，不单独存 |
| 手工入库单 | 已入库 → 已作废 | 仓库 |
| 手工出库、报损 | 已出库 / 已报损 → 已作废 | 仓库，不能修改 |
| 盘点 | 已盘点 | 仓库，不能修改或作废 |

卡片标记：订单「改单」「申请取消」；采购单「改单」「改价」「已全部退货」；手工入库单「改价」；发货单「售后抵扣」。

## 4. 金额与库存计算

名称全站统一，不换叫法。金额在后端按「分」算，四舍五入到分。

| 名称 | 算法 |
|---|---|
| 订单金额 | Σ 数量 × 单价（发货前显示） |
| 发货金额 | Σ 实发 × 单价 |
| 售后金额 | Σ 售后数量 × 售后单价；单价默认发货单价，只能改低 |
| 应收 | 发货金额 − 已处理售后 |
| 已收、未收 | 已收 = 这张发货单的有效核销生效金额；未收 = 应收 − 已收（门店端叫待付） |
| 预收 | 每笔有效收款 − 它的核销生效金额 − 它的有效退款，不小于 0；客户预收是各笔合计 |
| 采购金额 | Σ 采购数量 × 单价 |
| 净实收 | 实收 − 退货 |
| 应付 | 采购单：Σ 净实收 × 单价（只算已收货、没作废）；手工入库单：Σ 数量 × 单价（没作废） |
| 已付、待付 | 已付 = 这张单的有效核销生效金额；待付 = 应付 − 已付 |
| 预付 | 每笔有效付款 − 它的核销生效金额 − 它的有效退款，不小于 0；供应商预付是各笔合计 |

收款和付款是同一套规则（2026-10-02 梳理确认，按常规财务做法）：

- 收款、付款按客户、供应商登记实际收到、付出的金额，再核销到单据（发货单；采购单，手工入库单阶段 5 接入）。登记时默认按出货日期、收货日期从早到晚自动填入核销，每条不超过单据的未收、待付和这笔钱剩下的金额，财务可以改；没核销的记为这笔钱的预收、预付，以后「核销预收」「核销预付」。
- 核销生效金额：按核销登记时间依次算，每条 = min(登记金额, 单据剩余应收或应付, 这笔钱扣掉已退款后的剩余)，小于等于 0 记 0。单据金额变化（售后、退货、改价、作废）或作废收付款、撤回核销、作废退款后全部重算，同一笔钱不会算两次，预收、预付不会是负数。
- 单据收清、付清后金额变少（确认售后、退货、改价），多出的钱自动回到对应那笔钱的预收、预付。付款后仍可以退货、改价，不再有「付过款就锁定」。
- 登记错了不改原记录，只做反向操作：整笔错了作废这笔收款、付款（核销全部撤回）；某一条核销错了单独撤回（写原因），释放的金额参与这笔钱的全账重算，未被其他历史核销用掉的才成为预收、预付。
- 「有效核销」指所属收付款有效且核销未撤回，不等于「生效金额大于 0」（2026-10-02 交叉审查确认）。作废业务单据前，生效金额为 0 的有效核销也必须先撤回；财务详情保留全部核销历史和撤回入口，外部对账只列生效金额大于 0 的核销。
- 全部重算仍按核销登记顺序，不改登记金额。旧单据金额恢复时，旧核销可能恢复生效并占用已用于其他单据的余额，其他单据因此重新出现未收、待付；已退款的钱不会再参与核销。撤回某条后其他历史核销也可能恢复，因此提示和页面以重算后的真实余额为准，不承诺「撤回多少，余额一定增加多少」。
- 多笔预收、预付按收付款的登记时间先后取用，同一时刻按 id；不按可以补录的业务日期。核销生效顺序按核销登记时间、id，两种顺序不要混用。
- 预收、预付可以退款：选从哪一笔收款、付款里退，金额不超过这笔的预收、预付，日期不晚于今天；退款错了作废重登。
- 不做会计期间结账；收付款、退款日期可以补录以前的，不能晚于今天。

- 售后刚好抵完、应收 0 的发货单：状态仍是已收（门店端已付），标「售后抵扣」。
- 售后可申请数量 = 实发 − 同一订单同一产品已处理和待处理的售后；关闭、作废后恢复。售后金额不会超过发货金额。
- 财务待付款只列待付大于 0 的有效已收货采购单、手工入库单；供应商对账列有效且应付大于 0 的单据，包含未付、部分付、已付（2026-10-02 交叉审查确认）。已拒收、全部退货、全部赠送、0 元入库、已作废的两边都不进，历史仍从业务单据和收付款详情查看。
- 客户对账：发货金额、售后、已收、未收，另外单独显示预收和退款记录。门店对账：发货金额 − 售后 − 已付 = 待付，每张发货单列核销记录（日期、金额），不显示预收（预收记在客户名下），不列售后明细。
- 供应商对账（财务、供应商端一致）：应付、已付、待付，每张单列付款核销记录（日期、金额），另外单独显示预付和退款记录。单据按收货日期筛选：采购单用实际收货时间的上海日期，阶段 5 手工入库用单据入库日期，不用采购下单日期；先按全账重算核销，再筛单据和汇总。
- 客户、供应商对账和供应商端的退款记录包含已作废记录，明确标状态；金额计算只扣有效退款，作废记录不重复扣钱（2026-10-02 交叉审查确认）。业务单据日期筛选只筛单据及其汇总，不截掉退款历史或重分配核销，预收 / 预付始终显示当前全账余额。财务收付款详情保留完整退款历史，只有登记人和管理员能作废。
- 库存：每次入库（采购收货、手工入库）生成一个批次。出库按入库时间先进先出；采购退货、作废已收货采购单、作废手工入库单先扣这张单入库的批次，不够再先进先出；作废手工出库、报损按原来扣的批次加回。库存不够不能出库、报损、退货、作废入库类单据。
- 在途 = 待收货采购单的采购数量，不分到货日期；待填报的邀请不算。采购需求余量 = 实际库存 + 在途 − 出货日期区间内待发货订单按配方拆出的花材合计，负数是缺口。待确认订单没有出货日期，不算。

## 5. 修改、取消、作废条件

| 操作 | 谁 | 前提 | 原因 | 记录 |
|---|---|---|---|---|
| 门店改单 | 门店 | 订单待确认；客户启用；原单里已停用的产品要先删掉；不选出货日期 | 不用 | 日志 + 变更记录 |
| 门店取消订单 | 门店 | 订单待确认 | 不用 | 日志 |
| 确认订单 | 销售 | 待确认、门店和客户都启用、单里没有已停用的产品；选出货日期（可以早于今天） | 不用 | 日志（第一次定出货日期不写变更记录） |
| 修改并确认 | 销售 | 待确认、门店和客户都启用；已停用的产品要先删掉；填出货日期 | 必填 | 日志 + 变更记录，保存后是待发货 |
| 修改订单 | 销售 | 待发货；没有待处理的取消申请；已停用的产品要先删掉 | 必填 | 日志 + 变更记录（内容没变不写） |
| 取消订单 | 销售 | 待确认或待发货；没有待处理的取消申请（有的话用同意、拒绝） | 待确认的不用；待发货的必填 | 日志 |
| 申请取消 | 门店 | 订单待发货；没有待处理的申请；这张单没有被拒绝过的申请 | 选填 | 日志 |
| 撤回取消申请 | 门店 | 申请待处理 | 不用 | 日志；撤回后可以再申请 |
| 同意取消申请 | 销售 | 申请待处理、订单待发货 | 不用，取消原因自动写「门店申请取消」，门店写了原因接在后面 | 日志；订单已取消 |
| 拒绝取消申请 | 销售 | 申请待处理 | 必填，门店能看到 | 日志；以后不能再申请 |
| 确认发货 | 发货 | 待发货；出货日期不晚于今天；实发和订单数量不一致（少发、多发）要写发货备注；实发不设上限 | 有差异写备注 | 日志；有待处理的取消申请时申请自动失效 |
| 作废已发货订单 | 销售（归属见第 2 节） | 已发货；没有有效核销（先由财务撤回）；没有待处理、已处理的售后（先关闭、作废） | 必填 | 日志；不再算应收，门店看到已作废和原因 |
| 申请售后 | 门店 | 订单已发货；在售后申请期限内（实际发货那天的上海日期再加 `AFTER_APPLY_DAYS` 天，最后一天当天结束前都能申请，例如 09-28 发货、7 天，10-05 还能申请）；数量不超过可申请数量；每行写问题说明；原因是「花材损坏」「品质问题」的行至少 1 张图片 | — | 日志 |
| 处理售后 | 销售 | 待处理；门店提交的只改数量和单价，不能删行、加产品；不给的行填 0，全 0 要改成关闭 | 说明选填 | 日志 |
| 关闭售后 | 销售 | 待处理 | 必填 | 日志 |
| 作废售后 | 销售（归处理它的销售） | 已处理，不限时间 | 必填 | 日志；应收加回、核销重算、可申请数量恢复 |
| 登记收款、付款 | 财务 | 日期不晚于今天；每条核销不超过单据未收、待付和这笔剩余金额；确认时单据金额和打开时一致，变了整笔拦住、刷新后再确认 | — | 日志 |
| 核销预收、预付 | 财务 | 这笔钱有预收、预付；同上 | — | 日志 |
| 撤回核销 | 财务（登记这条核销的人） | 核销有效 | 必填 | 日志；释放金额后全账重算，预收、预付按重算结果显示 |
| 作废收款、付款 | 财务（登记的人） | 有效；这笔没有有效退款（先作废退款） | 必填 | 日志；核销全部撤回、重算 |
| 登记预收退款、预付退款 | 财务 | 选一笔有效收款、付款；金额不超过它的预收、预付；日期不晚于今天 | 选填 | 日志 |
| 作废退款 | 财务（登记的人） | 有效 | 必填 | 日志；资金可用上限恢复后全账重算，余额按重算结果显示 |
| 修改、取消邀请 | 采购 | 待填报 | 不用 | 日志 |
| 提交填报 | 供应商 | 待填报、发给自己这家；每行供货量大于 0；提交行不能有已停用花材（供应商自己删行） | — | 日志 |
| 修改采购单 | 采购 | 待收货；填报生成的单不能换供应商 | 必填 | 日志 + 改单记录 |
| 供应商改单 | 供应商 | 自己填报生成、待收货；改数量、单价、删行、另报启用花材；至少一行、每行大于 0 | 选填 | 日志 + 改单记录 |
| 取消采购单 | 采购 | 待收货 | 必填 | 日志 |
| 供应商取消采购单 | 供应商 | 自己填报生成、待收货 | 必填 | 日志；邀请卡片显示已取消 |
| 确认收货 / 拒收 | 仓库 | 待收货；实收全 0 为拒收；停用花材已下单的照常收 | 改单价时必填 | 日志 |
| 退货 | 仓库 | 已收货、没全部退货；不超过净实收和库存 | 不用 | 日志 + 退货记录；已付的多出转预付 |
| 改单价（采购单、手工入库单） | 仓库 | 采购单已收货且未全部退货、手工入库单已入库 | 必填 | 日志 + 改价记录；已付的多出转预付 |
| 作废已收货采购单 | 仓库（收货的人） | 已收货；没有有效核销（先由财务撤回）；库存够按净实收扣回 | 必填 | 日志；不再算应付，供应商看到已作废和原因 |
| 作废手工入库单 | 仓库（录的人） | 已入库；没有有效核销；库存够扣回 | 必填 | 日志 |
| 作废手工出库、报损 | 仓库（录的人） | 已出库、已报损 | 必填 | 日志；库存按原批次加回 |

- 已发货订单的实发、已处理的售后不能修改，填错了走反向单据：实发记多了（实际少发），销售新建售后冲减，原因选「数量不符」；实发记少了（实际多发），销售补建一张订单；整张记错了，满足前提时销售作废已发货订单再重建；售后记多了，先作废再按正确数量新建。
- 作废的记录保留、标「已作废」，不能恢复。
- 主数据（客户、门店、产品、花材、供应商、收付款方式、出库分类）只停用不删除，历史单据照常显示。停用的客户不能再下新单（旗下门店也不能下单），但门店账号照常登录，能看订单、售后、对账（2026-09-30 确认）；门店首页顶部提示「这个客户已停用，不能再下新单，请联系花众」，「订货」卡变灰不能点（2026-09-30 确认）；购物车和底栏角标保留，「去结算」禁用并写同一句提示，重新启用后可以接着下单。这个客户已有的待确认订单和门店停用时一样处理：门店不能改、能取消；销售不能确认、修改并确认，能取消；待发货的照常发货（阶段 3 确认）。停用的产品不能加进订货目录和新订单，已有的待发货订单不改就照常发货。
- 产品分类不属于上面的主数据：没有产品（含停用的产品）时可以删除，有产品时要先把产品移到别的分类（阶段 3 确认，照原型）。
- 产品管理和订货目录分开（2026-10-03 确认）：产品本身（名称、单位、图片、内部分类、配方）所有客户共用；订货目录（订货价、可订、客户产品编码、订货分类）每个客户一份。
- 产品分类是内部分类（初始「单品」「花束」，可新增、改名、排序、删除），只在产品管理里用，门店订货页不用它（2026-10-03 确认）。
- 订货分类（2026-10-03 确认）：每个客户一套，在订货目录里维护；产品加进目录必须选一个订货分类。规则同产品分类：同一客户内不重名、新增排最后、上移整组提交、分类下有目录项（含停用的）不能删（「分类中仍有目录产品，请先换分类」）。新客户目录为空，先建分类再加产品，或者「从其他客户复制」（2026-10-02 梳理确认）：只在这个客户目录为空时可用；只复制来源客户启用且可订的目录项，带订货分类、订货价、可订，不带客户产品编码；复制前提示「将复制 N 个产品，跳过 M 个已停用或不可订的」；复制后两边各自独立。门店订货页左侧按这个客户的订货分类排，只列有可订产品的分类。
- 客户产品编码（2026-10-03 确认）：选填，同一客户内不重复（「这个客户下已有相同的产品编码」），不同客户可以重复。显示在订货目录、门店订货页、订单明细（对账点进订单也能看到）。下单时和名称、单位一起快照进订单行，之后改编码旧单不变；销售改单原有行保留原编码，新加的行取当前编码。
- 订货目录里改配方（2026-10-03 确认）：目录弹层里改的是产品本身的配方，所有客户跟着变；和这个客户的目录项一起保存、同一事务，保存前确认「配方所有客户共用，改后所有客户的这个产品都会变」。
- 每次确认、保存、取消、作废前后端都按当前状态和版本号复查；变了就拒绝并返回最新内容。
- 复制目录的「空」按没有任何目录项判断，停用项也算已有项；已有空分类不影响复制。同名分类复用，只带来源中有可复制产品的分类，按来源顺序添加新分类，已有分类原顺序不动；来源没有可复制产品时提示「没有可复制的产品」，不写入。预览后来源或目标变了先重新预览，不按旧预览复制（2026-10-02 交叉审查确认）。

## 6. 必须互斥的操作

后端在事务里加锁或按版本号条件更新，保证下面每一对不会同时成功：

- 确认发货 ↔ 取消订单、修改订单、同意取消申请
- 门店申请取消、撤回 ↔ 销售修改订单、取消订单、同意或拒绝申请
- 确认订单、修改并确认 ↔ 门店改单、门店取消
- 订货目录调价（同步待确认订单的单价）↔ 确认订单、修改并确认
- 作废已发货订单 ↔ 登记收款或核销预收（核销到这张单）、申请售后、新建售后
- 收货 ↔ 采购改单、采购取消、供应商改单、供应商取消
- 采购改单、采购取消 ↔ 供应商改单、供应商取消
- 登记付款或核销预付（核销到这张单）↔ 退货、改单价、作废已收货采购单、作废手工入库单
- 撤回核销、作废收款或付款、作废退款 ↔ 登记退款、核销预收或预付（同一笔钱）
- 处理售后 ↔ 关闭售后
- 库存变动（出库、报损、退货、作废入库类单据、作废出库和报损、盘点）之间：锁住批次后按先进先出扣、按原批次加回，不能超扣

订货目录调价和门店改单按客户目录排队执行，先后顺序不影响结果：待确认订单的单价最终都等于新的目录价；门店拿调价前的版本提交会提示内容已变，刷新后重新提交（阶段 3 确认）。

上述互斥指不能基于同一份过期状态同时写成功；按正确先后重新核对后仍各自合法的操作可以依次成功，不能一概禁止付款后退货或改价。所有影响同一客户、供应商账本的操作（含售后新建、处理、作废）统一串行复核；全部核销、退款、余额重算和通知在同一事务内完成。取消申请每次流转都提升订单版本，旧请求不能误处理撤回后重新发起的申请。

## 8. 各模块规则

### 8.1 销售、发货、门店端

- 订单状态五种：待确认、待发货、已发货、已取消、已作废。发货后订单结束，门店不确认收货；已发货订单整张记错了由销售作废（第 5 节）。
- 下单单价默认取订货目录价，销售可以改，改过的标「改价」。
- 待确认订单的单价始终等于目录价（阶段 3 确认）：销售改订货目录价时，这个客户待确认订单里这种产品的单价同时更新，只记在「修改订货目录」的日志里（写明改了哪些订单），不写变更记录、不标「改单」。销售改单时原有行保持原单价，新加的行默认目录价。
- 出货日期由销售定（阶段 3 确认）：门店下单、改单不选出货日期，待确认时没有出货日期，显示「待销售安排」；销售「确认订单」时选出货日期（默认明天），「修改并确认」、新建、修改订单在表单里填，都可以选今天以前（补录）。门店能看到出货日期，只读。第一次定出货日期不写变更记录、不算改单，以后再改才写。
- 下单日期是录入那天，门店和销售都不能改；补录只补出货日期（阶段 3 确认）。
- 销售处理门店的待确认订单：确认、取消，或「修改并确认」。
- 订单变更记录：门店改待确认的单、销售改单都写（改了什么、原因、谁、什么时候；门店改单没有原因）。销售、门店、发货的订单详情都显示，卡片标「改单」。内容没变的修改不写。
- 原单里有已停用的产品：门店改单的结算页、销售的订单表单都标「已停用」，拦住保存，提示先删掉，不悄悄去掉；这样的待确认订单不能直接「确认订单」，要「修改并确认」删掉或取消。待发货订单不改就照常发货（阶段 3 确认）。门店改单把产品全删光（例如只剩已停用产品、都删掉了）提交时提示「请先选择产品」，整单不要了用「取消订单」（阶段 3 确认）。
- 门店取消待发货订单（2026-10-02 梳理确认）：订单确认后门店不能直接取消，可以「申请取消」，原因选填。处理前门店可以撤回，撤回后还能再申请；被拒绝后这张单不能再申请，要找销售。同一时间只有一条待处理。销售在订单详情「同意取消」（订单变已取消，取消原因自动写「门店申请取消」加门店原因）或「拒绝」（必写原因，门店能看到）；有待处理的申请时销售不能改单、不能直接取消，只能同意或拒绝。申请不进销售首页待办，订单卡片标「申请取消」，订单列表的状态标签加「申请取消」并显示数量。发货照常能发，发了申请自动失效，门店看到「已发货，取消申请未处理」。
- 发货默认按订单数量，可以少发、多发（实发不设上限）；实发和订单数量不一致要写发货备注，明细和卡片标「少发」「多发」，应收按实发算。整单不发要由销售取消订单。出货日期到了（不晚于今天）才能确认发货；要提前发，由销售把出货日期改早（阶段 3 确认）。一张订单一次发完，不分批。
- 发货端（发货单列表、发货表单、发货详情）不显示单价和金额（2026-10-02 梳理确认）。
- 售后：门店在售后入口申请，原因是「花材损坏」「品质问题」的行至少带 1 张图片，「数量不符」「其他」图片选填（2026-10-02 梳理确认）；销售在客户售后确认数量和单价；售后金额 = 数量 × 单价，没有单独的金额框，处理说明选填。门店提交后不能撤回、修改。一次售后只针对一张订单。
- 门店申请售后的期限：实际发货那天起 `AFTER_APPLY_DAYS` 天（第 5 节）；过了期限门店不能再申请，提示联系花众销售，由销售新建（不限时间）。销售新建售后每行选原因，说明选填，不带图片（阶段 3 确认）。
- 销售处理门店提交的售后：门店填的原因、说明、图片只读，只改数量和单价。门店原来申请的数量另外保存，不被覆盖；售后详情（销售、门店两端）同时显示「申请数量」和「处理数量」。
- 作废售后：只有销售能做（售后详情，归处理它的销售）；财务在发货单弹层里只能查看售后详情（2026-10-02 梳理确认）。门店看到「已作废」和原因，不显示金额。
- 售后挂在原发货单下：发货单应收 = 发货金额 − 售后金额。
- 门店端：底部标签首页、购物车、我的；订货、订单、售后、对账从门店首页进。订货是外卖式：左侧订货分类、右侧产品（名称下写客户产品编码）、底部购物车条；顶部显示客户 · 门店、下单日期（改单时是原订单日期）、可订款数和产品搜索（跨分类）。
- 门店改单用单独的一份购物车，改单时隐藏底部标签；放弃或提交后，原来的购物车还在。
- 购物车按账号存在这台手机上，关掉小程序还在，退出登录时清空。里面的产品停用了，打开订货页、购物车时自动去掉，提示一次「白绿清新花束已停用，已从购物车移除」（阶段 3 确认）。
- 门店对账只看本店发货单，可以按出货日期筛选（默认全部）；每张发货单显示核销记录（日期、金额），不显示预收（2026-10-02 梳理确认）。
- 客户、门店、产品资料（阶段 3 确认）：客户名称必填、不重复，在客户门店页新建、改名、启用 / 停用。门店名称必填、同一客户下不重复；联系人、电话、地址选填，填了登录手机号（开通门店账号）时联系人必填，门店账号的名字就是联系人。改门店的登录手机号时，原来绑定的微信同时解绑，日志原因写「同时解绑微信」，和员工一致（阶段 3 确认）。产品名称必填、不重复；分类、单位必填；配方至少一种花材；启用开关在产品表单里。产品分类在产品管理里新增、改名、排序、删除（第 5 节）。
- 邀请下单：销售在门店资料里把小程序卡片分享给门店，门店打开后用手机号快速验证，绑定到这家门店的账号（手机号要和门店账号的登录手机号一致）。链接有效期 `STORE_INVITE_TTL_DAYS`，绑定成功后失效；过期或已失效时显示「邀请已失效」和原因。同一家门店重新生成邀请时，旧的未使用邀请自动作废，同一时间只有一条有效。门店账号已经绑了一台微信，要先由销售或管理员在门店资料里解绑，才能用新邀请绑另一台。已经绑了别的账号的微信打开邀请：提示先在「我的」退出登录再接受邀请，不自动解绑，邀请不失效；已经是这家门店的账号，直接进订货（阶段 3 确认）。「门店接受邀请」的日志记在销售模块（阶段 3 确认）。
- 发货首页和发货待办只算出货日期不晚于今天的待发货订单；「查看全部」进发货单（待发货 / 已发货），待发货列表里也能看到以后的单（不能确认发货），没有到期的待发货时换成「发货记录」。

### 8.2 采购、供应商端

- 采购单状态：待收货、已收货、已拒收、已取消、已作废；没有草稿和预计到货日期。
- 待收货的单采购可以修改（包括换供应商）或取消，必须写原因。供应商填报生成的单不能换供应商。换了供应商后，原供应商端看不到这张单。收货后采购不能再改；已收货的单整张记错了由仓库作废（第 5 节）。
- 供应商改单、取消（2026-10-02 梳理确认）：供应商自己填报生成、还没收货的采购单，供应商可以修改（数量、单价、删行、另报启用的花材，至少一行、每行大于 0，原因选填），也可以取消（必写原因）。采购直接新建的单供应商只能看。改单写改单记录，采购、仓库、供应商三端都显示；取消后采购、仓库看到已取消和原因，邀请卡片显示已取消。
- 改单记录（改了什么、原因、谁、什么时候）采购、仓库收货页、供应商端都显示，卡片标「改单」。取消原因三端都能看到。
- 单价手填，可以是 0（赠送）。应付 =（实收 − 退货）× 单价。
- 采购需求：出货日期区间默认今天起 `DEMAND_DEFAULT_DAYS` 天，只算待发货订单，按配方拆成花材合计。停用花材照常计算、标「已停用」、不能勾选；配方通过 `materialId` 外键关联花材，保存时拒绝不存在的花材，不保留旧原型按名称匹配、找不到则跳过的逻辑。已邀请、还没提交的花材标「已邀请」，不算在途、缺口不变；来源里列出按出货日期和订单的明细，以及哪家、哪张邀请、邀请了多少。待确认订单不算（没有出货日期，确认后才进需求）。需求卡片的日期写这种花材实际涉及订单的出货日期区间（最早到最晚，例如「09-29 ~ 10-03 出货」，只有一天写「09-29 出货」），不写筛选区间（2026-10-02 梳理确认）。不设安全库存。
- 采购需求自动同步（2026-10-02 采购优化确认）：订单确认、修改并确认、销售直接建单后自动纳入；待发货改单（数量、产品、出货日期）、取消或同意取消、确认发货后重新计算；配方、库存、在途变化也重新计算。事务提交后采购需求页自动刷新，回滚不发变化通知。这里是更新计算结果，不自动建采购单、发邀请或出库，不改变模块独立边界。
- 需求列表默认缺货优先，同组按最早实际出货日期、花材编码、id 排列；可切换「只看缺货 / 全部」，默认全部，保留够用项，不改变计算口径。逾期待发货订单另行提示「有 N 张逾期待发货订单，查看需求」，点击查看对应过去日期；不自动混进当前区间（2026-10-02 采购优化确认）。
- 在途可展开看采购单（供应商、采购数量、状态），提示「在途不代表已到库」；仍不分到货日期，不新增到货日期、安全库存或自动分配。未提交邀请单独列供应商、邀请号、需求量，仍不算在途（2026-10-02 采购优化确认）。
- 再次邀请或下单前，有包含这些花材的待填报邀请就提示已有邀请，可点开原邀请，只提醒、不禁止。需求带入表单后，确认前复核最新需求、库存、在途；缺口变化先提示核对，保留已填数量、供应商、价格，采购员确认后可以按原数量继续。允许主动买得比缺口多，不自动改数量，不以超缺口为错误；复核与确认之间再次变化则重新提示（2026-10-02 采购优化确认）。
- 「生成采购单」：数量带入缺口（够用带 0，要改成大于 0），供应商、单价手填。「邀请供应商」：一次只邀请一家已开通供应商端账号的供应商，需求量默认缺口、可改。两种操作完成后回到需求页，勾选清空。
- 供应商填报邀请：待填报的可以修改（需求量、增减花材）、取消，不用原因。可以把邀请分享给供应商（小程序卡片），打开前要先登录，只有这家供应商的账号能打开。分享链接不另设有效期，跟着邀请走：邀请已提交或已取消，链接就失效，显示「邀请已失效」和原因。
- 供应商资料：名称必填不重复；联系人、电话、地址、启用；开通供应商端账号要填 11 位登录手机号（不能和别家重复）。停用供应商或关闭账号后不能登录，这家待填报的邀请自动取消并记日志；已下的单照常收货和付款。
- 停用供应商或关闭供应商端账号时保留微信绑定（`openid`、`bound_at`），关闭实时连接并显示账号停用状态；供应商和账号都重新启用后，原微信可直接恢复使用，无须重新验证手机号。改登录手机号仍按下一条解绑（阶段 4 确认）。
- 供应商账号修改登录手机号时同时解绑微信，清空 `openid`、`bound_at`，关闭该账号的实时连接；日志原因「同时解绑微信」。下次须用新手机号重新验证绑定（阶段 4 确认）。
- 供应商端：底部标签首页、填报、我的；采购单、对账从供应商首页进。填报时每行实际供货量大于 0（不供的行删掉，可多可少）、单价（赠送填 0），可以另报启用的花材；邀请中已停用的花材标「已停用」，数量和单价只读，只能删行；供应商自己删掉就能提交，不用等采购修改邀请。提交行（邀请行和另报行）含停用花材 → `BUSINESS_RULE`「花材已停用，请删掉这一行再提交」；未提交的邀请行算「未供」，需求快照保留，不影响生成采购单（阶段 4 确认）；提交就生成待收货采购单，采购员是发邀请的人。采购单里能看到这家全部采购单（含已取消、已拒收、已作废）、实收、退货、改价、付款记录（日期、金额）。供应商对账显示应付、已付、待付、预付和退款记录（第 4 节）；手工入库单阶段 5 接入。

### 8.3 仓库

- 入口：阶段 4 先做待收、库存、花材；手工入库、手工出库、报损、盘点在阶段 5 接入。首页下面列待收货的单（阶段 4 确认）。
- 待收：实收可多可少，不用备注；单价可以改，改了必须写原因，采购单标「改价」。实收全填 0 确认后是「已拒收」，应付 0。采购途中改单或取消，收货页实时刷新并提示。
- 收货后：可以多次退货（不用原因，不要供应商确认），每种花材累计不超过实收，库存不够不能退；可以改单价（必须写原因）。付款后也能退货、改价，已付的多出部分转为这笔付款的预付（2026-10-02 梳理确认，取代「付过款不能再退货和改价」）。全部退货后应付 0，采购单标「已全部退货」，不再允许退货或改单价（阶段 4 确认）。
- 作废已收货采购单：收货的人做；没有有效核销（已付的先由财务撤回核销），库存够按净实收扣回（先扣本单批次），必写原因；作废后不算应付，供应商看到已作废和原因（2026-10-02 梳理确认）。一张采购单一次收完，不分批。
- 停用的花材：已下单的采购单照常收货；不能入库，也不能加进采购单、邀请、填报和配方；还能出库、报损、盘点。
- 花材：名称（可以重复）、编码（自动生成：前缀 `MATERIAL_CODE_PREFIX` + 四位序号，可改，不能重复）、单位、分类（从分类列表选，分类可新增、改名）、启用。改单位不换算已有数量，只记日志。
- 手工入库：阶段 5 实现。入库单列表按状态、供应商、入库日期筛选，「新建入库」在底栏，保存后回到列表。供应商必选（启用的供应商），每行花材、数量、单价（赠送填 0），自动算金额和合计；金额大于 0 生成应付，全部赠送不进财务；原因选填。可以改单价（必须写原因，标「改价」；已付的多出转预付）。没有有效核销的可以作废（录的人做，必须写原因，库存按入库数量扣回，先扣本单批次，库存不够不能作废）。花材详情的「手工入库」直接新建并带上这种花材。
- 手工出库：阶段 5 实现。出库单列表按出库分类、出库日期筛选，「新建出库」在底栏，保存后回到列表，和手工入库一致。花材详情的「手工出库」直接新建并带上这种花材。
- 手工出库必须选出库分类，原因选填。出库分类阶段 5 实现，可改名、新增、启用 / 停用，至少保留一个启用的；初始分类：生产领用、门店零售、样品、其他（生产模块不做，「生产领用」照样保留，用于领花材做花束）。
- 报损必须写原因，图片选填（2026-10-02 梳理确认）。
- 手工出库、报损录错了，录的人可以作废（必写原因），库存按原来扣的批次加回；盘点不能作废，填错了再盘一次（2026-10-02 梳理确认）。
- 盘点先选花材分类（可多选），只列这些分类的花材（停用的也列）；账面默认等于当前库存，有差异必须写原因，确认后直接调整库存。确认时后端复查账面数：打开盘点后库存又变了（例如有人出库），拦住并提示「库存已变化，已刷新账面数，请核对后再确认」，已填的实盘数保留。
- 批次按入库时间先进先出。阶段 4 在花材详情显示入库日期和剩余数量，不编批次单号；阶段 5 的出入库记录显示「MM-DD 入库」（阶段 4 确认）。
- 明细行统一：「添加」按钮在明细下面居中；删除用行右侧垃圾桶，点一下就删。

### 8.4 财务

- 入口：客户对账、供应商对账、收付款记录、收付款方式。首页下面列待付款单据和有预收的客户；阶段 4 的待付款和供应商对账只算采购单，手工入库单阶段 5 接入（阶段 4 确认）。
- 收款、付款、核销、撤回、退款的规则见第 4 节，按常规财务做法，两侧对称（2026-10-02 梳理确认）。
- 登记收款：选客户，填金额、日期（默认今天，可补录，不能晚于今天）、收款方式；下面列这个客户有未收的发货单，默认按出货日期从早到晚自动填入核销，财务可以改；没分完的记为这笔收款的预收。以后「核销预收」（客户没有未收时隐藏）。
- 登记付款：从供应商对账进，填金额、日期、付款方式；下面列这家待付的单据，默认按收货日期从早到晚自动填入核销，可以改；没分完的记为这笔付款的预付，以后「核销预付」。阶段 4 只核销采购单，接口按 `docType` 留位置，手工入库单阶段 5 接入。付款页显示退货、改价记录，改过价时提示核对。
- 确认登记时复核单据金额：任何一张的未收、待付和打开时不一样，或被别人核销了，整笔拦住，刷新后核对再确认。
- 收款详情、付款详情列出全部核销历史（登记金额、生效金额、有效 / 已撤回、撤回原因），生效为 0 的有效核销也能「撤回核销」（必写原因）；整笔可以作废（必写原因，有有效退款时先作废退款）。
- 预收退款、预付退款：在收款、付款详情里登记，金额不超过这笔的预收、预付，日期不晚于今天，可以作废（必写原因）。
- 客户对账可以按出货日期筛选（默认全部）：发货单列表和发货金额、售后、已收、未收按区间里的发货单算，预收照常显示当前余额（阶段 3 确认）；另外列退款记录。供应商对账同样写法，显示预付和退款记录。
- 发货单弹层里的售后可以点开看详情（只读，作废售后在销售模块）。
- 登记错了只做反向操作（作废、撤回），不改原记录。作废、撤回只能做自己登记的，别人登记的找管理员。
- 收付款记录顶部「收款 / 付款」是两个标签页，不是筛选维度；每页按状态、日期筛选；状态标签不带数量（有效、已作废不是等待类）（阶段 4 确认）。退款记录在对应收款、付款详情和对账里看。
- 收款方式、付款方式分开两份，财务新增、停用；每份至少保留一种启用的。

### 8.5 公共

- 花众首页：花众字标 + 身份行，下面是两列入口卡（只放本人有权限的模块），不显示待办。
- 门店首页、供应商首页：花众字标 + 身份行，下面一张主卡（门店「订货」、供应商「填报」）加一排小卡（门店订单、售后、对账；供应商采购单、对账）。待办数只在外部端显示：供应商「填报」主卡和底栏「填报」显示待填报数；员工首页、门店首页不显示待办数。
- 模块首页：品牌背景淡化铺底 → 图标入口 → 待办列表；待办为空不显示「查看全部」。待办按最早的在前：销售待确认订单按下单日期、待处理售后按售后日期，发货待办按出货日期，同一天按录入先后（阶段 3 确认）。
- 员工底栏「首页 / 我的」。没有仓库模块权限的员工在「我的」里只读查询库存；有仓库权限的（含管理员）不显示这个入口，用仓库「库存」。库存查询列出全部花材（含库存 0 的），停用的标「已停用」，和仓库「库存」一致（2026-10-03 确认）。
- 身份行的岗位：管理员写「管理员」，员工写模块名，多个用「、」连（例如「销售、仓库」），员工与岗位列表同一写法（2026-10-03 确认）。
- 管理员看全部日志，员工只看自己做的操作的日志（2026-10-02 梳理确认，取代「看自己模块的日志」）。日志记操作人、时间、动作、对象、原因、修改前后，前端不能改。账号类操作（绑定微信、解绑微信、新增员工、修改员工）不属于任何模块，记为「公共」，只有管理员能看（2026-10-03 确认）。
- 员工调岗后仍能看自己在原模块做过的非公共历史操作；列表、详情、模块筛选都按本人历史范围，不用当前岗位把历史操作裁掉。不能借选原模块看到别人的日志（2026-10-02 交叉审查确认）。
- 员工与岗位（2026-10-03 确认）：打开「管理员」开关后不再选模块（管理员默认全部模块），「请至少选一个模块」只对普通员工；关掉开关恢复原来选的模块。管理员改了员工的登录手机号或停用员工，原来绑定的微信自动解绑，日志写明；员工已绑定微信时，管理员可以在员工弹层里「解绑微信」，对方下次打开要重新手机号验证。
- 登录页的隐私保护指引没勾选时，「手机号快速验证登录」照常可点，点了提示「请先阅读并同意隐私保护指引」、勾选框轻微抖动，不弹手机号授权（2026-10-03 确认）。
- 列表卡片最多三行；筛选最多三项：状态是列表上方的标签行，等待类状态显示数量；日期、对象放进筛选按钮的弹层，改了立即生效，设了条件在列表上方显示可去掉的胶囊（外观见 02 章第 4 节 `hz-filter-bar`）；新建、邀请类操作固定在列表页底栏。
