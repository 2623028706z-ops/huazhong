## 一、通用写法（02 第 6~8 节、06 第 1 节，代码的公共组件和格式工具）

- 视觉：墙色铺满；入口用窗格（图标在上、名称 + 箭头在下的大窗格；「资料」类用小格），内容用卡片（一单一张卡，抬头写往来方 + 状态，细描边、无阴影，圆角 10px，按钮 8px）；标题和金额用思源宋体；品牌红只用于主按钮、选中、待办数字。
- 字段一律「字段名在左、值在右」，可以两列并排，长内容（备注、对账期间、带时间的字段）占整行。每个日期、金额都写字段名，列表行、弹层行的小字也写（多个字段之间两个全角空格，不用「 · 」拼）；单号、手机号也写字段名。
- 日期一律年月日 `2026-09-29`；带时间的一律 `2026-09-28 07:30`（不写「09-28 07:30」）；按日期分组的组头带周几「2026-09-29 周二」。
- 出货日期没定写「待定」。
- 明细统一是表格：第一列表头写卡片标题（产品明细 / 花材明细），后面数量、单位、单价、小计；编码在名称下一行写「编码 …」；内部页面不放产品图（只有门店订货页有）。底部一行两列「合计数量 n 单位 | 合计金额 ¥…」，一行明细也显示。发货明细表头「数量 / 实发 / 单位」，没有单价金额；收货明细「实收」，编码那行写「采购数量 n 枝」。
- 可编辑明细统一「表格 + 点行改」：点一行弹小窗口（数量步进器 + 单位、单价框后缀「元」、小计，底部「删除」「确定」）；「添加产品 / 花材」选好后弹同一个窗口。
- 单价展示「¥68.00/束」，输入框后缀「元」。
- 表单里备注、修改原因：字段名在左、内容在右，同一张卡里各占一行。
- 底栏最多 2 个按钮，不要「更多」；第三个操作放页面最下面一行灰字（例：对账单详情「作废对账单」、W3 已收货「作废采购单」、C9「取消邀请」）。只剩 1~2 个操作时作废 / 取消也进底栏。
- 列表：搜索框占满一行；状态标签行 + 最右「筛选」文字 + 小图标（不加框），条件和默认不同时「筛选」变红带个数；等待类标签带数字（「待确认 1」「待发货 2」）。
- 详情页顶部进度条：一格一个关键节点，走过的写过去式，当前格写现在状态（红圈），取消 / 拒收 / 关闭用灰色终点替换最后一格，作废在后面多一格灰色；日期写全，待发货那格写「出货日期 / 2026-09-29」。订单 3 格（已下单 → 已确认 / 待确认 → 待发货 / 已发货），售后（员工、门店都是）已提交 → 待处理 → 已处理，采购单 2 格，填报邀请 2 格；收付款、对账单、手工出入库、报损、盘点不加。
- 模块首页：待办（并排小卡、大数字，点进筛好的列表，0 也显示）→ 常用（大窗格）→ 资料（小格，可选），不写今日数字、不写身份行。
- 叫法统一：
  - 金额：待确认 / 待发货的订单叫「订单金额」，已发货叫「发货金额」；采购单收货前后都叫「采购金额」；「应收 / 应付」只在财务对账里用；单据详情信息卡不放金额（看明细合计）。
  - 售后没处理时售后金额写「待处理」。
  - 门店提交订单的页叫「提交订单」（S5，原「确认订单」）；销售「确认订单」不变。新建采购单按钮「提交采购单」。
  - 联系方式叫「联系电话」，登录账号叫「登录手机号」。
  - 出入库来源叫「采购入库」。
  - 门店申请取消：动作「申请取消」，对象「取消申请」，撤回「撤回申请」。
  - 填报明细标题「花材明细」。
- 操作日志：门店、供应商账号不写岗位，写「门店 滨江店」「供应商 春禾花材」。
- 员工底栏：只有仓库岗位（只管仓库）的员工有底栏「首页 / 库存 / 我的」；其他只管一个模块的员工没有模块底栏，从模块首页进、左上角返回。

- S6 订单详情：
  - 待确认：信息卡单号、下单日期、出货日期「待定」、备注；不放金额；底栏「取消订单」「修改订单」。
  - 待发货（新画）：信息卡单号、下单日期、出货日期、备注；明细；**变更记录**卡（销售改过就一条一条列：动作 · 谁、修改时间、旧 → 新、原因；没改过写「没有修改」）；底栏「申请取消」（填原因，选填）。
  - 取消申请待处理（新画）：最上面黄条「取消申请待处理　提交时间 …　原因 …」，抬头多「申请取消」标签；底栏「撤回申请」。被拒绝：黄条「取消申请被拒绝：原因 …」，不能再申请、没有按钮；同意：已取消；没处理就发了：黄条「已发货，取消申请未处理」。

- S8 申请售后、小窗口：见 v33 说明（售后数量「最多 15」、问题原因四选一、说明、图片必填）。
- S10 售后详情：进度「已提交 → 待处理 → 已处理」；每个产品一张卡。
- S9 对账（改）：看**对账单**列表。上面一格「未结清」（本店在没结清的对账单里的金额）、「未对账」（已发货还没进对账单的本店金额）；标签「全部 / 未结清 / 已结清」+ 筛选（开单日期）；卡片：抬头「对账单」+ 状态，单号、开单日期、付款截止、对账期间、发货单 n 张、本店金额。作废的不显示。只看、不用确认。
- 门店对账单详情（新）：抬头「客户 · 门店」+ 状态，单号、开单日期、付款截止、对账期间（已结清多结清日期）；金额一格只算本店：发货金额、售后金额、本店金额；本店发货单（单号、发货日期、发货金额，点了进订单详情）、售后。**不显示收款记录和抵扣多收**，没有按钮。
- M4 我的（门店）、M2 邀请落地：见 v33。

## 八、财务（大改：03 第 4 / 5 / 6 / 8.4 节，04 第 7 节，05 第 10 节，06 第 10 节，07 第 5 节；后台核销那套重写）

**新单据：对账单**（单号前缀 DZ，客户、供应商各一种，对称）
- 按客户开（含所有门店，里面按门店分组）/ 按供应商开。字段：单号、客户 / 供应商、对账期间起止（默认本月 1 号到今天，可改）、开单日期（今天）、开单人、备注、付款截止、状态、结清日期、作废原因 / 人 / 时间。
- 内容：期间里**还没进过对账单**的发货单（按**实际发货日期**算，不按计划出货日期）和处理完的售后（按处理日期，写负数）；期间开始以前还没对过账的也列出，标「上期未对账」、默认勾上。供应商：已收货采购单（按收货日期，净实收金额）、退货（负数）、改价、手工入库单（按入库日期）。一张单据只能进一张对账单。
- 金额：发货金额 − 售后金额 − 抵扣多收（这家之前多收的自动抵）+ 期初欠款（只在第一张）= 应收。供应商：收货金额 − 退货金额 − 抵扣多付 + 期初欠款 = 应付。应收是 0：生成后直接已结清；小于 0：应收记 0、直接已结清，差额记成多收。
- 状态：未结清 / 已结清 / 已作废。没有部分结清。
- 付款截止 = 开单日期 + 这家的账期（没设账期就不写、不算逾期）；过了没结清标红「逾期 n 天」。
- 作废：只有没收过款的能作废，要填原因；作废后状态「已作废」留着能查（财务对账详情里灰色标），里面的单据回到「未对账」，抵扣的多收退回这家名下。门店、供应商端不显示已作废的。
- **进了对账单的单据不能改**：订单作废、售后作废、采购单退货 / 改价 / 作废、手工入库单作废 / 改价，都要先作废对账单；按钮变灰并提示「已进对账单 DZ-…，请先由财务作废对账单」。对账单开出以后才处理完的售后进下一张。
- 分享：对账单详情底栏「分享」→ 生成整张对账单**图片**（客户、单号、开单日期、付款截止、对账期间、按门店列每张发货单（单号、发货日期、发货金额）、发货金额 − 售后金额 − 抵扣多收 = 应收、已收、状态、生成时间），「保存图片」「发给微信好友」，对方不用登录。供应商对账单一样。

**收款 / 付款**
- 登记收款：选客户 → 列这家没结清的对账单，勾要收的（可以勾几张）；收款日期、收款金额（默认等于勾的应收合计）、优惠金额（抹零，选填）、**优惠原因（填了优惠就必填）**、收款方式、备注。规则：勾了对账单时，收款 + 优惠要不少于勾的应收合计，勾的全部结清，多出来的记成这家的多收；少了不能确认，提示「还差 ¥x，填优惠或少勾一张」。**一张不勾也能确认**（钱先到），整笔记成多收。不再有核销明细、转为预收。
- 作废收款（填原因）：勾的对账单回到未结清，多收扣回；**这笔的多收已经被后面的对账单抵掉的不能作废**，提示「这笔多收已抵进 DZ-…，请先作废那张对账单」。只能作废自己登记的，别人登记的找管理员。
