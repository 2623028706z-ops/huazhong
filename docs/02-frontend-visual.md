# 02 前端与视觉

整理日期：2026-09-30，2026-10-01 改视觉基准，2026-10-03 改首页和「我的」、加信息层级。视觉以本章和 `docs/design/` 样稿为准（组件总览 `gallery.html`；页面 `mock-art.html` 花众首页、模块首页、门店首页、供应商首页、「我的」，`mock-light.html` 列表，`mock-login.html` 登录页，`mock-pages.html` 列表、弹层、空状态、登录页的信息层级）；冻结原型（路径见 README）只作业务和交互参考，它的配色、背景、筛选样式已不用。本章是唯一出处，写代码以本章为准。品牌主色、字体、圆角不改，要改先确认。只做手机。

## 1. 原则

- 全站一套样子：同一种东西（按钮、卡片、状态标签、提示、空状态、加载、报错）只有一种写法，只在 `hz-*` 组件里定义一次。
- 页面不写外观，只写布局。页面的 WXSS 只允许间距、排列、显示隐藏。
- 设计值只从 `styles/tokens.wxss` 读，不写死颜色、字号、圆角。Stylelint 检查。
- 所有状态（加载、空、断网、出错、提交中、不可操作、过期）都有统一的组件和文案，页面不自己拼。

信息层级（2026-10-03 确认，对照 `mock-pages.html`）：

- 一张卡、一行只有一个主信息（15px 墨色）；关键数字（金额、库存）墨色加粗靠右；其余 12–13px 次要色。列表一条一张卡。
- 弹层先写「这是哪一条」，再写内容；改动写「旧 → 新」，只列改了的。
- 控件区（搜索、筛选）和下面的内容隔 `--hz-gap-controls`（16px），卡片之间 `--hz-card-gap`（10px）。按天分组的列表（操作日志）组头 13px 墨色加粗，格式见第 6 节。
- 整页状态（空、出错、断网）不装卡片。
- 弹层和表单左右留 `--hz-gap-sheet`，内容不贴边；表单按意思分组，组之间 `--hz-line` 细线。

颜色用法（2026-09-30 确认）：

- 陶土红只上 logo、图标、主按钮底和选中短线；它对浅色底的对比不够小字用，页面上不出现红色小字。金额、选中的筛选项、底栏选中的文字都用墨色。
- 主按钮：陶土红底 + 白字（4.5:1）。
- 原来用陶土色文字的地方已改掉：文字按钮是墨色字 + 陶土红下划线，待付 / 未收用琥珀浅底（见第 4 节）。
- 墙上的线（首页窗格、次按钮描边、筛选栏状态标签行下的细线、添加按钮虚线框、图片上传添加格）用 `--hz-rule`；`--hz-hair` 对墙色只有 1.2:1，只用在亮格、卡片上（2026-10-03 确认）。

状态颜色三类，用柔色胶囊：浅底配同色系深字，不描边（2026-09-30 确认），所有端一致：

- 绿色（完成）：已发货、已处理、已收、已付款、已收货、已提交、已入库、已出库、已报损、已盘点、有效、够用、已使用（门店邀请）。
- 灰色（结束、无效）：已取消、已关闭、已作废、已拒收、已停用、已过期（门店邀请）、无需付款。
- 琥珀色（等待）：待确认、待发货、待处理、未收、部分收、待收货、待填报、待付款、待使用（门店邀请）。

门店端对收款状态的叫法（未付、部分付、已付）颜色同未收、部分收、已收。

状态中文名和颜色都从 `shared` 的状态表里取，页面不写。

## 3. 字体、图标、图片

- 正文：系统字体。
- 标题、金额、空状态：思源宋体（Noto Serif SC）子集，只含数字、¥、常用标点和页面标题、模块名用到的字。`wx.loadFontFace` 在 `app.onLaunch` 里全局加载，加载完成前用系统宋体或系统字体，不阻塞页面。子集由 `scripts/` 从代码里的标题文案自动抽字生成。
- logo：花众正式字标（陶土红横版，原图为原型 `assets/signature.png`），放在主包；拿到矢量原文件后换成 SVG。
- 图标：Lucide 线性图标，1.5px 线宽，按需生成 iconfont，颜色跟随 `color`。TDesign 组件内置的图标能换就换成 Lucide，换不了的调成同样粗细和颜色。
- 品牌背景：一张图「窗」（浅杏墙 + 2×2 窗光 + 一枝梅影），内置在主包 `assets/backdrop.jpg`，不支持上传更换（2026-09-30 确认取消品牌封面上传）。图由 `scripts/` 程序绘制生成（`pnpm gen:backdrop`），不用图库；JPG 控制在 200KB 以内（主包体积见 00 章第 9 节）。三处用法（2026-10-01 确认），都由 `hz-cover` 铺，页面不直接引用图片：
  - 花众首页、门店首页、供应商首页、「我的」：整屏铺满，内容直接落在墙上，不铺卡片底，入口是 `--hz-rule` 细线窗格（2026-10-03 确认）。
  - 登录页：同首页整屏铺满；logo 在上部，下部渐亮到墙色，隐私勾选和登录按钮贴底（按钮底边离屏幕底 58px），落在渐亮的墙上。
  - 模块首页：同一张图淡化铺底（叠一层 60% 墙色），入口窗格和待办卡片落在上面。
  - 列表、详情、表单页只用墙色，不铺背景。
- 产品图：统一 1:1，上传后生成缩略图，列表只加载缩略图，详情加载大图。图片加载前显示 `--hz-tint` 底色占位，加载失败显示同样的占位加一个图片图标。

## 5. 统一状态：加载、网络、异常

所有页面按同一张表处理，页面不自己判断。请求层（`core/request`）把后端错误码转成下面的界面状态，页面只接结果。

### 5.1 加载

| 场景 | 做法 |
|---|---|
| 首次进入页面 | 骨架屏：按页面类型出灰块（列表页 3 张卡片、详情页 标题 + 3 行信息 + 明细、表单页 字段块）。`SKELETON_DELAY_MS` 内回来就不显示骨架，避免闪一下 |
| 下拉刷新 | 微信原生下拉刷新，背景用墙色（`--hz-bg`）；刷新时保留旧内容，不出骨架 |
| 列表翻页 | 滚到底自动加载下一页，底部一行「加载中」；全部加载完显示「已显示全部」（次要色 12px），只有一页时不显示 |
| 实时推送后刷新 | 静默重新拉取，不出骨架、不出加载提示；拉完出 `hz-realtime-bar` |
| 提交中 | 按钮文字换成「提交中」并禁用，其他按钮也禁用；超过 `SUBMIT_SPINNER_DELAY_MS` 按钮里加转圈；页面不遮罩 |
| 图片 | 见第 3 节，底色占位 |

### 5.2 网络

| 场景 | 做法 |
|---|---|
| 断网（`wx.onNetworkStatusChange`） | 顶栏下出一条提示「网络已断开，恢复后自动刷新」，页面内容保留可看；恢复后自动刷新当前页并收起提示 |
| 首次加载就失败 | 整页 `hz-state`：「网络不太好，没有加载出来」+ 次按钮「重试」 |
| 刷新、翻页失败 | 保留已有内容，顶部 `hz-error`「刷新失败，请重试」+ 文字按钮「重试」 |
| 提交失败（断网、超时） | 表单内容全部保留，`hz-error`「网络不太好，没有提交成功，请重试」；不自动重发 |
| 超时 | 按提交失败或加载失败处理，文案同上 |
| WebSocket 断开 | 不打扰用户，后台自动重连；重连后整页刷新一次 |

### 5.3 后端错误码

| 错误码 | 界面 |
|---|---|
| `UNAUTHENTICATED` | 回登录页，走手机号快速验证 |
| `ACCOUNT_DISABLED` | 整页 `hz-state`：「账号已停用，请联系花众」，只有「退出登录」 |
| `FORBIDDEN` | 整页 `hz-state`：「没有权限查看这个页面」+「返回」；弹层里出现时在弹层内写 |
| `NOT_FOUND` | 整页 `hz-state`：「没有找到这张单据」+「返回」 |
| `VALIDATION_FAILED` | 按 `fields` 标红对应字段并在字段下写原因，表单顶部 `hz-error` 写第一条原因，滚到第一个出错字段。规则没写专门提示的字段，原因统一写「格式不对，请检查后重试」 |
| `STALE` | 用 `latest` 刷新成最新内容，页面或弹层里写后端给的状态句（例如「订单已变成「待发货」，已刷新成最新内容，请核对后再保存」）；表单里已填的原因保留 |
| `BUSINESS_RULE` | 在页面或弹层里用 `hz-error` 写 `message`，不用 toast |
| `INTERNAL` | 首次加载：整页 `hz-state`「系统出错了，请稍后再试」，下面一行请求编号 + 次按钮「重试」（2026-10-05 确认）；刷新、提交、弹层里：`hz-error` 同一句，下面小字显示请求编号，方便排查 |

拦住操作的错误一律写在页面或弹层里，不用一闪而过的提示。用户重新输入后清掉对应字段的错误。

### 5.4 其他状态

| 状态 | 做法 |
|---|---|
| 空状态 | `hz-state` 空：衬线字一句「暂无 + 对象」，上方 28px 陶土短线；筛选后为空也用同一句 |
| 不可操作（状态不允许） | 按钮只按后端返回的 `actions` 显示；没有可做的操作时，用 `hz-notice` 显示后端给的 `lockedReason`，例如「已付款，不能再退货或改单价」。前端不按状态自己推算（00 章第 1 节） |
| 条件未满足 | 显示禁用按钮。业务条件（例如门店停用时的「确认订单」）来自后端 `actions` 里 `enabled: false` 的项，按钮下方写它的 `disabledReason`；只和本页输入有关的条件（例如还没勾选花材）由前端按输入禁用 |
| 操作成功 | `wx.showToast`，写结果，带图标最多 7 个字（「订单已确认」「已付款」），更长用 `icon: 'none'`；停留 `TOAST_DURATION_MS` |
| 放弃修改 | 改过内容再离开（返回、×、遮罩、右滑、安卓返回键），`hz-confirm`「放弃修改吗？」；改回原值不算修改 |
| 别人改了单（实时） | 查看页：静默刷新 + `hz-realtime-bar`。编辑页：不覆盖输入，出 `hz-realtime-bar`「这张订单刚被修改，点此查看最新内容」，用户点了才刷新；提交时仍有 `STALE` 兜底 |
| 分享链接失效 | 整页 `hz-state`：「邀请已失效」+ 一句原因（已取消、已提交、已过期）+「返回」 |

## 6. 信息层级细则（2026-10-04 补充）

从全站层级排查（2026-10-04）补充的 8 条规则：

1. **档案卡片（门店、员工、产品）**：用 `hz-card` 三行结构，第 2 行是名称（15px 墨色）、第 3 行是联系方式（次要色）+ 标记接在后面。
2. **组标题只两种**：
   - 页面卡片外的组标题：13px 墨色加粗（例如订单详情「订货明细」、对账「本月核对」）。
   - 弹层内的区块标题：12px 次要色（例如订货目录弹层「订货信息」「配方明细」）。
   - 字段标签（`hz-field` 上方 12px 次要色）不当组标题用。
3. **开关标签**：15px 墨色，同第 4 节 `hz-switch`（开关是可点的一行，不当字段标签；2026-10-05 确认）。
4. **金额统一**：15px 墨色加粗，不靠继承字号；详情和表单都用同样字号。
5. **明细行补两种变体**：
   - 不带价格的明细（配方）：名称一行（15px）、数量 + 单位一行（13px 次要色）。
   - 带附加字段的明细（售后）：在两行结构基础上加第三行（附加信息 13px 次要色）。
6. **带图目录卡统一价格格式**（订货页、产品管理）：统一写「¥68.00/束」，不分开写价格和单位。
7. **警示说明**：用琥珀色提示（`u-note-warn`，琥珀浅底 + 琥珀字 12px），不用灰色次要色文字。例如订货目录弹层「配方所有客户共用，改了所有客户都会变」。
8. **从详情页本页打开的弹层可不写单号**：用户知道在看哪一条，弹层抬头只写对象名（例如订货目录弹层「红玫瑰花束 · 春泥花店」），不重复单号。

这些规则和第 1 节「信息层级」、第 4 节「花众组件」的规则一起构成完整的层级系统。发现违反的地方按这 8 条改。

## 8. 文案规则

- 金额名称全站统一，见 03 章第 4 节，不换叫法。
- 按钮写动作：「确认订单」「登记收款」「作废售后」，不写「确定」「提交」「保存」这类泛词；保存写对象：「保存客户」「保存门店」「保存产品」「保存目录项」「保存员工」「保存分类」「保存售后」（2026-10-05 确认）；「提交订单」「提交售后」保留（弹层里的最终确认可以用「确认取消」「确认作废」「确认保存」）。
- 成功提示写结果，不写规则；报错写原因和怎么办，一句话。
- 空状态「暂无 + 对象」；页面不放规则说明，只放状态提示和需要核对的警告。
- 文案集中放在 `shared/copy`，页面和组件从这里取，方便统一修改。

## 9. 视觉验收

- 组件：在「组件总览」页逐个核对每个组件的所有状态，和 `docs/design/gallery.html` 对照。
- 页面：每个页面按 375、390、430 三个宽度截图，有样稿的和样稿对照，没有样稿的按本章组件规则和冻结原型的交互对照；iOS、安卓各一台真机看字体、细线、安全区。
- 状态：每类页面至少过一遍 第 5 节的加载、空、断网、出错、提交中、过期、实时刷新。
- 检查项：只用设计变量（Stylelint）；点击区域不小于 44px；次要文字对比度不低于 4.5:1（禁用按钮除外）；页面上没有第二种按钮、卡片、标签样式。
- 发现和样稿不一致的，先确认是改样稿还是改实现，不在代码里临时调整。
