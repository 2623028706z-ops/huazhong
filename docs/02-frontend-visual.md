# 02 前端与视觉

整理日期：2026-09-30；2026-10-04 按 `docs/spec-redesign-changes.md` 和定稿 `docs/audit/2026-10-03-redesign/v33.html` 同步。本章规定当前视觉和公共组件；定稿说明与旧 `docs/design/` 样稿、前端改版交接记录冲突时，以清单和本章为准。冻结原型只用于补充未变化的业务交互，不复制它的数据层。只做手机。

## 1. 原则

- 全站一套样子：按钮、卡片、状态标签、提示、空状态、加载和报错只在 `hz-*` 组件中定义一次；页面 WXSS 只写布局、间距和显示隐藏，设计值从 `styles/tokens.wxss` 读取。
- 墙色铺满页面；入口用细线窗格，内容用亮色卡片。入口大格的图标在上，名称和箭头在下；资料入口用小格。内容一单一张卡，抬头写往来方或对象 + 状态，细描边、无阴影，卡片圆角 10px，按钮和输入框圆角 8px。
- 标题和金额用思源宋体；金额衬线加粗、墨色。品牌红用于主按钮、选中和待办数字；警告、报错、逾期使用各自状态色，不能拿品牌红替代所有金额和正文。
- 字段名在左、值在右；可两列并排，备注、对账期间和带时间的字段占整行。每个日期、金额、单号、手机号都写字段名，列表和弹层的小字同样执行；多个字段之间用两个全角空格。
- 模块首页顺序是待办（并排小卡、大数字，0 也显示）→ 常用（大窗格）→ 资料（可选的小格），不写今日数字和身份行。门店、供应商直接落在业务页，没有首页。
- 明细统一表格；编辑用「表格 + 点行改」，不在表格行堆输入框。明细底部一行两列「合计数量 / 合计金额」，单行也显示；发货明细只显示合计数量，不显示价格。
- 底部固定操作区最多 2 个按钮；第三项按 06 章放到页面最下面的灰字操作，不设置「更多」。剩下 1～2 项操作时，作废或取消也进底栏。
- 校验只显示一次：能定位字段的写字段下，不能定位的写当前表单或弹层顶部。校验和业务规则不带「重试」，加载、网络、系统失败提供重试。提交中锁住同一操作区的所有按钮；实时变化不覆盖编辑输入。

改版取消的变量（2026-10-03）：`--hz-card`（卡片改用不透明 `--hz-paper` + 1px `--hz-hair` 描边）、`--hz-font-badge`（并入 `--hz-font-xs`）、`--hz-font-note`（13px，按用途并入 12 或 14）、`--hz-font-title`（17px，并入 18）、`--hz-font-amount`、`--hz-gap-home`、`--hz-gap-bar`。旧值的替换：10→11、13→12（次要信息）或 14（正文、记录）、15→16、17→18。

层次（2026-10-03 改版确认，「墙 → 卡 → 格」三层）：

- 墙：`--hz-bg`，颜色不变，首页背景图不受影响。
- 卡：所有 `u-card`、`hz-card`、明细卡、表单卡、搜索框、`hz-notice` 都是不透明 `--hz-paper` + 1px `--hz-hair` 描边，不加阴影。
- 格：卡片里的二级格（对账格、结算条合计）用 `--hz-tint`；待付 / 未收格用 `--hz-amber-bg`。
- 首页窗格（花众首页入口、模块首页常用和资料入口、「我的」入口）仍不铺底色，直接落在墙上：外框 `--hz-rule-frame`，格子之间 `--hz-rule`。

字距（2026-10-03 改版确认）：全站字距一律 0，包括按钮、入口名、顶栏标题、弹层标题、空状态、添加按钮、「我的」。只有 logo 图片例外。

按下反馈（2026-10-03 改版确认）：所有能点的卡片、入口格、待办卡、窗格、「我的」入口行、选择行、文字按钮都有按下态，在 100ms 内出现（`hover-class`，`hover-start-time` 20、`hover-stay-time` 70）：卡片、选择行底色换 `--hz-press`；墙上窗格铺 `--hz-press-wall`；按钮按下底色加深一档（主按钮叠 8% 墨色）。不能点的卡片（库存查询）不加，借此和能点的卡片区分。
颜色与状态：

- 品牌红用于主按钮、选中（勾选、下划线、角标）和待办数字；其他数字和金额用墨色。待办 0 用次要色。主按钮红底白字；文字操作通常墨色，页面最下面的第三项操作用灰色。
- 绿色：已发货、已处理、已收货、已提交、已入库、已出库、已报损、已盘点、已结清、有效、够用、已使用。
- 灰色：已取消、已关闭、已作废、已拒收、已停用、已过期。
- 琥珀色：待确认、待发货、待处理、待收货、待填报、未结清、待使用，以及「放久了 · 先用」和差异提醒。逾期用报错红色。
- 订单、采购单、入库单没有收付款状态；对账单仅「未结清 / 已结清 / 已作废」，没有部分结清。有效收付款卡片不画绿色「有效」，只有作废的标灰色「已作废」。
- 外部端订单、采购单、售后的作废显示为「已取消」，原因写「取消原因」；外部端不显示已作废的对账单。供应商对账从供应商角度写「应收」。
- 状态中文名和颜色从 `shared` 的状态表中取，页面不写。墙上线用 `--hz-rule`，卡片描边用 `--hz-hair`。

## 3. 字体、图标、图片

- 正文：系统字体。
- 标题、金额、空状态：思源宋体（Noto Serif SC）子集，只含数字、¥、常用标点和页面标题、模块名用到的字。金额不论在卡片、明细、信息行、对账格还是底栏，一律衬线加粗墨色（2026-10-03 改版统一，不再有无衬线常规字的金额）；字体没加载出来时回退系统宋体加粗，外部端同样处理。`wx.loadFontFace` 在 `app.onLaunch` 里全局加载，加载完成前用系统宋体或系统字体，不阻塞页面。子集由 `scripts/` 从代码里的标题文案自动抽字生成。
- logo：花众正式字标（陶土红横版，原图为原型 `assets/signature.png`），放在主包；拿到矢量原文件后换成 SVG。
- 图标：Lucide 线性图标，1.5px 线宽，按需生成 iconfont，颜色跟随 `color`。TDesign 组件内置的图标能换就换成 Lucide，换不了的调成同样粗细和颜色。同一个首页里不同入口不共用图标：手工入库 `arrow-down-to-line`、出库 `arrow-up-from-line`、报损 `trash-2`、客户对账 `store`、供应商对账 `truck`。
- 读屏：只有图标没有文字的可点控件（返回、关闭、筛选、垃圾桶、步进器加减、购物车、拨号）写 `aria-role="button"` 和 `aria-label`（文字在 `shared/copy`）；状态标签、金额不另写（2026-10-03 改版，B16）。
- 品牌背景：一张图「窗」（浅杏墙 + 2×2 窗光 + 一枝梅影），内置在主包 `assets/backdrop.jpg`，不支持上传更换（2026-09-30 确认取消品牌封面上传）。图由 `scripts/` 程序绘制生成（`pnpm gen:backdrop`），不用图库；JPG 控制在 200KB 以内（主包体积见 00 章第 9 节）。三处用法（2026-10-01 确认），都由 `hz-cover` 铺，页面不直接引用图片：
  - 花众首页、门店订货页、「我的」：整屏铺满，内容直接落在墙上，不铺卡片底，入口是细线窗格（外框 `--hz-rule-frame`、内线 `--hz-rule`，2026-10-03 改版）。
  - 登录页：同首页整屏铺满；logo 在上部，下部渐亮到墙色，隐私勾选和登录按钮贴底（按钮底边离屏幕底 58px），落在渐亮的墙上。
  - 模块首页：同一张图淡化铺底（叠一层 60% 墙色），待办卡和入口窗格落在上面。
  - 列表、详情、表单页只用墙色，不铺背景。
- 产品图：只有门店订货页显示产品图，产品资料表单保留查看、上传和更换；内部单据、产品列表和选择产品列表不放图。统一 1:1，上传后生成缩略图，订货列表加载缩略图。图片加载前显示 `--hz-tint` 底色占位，加载失败或没有图片时显示同样的占位加一个图片图标。

## 4. 花众组件（`components/hz-*`）

页面只用这些组件。「内部用」为空的是自己写的。

| `hz-tabs` 顶部业务标签 | 宋体大字、44px 点击区，选中墨色加粗 + 品牌红短下划线；门店「订单 / 售后 / 对账」、供应商「采购单 / 对账」、客户「门店 / 订货目录」、财务「对账单 / 未对账」「收款 / 付款」共用 |  |
| `hz-tabbar` 底栏 | 高 62px + 安全区，亮格底、顶部细线；图标 + 11px 文字，选中图标品牌红。门店「订货 / 订单 / 我的」；供应商「填报 / 采购单 / 我的」，填报角标为待填报数；只管仓库的员工「首页 / 库存 / 我的」。其他只管一个模块的员工没有模块底栏；多模块员工按当前账号导航进入模块，模块内有左上角返回 |  |

## 5. 统一状态：加载、网络、异常

所有页面按同一张表处理，页面不自己判断。请求层（`core/request`）把后端错误码转成下面的界面状态，页面只接结果。

### 5.1 加载

| 场景 | 做法 |
|---|---|
| 首次进入页面 | 骨架屏：按页面类型出灰块（列表页 3 张卡片、详情页 标题 + 3 行信息 + 明细、表单页 字段块）。`SKELETON_DELAY_MS` 内回来就不显示骨架，避免闪一下 |
| 下拉刷新 | 微信原生下拉刷新，背景用墙色（`--hz-bg`）；刷新时保留旧内容，不出骨架 |
| 列表翻页 | 滚到底自动加载下一页，底部一行「加载中」；全部加载完显示「已显示全部」（次要色 12px），只有一页时不显示 |
| 实时推送后刷新 | 静默重新拉取，不出骨架、不出加载提示；拉完出 `hz-realtime-bar` |
| 提交中 | 按钮文字换成「提交中」并禁用，其他按钮也禁用；超过 `SUBMIT_SPINNER_DELAY_MS` 按钮里加转圈；页面不遮罩 |
| 图片 | 见第 3 节，底色占位 |

### 5.2 网络

| 场景 | 做法 |
|---|---|
| 断网（`wx.onNetworkStatusChange`） | 顶栏下出一条提示「网络已断开，恢复后自动刷新」，页面内容保留可看；恢复后自动刷新当前页并收起提示 |
| 首次加载就失败 | 整页 `hz-state`：「网络不太好，没有加载出来」+ 次按钮「重试」 |
| 刷新、翻页失败 | 保留已有内容，顶部 `hz-error`「刷新失败，请重试」+ 文字按钮「重试」 |
| 提交失败（断网、超时） | 表单内容全部保留，`hz-error`「网络不太好，没有提交成功，请重试」；不自动重发 |
| 超时 | 按提交失败或加载失败处理，文案同上 |
| WebSocket 断开 | 不打扰用户，后台自动重连；重连后整页刷新一次 |

### 5.3 后端错误码

| 错误码 | 界面 |
|---|---|
| `UNAUTHENTICATED` | 回登录页，走手机号快速验证 |
| `ACCOUNT_DISABLED` | 整页 `hz-state`：「账号已停用，请联系花众」，只有「退出登录」 |
| `FORBIDDEN` | 整页 `hz-state`：「没有权限查看这个页面」+「返回」；弹层里出现时在弹层内写 |
| `NOT_FOUND` | 整页 `hz-state`：「没有找到这张单据」+「返回」 |
| `VALIDATION_FAILED` | 按 `fields` 标红对应字段，原因只在字段下显示；无法定位的才在当前表单 / 弹层顶部用 `hz-error`，不带重试，不重复显示。滚到第一个出错字段。规则没写专门提示的字段，原因统一写「格式不对，请检查」（阶段 4 确认） |
| `STALE` | 用 `latest` 刷新成最新内容，页面或弹层里写后端给的状态句（例如「订单已变成「待发货」，已刷新成最新内容，请核对后再保存」）；表单里已填的原因保留 |
| `BUSINESS_RULE` | 在页面或弹层里用 `hz-error` 写 `message`，不用 toast |
| `INTERNAL` | 首次加载：整页 `hz-state`「系统出错了，请稍后再试」，下面一行请求编号 + 次按钮「重试」（2026-10-05 确认）；刷新、提交、弹层里：`hz-error` 同一句，下面小字显示请求编号，方便排查 |

拦住操作的错误一律写在页面或弹层里，不用一闪而过的提示。用户重新输入后清掉对应字段的错误。

### 5.4 其他状态

| 状态 | 做法 |
|---|---|
| 空状态 | `hz-state` 空：衬线字一句「暂无 + 对象」，上方 28px 陶土短线；筛选后为空也用同一句 |
| 不可操作（状态不允许） | 按钮只按后端返回的 `actions` 显示；没有可做的操作时，用 `hz-notice` 显示后端给的 `lockedReason`，例如「已全部退货」。前端不按状态自己推算（00 章第 1 节） |
| 条件未满足 | 显示禁用按钮。业务条件（例如门店停用时的「确认订单」）来自后端 `actions` 里 `enabled: false` 的项，按钮下方写它的 `disabledReason`；只和本页输入有关的条件（例如还没勾选花材）由前端按输入禁用 |
| 操作成功 | `wx.showToast`，写结果，带图标最多 7 个字（「订单已确认」「已付款」），更长用 `icon: 'none'`；停留 `TOAST_DURATION_MS` |
| 放弃修改 | 改过内容再离开（返回、×、遮罩、右滑、安卓返回键），`hz-confirm`「放弃修改吗？」；改回原值不算修改 |
| 别人改了单（实时） | 查看页：静默刷新 + `hz-realtime-bar`。编辑页：不覆盖输入，出 `hz-realtime-bar`「这张订单刚被修改，点此查看最新内容」，用户点了才刷新；提交时仍有 `STALE` 兜底 |
| 分享链接失效 | 整页 `hz-state`：「邀请已失效」+ 一句原因（已取消、已提交、已过期）+「返回」 |

## 6. 信息层级细则（2026-10-04 补充）

1. 卡片抬头写对象或往来方 + 状态；单号、日期、经办人放下面并写字段名。订单 / 采购单详情信息卡不放金额，金额看明细底部合计。
2. 字段名在左、值在右；两列并排的字段仍各自写名称。备注、修改原因同一张卡各占一行；对账期间、带时间字段、地址等长内容占整行。
3. 明细统一表格；第一列标题就是卡片标题，不再另写重复「名称」。编码在名称下面。可编辑明细用点行小窗口，添加产品或花材进入同一个窗口；收货、发货、盘点分别改实收、实发、实盘。
4. 合计数量 / 合计金额一行两列，单行也显示；发货只显示合计数量；单价展示「¥68.00/束」，单价输入后缀「元」。配方按花材名称、用量和单位表格，不显示价格。
5. 列表搜索独占一行；状态行最右「筛选」文字 + 小图标无框，非默认条件时红色 + 个数；待确认、待发货等等待标签写数量。
6. 详情进度条一格一个关键节点：完成写过去式，当前写现在状态且红圈；订单 3 格（已下单 → 已确认 / 待确认 → 待发货 / 已发货）、售后 3 格（已提交 → 待处理 → 已处理）、采购单 2 格、邀请 2 格。取消 / 拒收 / 关闭用灰色终点替换最后一格，发货或处理后作废追加灰色作废格。日期只显示已发生且后端有记录的完整年月日；待发货格写「出货日期 / 2026-09-29」，缺失确认日期留空。
7. 收付款、对账单、手工入库 / 出库、报损、盘点不加进度条。单据收付款进度全部取消；信息卡最后一行「对账单 DZ-…　未结清 / 已结清 ›」，未进入写「未对账」。
8. 售后只读详情每个产品一张卡，申请 / 处理数量、问题原因、问题说明、图片展开；无图片不占位。处理表单保留问题内容只读，编辑数量 / 单价仍用表格 + 点行改。
9. 底栏最多 2 个按钮，无更多；第三操作放页面最下面灰字。具体动作、权限和禁用原因以 06 / 05 章为准。
10. 内容有记录列表、能跳其他单据或复杂表单的使用整页（订单确认、售后详情、采购单详情、收付款详情、对账单详情）；短只读内容、单层原因 / 退货 / 改价 / 退款 / 档案表单、筛选和选择保留半屏弹层；明细编辑用居中小窗口。弹层最多切一层，跳页面先关弹层；一句确认使用 `hz-confirm`。
11. 警告用琥珀提示，逾期用红色；已进对账单的来源单据操作禁用时写「已进对账单 DZ-…，请先由财务作废对账单」。
12. 外部端订单、采购单、售后的已作废显示为已取消；门店只看本店对账金额，不显示客户收款记录 / 抵扣多收；供应商对账用应收并显示花众付款的收款记录。外部账号操作日志不写员工岗位，写「门店 滨江店」「供应商 春禾花材」。

## 7. 统一格式（`shared/format` + 一个 WXS 工具文件）

| 内容 | 格式 | 例子 |
|---|---|---|
| 金额 | 字段名 + ¥ + 千分位 + 两位小数；后端给分，显示换元 | 合计金额 ¥1,234.50 |
| 减项金额 | 前面加「−」 | 售后金额 −¥136.00 |

| 未定出货日期 | 字段名 + 待定 | 出货日期 待定 |
| 多字段小字 | 每项写字段名，两项间两个全角空格，不用「 · 」连接 | 单号 SO-260929-018　　下单日期 2026-09-29 |

## 8. 文案规则

- 待确认 / 待发货订单叫「订单金额」，已发货叫「发货金额」；采购单收货前后都叫「采购金额」；应收 / 应付只在财务对账使用（供应商外部对账从供应商角度叫应收）。单据信息卡不重复金额，明细写合计。未处理售后金额写「待处理」。
- 门店 S5 标题「提交订单」，销售操作「确认订单」；新建采购单提交按钮「提交采购单」。手工单据「确认入库 / 确认出库 / 确认报损」。
- 新建单据和档案写「新建 + 对象」，添加只用于加明细；修改不用编辑，保存修改写「保存修改」；改单价叫改价。保存档案按钮写对象（保存客户、门店、产品、目录产品、员工、分类、供应商、花材）。明细小窗口底部「删除」「确定」。
- 作废按钮写对象；门店取消动作「申请取消」，对象「取消申请」，撤回「撤回申请」。财务只有对账单结清和作废收付款，不再出现核销、撤回核销、预收预付。
- 联系方式「联系电话」，登录账号「登录手机号」；入库来源「采购入库」；填报明细标题「花材明细」。日期写动作 + 日期，时间写动作 + 时间。
- 字段名在左、内容在右；自由文字叫备注，要解释取消、作废、关闭、拒绝、改价、修改、优惠的字段叫原因。优惠金额大于 0 时优惠原因必填。
- 产品计款，花材计种，单据计张；总数量按单位分别合计。筛选条件清掉叫重置，购物车叫清空。
- 日志外部操作人写「门店 滨江店」「供应商 春禾花材」，不拼员工岗位。
- 成功提示写结果；报错写原因和处理办法。空状态「暂无 + 对象」，不写无关规则说明；需要核对的警告保留。
- 文案集中在 `shared/copy`，页面和组件从统一出处取。

## 9. 视觉验收

- 组件：在「组件总览」页逐个核对每个组件的所有状态，和同步后的组件总览及 v33 定稿对照。
- 页面：每个页面按 375、390、430 三个宽度截图，有 v33 画稿的和定稿对照，没有样稿的按本章组件规则和冻结原型的交互对照；iOS、安卓各一台真机看字体、细线、安全区。
- 状态：每类页面至少过一遍 第 5 节的加载、空、断网、出错、提交中、过期、实时刷新。
- 检查项：只用设计变量（Stylelint）；点击区域不小于 44px；次要文字对比度不低于 4.5:1（禁用按钮除外）；页面上没有第二种按钮、卡片、标签样式。
- 发现和定稿、清单不一致的，按清单和本章统一修正；新发现的业务缺失单独说明，不复活作废决定。
