# 花众小程序设计审计：门店端、供应商端、登录

范围：login.png、store-*.png、sup-*.png，对照 wxml、docs/02、docs/06。优先级分三档：高 = 影响外部用户完成主任务，或和已定方向直接冲突；中 = 明显别扭；低 = 打磨。

截图的限制：store-order-detail 和 sup-order 用的 id 不是这个账号的单，所以只显示「没有找到这张单据」；login 截在 checking 阶段（已登录，正要跳转），只看到 logo。这三页按 wxml 评审，建议换成正确 id 后重拍。

## 一、门店端（登录 → 首页 → 订货 → 结算 → 订单 → 售后 → 对账 → 我的）

### M1 登录（login.png + wxml）
- 【低】checking 阶段只显示 logo，/me 慢时用户看不到任何反馈 → 超过 SKELETON_DELAY_MS 后，在 logo 下方显示一行 12px 次要色「加载中」。
- 【低】按钮「手机号快速验证登录」字距 0.16em → 改成 0（字距的共性问题见第三节）。
- 【低】门店、供应商第一次进来时，不知道该用哪个手机号 → 按钮下方加一行 12px 次要色「请用在花众登记的手机号」（需拍板，见第四节）。

### S0 门店首页（store-home.png）
- 【高】底栏要改成「首页 / 订货 / 我的」 → tabsOf 里的 cart 标签换成 order 标签（图标 shopping-bag），url 指订货页；原来购物车的件数角标挪到「订货」标签上。
- 【中】三张小格（订单、售后、对账）没有箭头，整个 hub 也没有按下反馈，看不出能点 → 小格右下角加 16px 次要色箭头，和主格一致；hz-hub 的主格和小格都加 hover-class，按下时铺一层 --hz-paper 50% 底色。整块和背景融在一起的样子保持不变。
- 【中】窗格描边用 --hz-rule（墨色 20%），落在窗光亮处时几乎看不见（截图里主格右上角） → 首页窗格线单独提到墨色 28–30%；小格内边距 16px 提到 18px，和主格对齐。
- 【中】主格「订 货」字距 0.3em，读起来像两个散开的字；小格名称字距 0.12em → 都改成 0。
- 【低】主格副行固定写「今日可订 3 款」 → 购物车里有东西时改写「已选 6 件 · ¥408.00」，点了照样进订货页。这样取消购物车标签后，首页仍能看到购物车。
- 【低】hub 下面空着大半屏 → 是否放「进行中的订单」预览需拍板。规格目前写的是「不显示待办数」。

### S1 订货（store-shop.png）
- 【高】订货页要变成底栏一级页 → 去掉返回；结算条用 hz-action-bar 的 tabbar 模式，贴在底栏上方。改单模式（?mode=edit）保持现状：有返回、没有底栏、用单独一份购物车。
- 【高】购物车的入口方案：结算条左侧现在只有「¥408.00 / 共 6 件」，虽然能点，但看不出来（规格写的是「点图标弹出」，实际没有图标） → 左侧加购物车图标，带件数角标，再跟金额；点图标或金额弹出现有的「已选产品」弹层（改数量、删除、去结算）。停用产品自动移除的 toast、客户停用时禁用「去结算」，这两段逻辑从 S2 并进这一页。S2 购物车页删除。
- 【中】「已选产品」弹层底部「清空」和「去结算」等宽并排，误点就清空整车 → 「清空」挪到弹层标题栏右侧，做成文字按钮，点了先确认；底部只留一个主按钮「去结算」。
- 【中】产品卡分四行：名称、编码、价格、步进器单独一行，一屏只放得下约 3 款 → 价格和步进器放到同一行（价格靠左、步进器靠右），卡高少一行。
- 【低】数量为 0 时减号看起来和可点状态一样 → 0 时减号变淡、不能点。
- 【低】没有图的产品只显示一块空粉色方块，像图没加载出来 → 按 02 章第 3 节「加载失败」的样子，占位里加一个图片图标。
- 【低】头部两行「晨曦花艺 · 滨江店」「下单日期 2026-10-03 · 今日可订 3 款」：门店名和首页重复，下单日期就是今天 → 平时合成一行「今日可订 3 款」，改单模式才显示原订单日期。
- 【低】「去 结 算」字距 → 0。

### S2 购物车（store-cart.png）
- 【高】按上面的方案删掉这一页。如果选择保留（见第四节），就改成二级页：有返回、没有底栏，从结算条图标进入。
- 【中】（如果保留）行内「6 [+] × ¥68.00」被加号隔开，读不成「6 × 单价」；「清空」孤零零飘在卡片右下 → hz-line-item 的 qty 模式改成：首行名称 + 「¥68.00/束」，次行左边步进器、右边金额；「清空」放顶栏下右侧。

### S5 结算（无截图，按 checkout wxml）
- 【高】只有一个产品时页面不显示合计（amountRows 为空），底栏只有「提交订单」，门店点提交前看不到要付多少 → 底部操作区左侧固定显示「¥408.00 · 共 6 件」，样式和订货页结算条一致，右侧是「提交订单」或「确认修改」。
- 【中】备注排在产品明细上面 → 改成常规顺序：下单信息 → 产品明细 → 合计 → 备注。
- 【低】下单信息里的「客户门店」是自己，可以删掉，只留下单日期。

### S3 订单（store-orders.png）
- 【高】卡片里两个日期都没有标签：首行「09-27」是下单日期，第 3 行「2026-09-28」是出货日期，而且格式还带年份，和首行不一致。出货日期正是门店最关心的 → 第 3 行改成「SO-260927-021 · 09-28 出货」，待定时写「出货待定」（叫法对照表那边定）；日期一律按 MM-DD。
- 【中】状态标签有 6 个（全部、待确认、待发货、已发货、已取消、已作废）加筛选按钮，「已作废」对门店是内部词 → 门店端去掉「已作废」标签，作废的单在「全部」里显示灰色胶囊（需拍板）。
- 【中】卡片半透明，和墙面几乎同色，卡片之间看不出边界 → 卡片改为不透明（见第三节）。

### S6 订单详情（截图无效，按 wxml + order.ts）
- 【中】订单金额排在产品明细下面，明细多时要往下滚才看得到 → 头卡的单号、状态下面加一行 16px 加粗金额，或者在底部操作区左侧显示金额（和结算页一致）。
- 【中】「核销记录」是财务用词，而且写死在 views/detail.wxml 里，没从 copy 取 → 门店端改叫「付款记录」，每条写「09-28 付款 ¥1,000.00」，文案移进 copy。
- 【中】「取消订单」（待确认，直接取消）和「申请取消」（待发货，要销售同意）随状态换名字，门店分不清有什么区别 → 按钮统一叫「取消订单」，区别写在弹层标题和说明里（需拍板）。
- 【低】取消申请记录是一张没有小标题的 info-card，夹在别的信息中间 → 加小标题「取消申请」，和 06 章「分组小标题」一致。
- 按钮数：同一时间最多两个（待确认：取消 + 修改；待发货：申请或撤回；已发货：申请售后），在 3 个以内。

### S7 售后 + 弹层（store-afters.png）
- 【中】「售后详情」现在是弹层，里面有图片、问题说明、状态和关闭原因，而且 S8 提交后就落到这个弹层上 → 改成整页「售后详情」，和员工端 X6 同一个模板。
- 【中】「申请售后」选订单的弹层每行用单号开头（SO-… · 粉玫瑰日常花束 等 2 项），门店记不住单号 → 改成首行「09-28 出货 · 粉玫瑰日常花束 等 2 项」，次行写单号和金额。
- 【低】标签「已作废」处理同 S3。底部固定「申请售后」符合方向。

### S8 申请售后（无截图，按 wxml）
- 【中】进来时明细是空的，要再点「添加产品」→ 弹层 → 选产品 → 填写，多一步 → 订单只有 1 个产品时直接带上；多个产品时一进页面就弹出选择弹层。
- 【中】每行卡片要填数量、原因、说明、图片，行多了很长，图片又不标必填 → 卡片内各组之间用 --hz-line 细线隔开；问题原因选「花材损坏 / 品质问题」时，「图片」标签后面加「必填」。

### S9 对账（store-statement.png）
- 【高】卡片第 2 行是自家门店名「滨江店」，每条都一样，没有信息量 → 改成产品摘要「粉玫瑰日常花束 等 2 项」，和订单卡一致。
- 【中】四格权重一样，门店最关心的「待付」不突出；四个格子的底色和外卡几乎同色，截图里看不出是分开的格子 → 「待付 ¥488.00」单独一行放大（16px 加粗，琥珀浅底），下面一行 13px 次要色「发货 ¥1,488.00 − 售后 ¥0.00 − 已付 ¥1,000.00」，把计算关系写明白；如果保留四格，格子用墙色底，和卡片拉开。
- 【低】筛选按钮独占一行，飘在右上角 → 改成左侧胶囊「出货日期：全部 ›」。
- 【低】首行日期是出货日期，含义和订单列表首行（下单日期）不同，两处都没标签 → 同 S3，在第 3 行写明「09-28 出货」。

### S4 我的（store-my.png）
- 【低】「个人资料」点开只重复身份卡上的三项 → 门店和供应商账号去掉这一行，身份卡直接显示完整手机号（自己看自己的）；空出来的位置可以放「联系花众」（需拍板）。
- 【低】「退 出 登 录」字距 → 0。（「组件总览」只在开发环境出现，不是问题。）

## 三、跨页共性问题

1. **卡片半透明，层次不分**【高】：--hz-card 是亮格 86%，放在 #f6ebdf 墙上，订单、采购单、对账卡和墙面几乎同色；对账格的内格又是亮格放在卡片上，完全看不出分格。→ u-card 改成不透明的 --hz-paper，加 1px --hz-hair 描边，或者把墙色再压深一档；卡内的二级格子（对账格、结算条）用墙色或 --hz-tint，形成「墙 → 卡 → 格」三层。首页窗格保持透明，不受影响。
2. **宽字距**【中】：hz-button 0.16em、hz-hub 名称 0.3em / 0.12em、hz-navbar 0.1em、hz-state 0.14em、hz-add-button 0.1em、hz-sheet 0.08em、hz-profile 0.06em、hz-entry-grid 0.2em / 0.14em → 全部改成 0（衬线标题最多 0.02em）。
3. **字号档位太多**【中】：tokens 有 10、11、12、13、14、15、16、17、18、22 十档，这几页实际用了 8 档 → 建议收成 11（只用于胶囊、角标、底栏）/ 12（辅助）/ 14（正文、次要）/ 16（卡片主信息、金额、按钮）/ 18（顶栏标题）/ 22（首页主格）。
4. **没有按下反馈**【中】：hz-card、hz-hub、hz-profile 行、hz-entry-grid 都没有 hover-class → 统一加一个按下底色。
5. **把自家名字当标题**【高】：门店对账「滨江店」、供应商填报「春禾花材 · …」、供应商采购单和对账「春禾花材」→ 外部端的卡片第 2 行一律写货品摘要。
6. **日期没标签、格式不统一**【高】：订单卡第 3 行出货日期带年份，首行又没标签 → 列表日期一律 MM-DD，第 3 行的日期带动词（「出货」「收货」）。
7. **弹层改整页**【高】：供应商采购单详情（P2、P5 共用）、门店售后详情（S7）→ 改整页。这些继续用弹层，都只有一层：已选产品、选订单 / 选产品、原因弹层、筛选、个人资料。
8. **主操作固定底栏**【中】：结算页底栏要带金额；供应商采购单详情的按钮要从弹层内容里挪到固定底栏；其余页面已经符合。
9. **页面边距**【低】：首页、我的、登录用 20px，列表、表单用 16px，订货页左侧分类贴边 → 统一 16px；分类栏贴边是常规做法，可以保留。
10. **文案写死在 wxml**【低】：「核销记录」（detail.wxml、purchase.wxml）、「退款记录」（ap-statement.wxml）、「取消采购单 / 确认取消」（po-list.wxml）没从 shared/copy 取，叫法统一时会漏掉 → 移进 copy。
11. **「已作废」对外部用户是陌生词**【中】：门店订单、售后标签和供应商采购单都有这个标签 → 外部端合并进「已取消」或隐藏这个标签（需拍板）。
12. **金额字体**【低】：截图里金额走的是系统宋体回退，笔画细、不显粗；HZ Serif 加载失败时，关键数字显得很弱 → 确认字体加载；或者外部端金额改用系统字体加粗加等宽数字（需拍板）。

## 四、需要用户拍板的取舍

1. **门店购物车入口**：方案 A（推荐）删掉 S2，订货页结算条加购物车图标和角标，点开「已选产品」弹层，「订货」标签和首页主格副行显示已选件数；方案 B 保留 S2 作二级页，从结算条图标进入。
2. **首页「订货」主格和「订货」底栏重复**：保持重复（常见做法），还是把主格换成别的内容（例如「再来一单」）？
3. **门店首页空白区**：是否放「进行中的订单」1–2 条预览？规格目前写的是「不显示待办数」。
4. **供应商底栏**：去掉「填报」后只剩「首页 / 我的」，保留两项的底栏，还是不要底栏、在首页右上放「我的」入口？
5. **取消叫法**：「取消订单 / 申请取消」统一成一个按钮名，靠弹层区分，是否同意？
6. **外部端「已作废」**：合并进「已取消」，还是隐藏这个标签？
7. **供应商对账叫法**：「应付 / 已付 / 待付」改成「货款 / 已收 / 待收」？
8. **联系方式**：多处报错写「请联系花众 / 销售」，但小程序里找不到电话。是否在「我的」加「联系花众」，在填报页显示采购员电话？
9. **门店订单详情加「再来一单」**（常规电商做法，按这张单的产品回填购物车）？
10. **登录页提示**：按钮下加「请用在花众登记的手机号」，这句算状态提示还是规则说明（02 章规定页面不放规则说明）？
11. **填报页日期**：信息卡显示邀请日期还是要货日期（看后端有没有要货日期字段）？
12. **外部端金额字体**：衬线还是系统字体加粗？
