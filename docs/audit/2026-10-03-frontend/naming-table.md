## 需要用户拍板

1. **新建还是新增**：按钮里「新建」有 12 处，「新增」有 3 处，日志全写「新增」。建议统一用「新建 + 对象」（档案和单据都这样写，日志跟着改）。也可以全部改成「新增」（金蝶、用友这类 PC 端 ERP 的习惯）。
2. **编辑还是修改**：建议全部用「修改」（日志和单据已经是修改，改动最小）。另一种做法是档案用「编辑」、单据用「修改」，这样有两种规则要记。
3. **销售新建订单的提交按钮**：规格定的是「确认订单」（销售新建的单直接就是待发货，叫确认也说得通），但和详情里定出货日期的「确认订单」同名。另一种做法是改成和门店一样的「提交订单」。采购单的「确认下单」要不要一起改，也请一并定。
4. **门店端的「结算 / 去结算」**：门店端不在线付钱，「结算」容易让人以为要付款。可以保持现状，因为这是微信商城的常见叫法。也可以改成「去下单 → 确认订单页 → 提交订单」。如果门店底栏按已定方向改成「首页 / 订货 / 我的」，这条要一起定。
5. **填报邀请还是询价 / 报价**：规格叫「填报邀请 / 填报」，常规采购叫法是采购发「询价单」、供应商「报价」。不过这里供应商填的是供货数量和单价，结果会直接生成采购单，比单纯报价多一步。建议保留规格叫法，按表一第 1 条统一。
6. **财务的「客户对账 / 供应商对账」**：可以保留（门店、供应商端也都叫「对账」，三端一个词）。也可以改成 ERP 常见的「应收 / 应付」或「客户往来 / 供应商往来」。建议保留「对账」。
7. **手工入库单 / 手工出库单还是其他入库单 / 其他出库单**：后一种是金蝶、用友的标准叫法，前一种是规格书现在的叫法。建议保留「手工」，仓库员工更容易懂。
8. **目录项还是目录产品**：02 §8 已经定了「保存目录项」，但弹层标题和空状态用的是「目录产品」。建议统一成「目录产品」（销售员想的是产品），按钮相应改成「保存目录产品」。如果维持「目录项」，那弹层标题和空状态要跟着改。
9. **采购单的留痕叫「变更记录」还是「改单记录」**：03 章和 02 章写的是「改单记录」，06 章 C4、P2 写的是「变更记录」。建议和订单统一成「变更记录」（卡片标记仍叫「改单」），需要改 03 章多处。
10. **「改单价」还是「改价」**：按钮和日志用「改单价」，标记、记录、原因、确认按钮都用「改价」。建议统一成「改价」。如果觉得「改单价」更清楚（不会误以为是改总价），那就把标记、记录、原因、确认按钮都改成「改单价」。
