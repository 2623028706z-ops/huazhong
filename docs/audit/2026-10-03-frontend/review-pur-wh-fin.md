# 花众小程序设计审计：采购 / 仓库 / 财务

范围：/tmp/hz-audit-shots 下的 pur-*、wh-*、fin-*，共 29 张截图，并对照 wxml 看了截图里看不到的弹层、滚动区和按钮。
优先级：高 = 影响主流程或会让人看错；中 = 多点一步、层级不清；低 = 细节。
已知 bug 不重复列。截图能印证的地方在条目里注明。

---

## 一、采购（看需求 → 建采购单 → 发填报邀请 → 看供应商）

### C1 采购首页（pur-home）
- 【高】入口格在上，待办在下；待办只有一张邀请卡，卡上只有供应商和邀请号，比列表卡少了花材和枝数。
  → 改成待办行在上，每类一行带数字：「待填报邀请 1 ›」（进 C6 并筛「待填报」）、「待收货采购单 2 ›」（进 C3 并筛「待收货」）。是否加「缺货花材 n ›」（进 C2 并打开「只看缺货」）要用户定，见第五节。入口格移到待办下面。
- 【中】入口格每格高约 75pt，图标在左上、名字在下，两行内容占一格，可点的感觉弱。
  → 保留和背景融为一体的窗格样式。图标和名字放进同一行，格高降到约 56pt；描边从 hair 改成 `--hz-rule`；加按下态（底色略加深）；名字去掉 0.2em 字距。

### C2 采购需求（pur-demand）
- 【中】起止日期占两个大输入框，下面还有一整行次按钮「只看缺货」，筛选区占了约 1/4 屏。「只看缺货」长得像动作按钮，不像筛选。
  → 日期合成一行「出货日期 10-03 至 10-09 ›」，点开选起止。「全部 / 只看缺货」改成两段切换，和日期放同一行或紧挨着。
- 【中】来源弹层（wxml 里的 sourceSheet）里有三组记录（已邀请、在途采购单、按出货日期分组），而且能跳到 C4 和邀请。这属于「有记录、能跳别处」的弹层。
  → 改成整页「需求来源」。至少要改的是：点「在途采购单」时，现在是在弹层上叠一个新页面，回来时弹层的状态不清楚。
- 【中】「邀请供应商」先弹一个只有一个下拉框的弹层，选完再点「下一步」进 C7，多了一步。
  → 去掉这个弹层，直接进 C7。C7 本来就有「请选择供应商」选择器（截图 pur-invite-form），在那里选就行。
- 【低】空状态写「暂无待发货订单」，「0 张订单」又单独占一行。
  → 没有数据时不显示「0 张订单」。

### C3 采购单列表（pur-orders）
- 【中】状态标签有 6 个（全部 / 待收货 / 已收货 / 已拒收 / 已取消 / 已作废），加上筛选按钮已经排满一行，屏幕再窄就挤。
  → 标签只留「全部 / 待收货 / 已收货」。已拒收、已取消、已作废这些结束类状态收进筛选弹层的「状态」。
- 【低】卡片第三行「PO-260929-006 · 周宁」里的「周宁」没有标注是谁，看不出是采购员。
  → 列表里不显示采购员，或者写成「采购 周宁」。
- 【低】新建按钮写「新建采购单」，表单底部按钮按规格是「确认下单」，详情页叫「修改采购单」。这几个叫法另一路在统一，这里只记一笔。

### C4 采购单详情（pur-order-detail，-2 截图和第一张一样，说明页面不用滚动）
- 【高】单子还是「待收货」，金额区已经显示「应付 ¥0.00 / 已付 ¥0.00 / 待付 ¥0.00 / 财务 无需付款」，容易让人以为这单不用付钱。规格写的是收货后才显示已付、待付。截图能印证。
  → 收货前金额区只显示「采购金额」。应付、已付、待付和财务状态都在收货后才出现。这正是记忆里的未决问题「C4/W3 金额是否隐藏」，见第五节。
- 【中】同一页里金额字体不统一：明细行的金额用衬线大字，合计区的金额用无衬线常规字，最该突出的合计反而最弱。
  → 金额统一用一种字体。合计「采购金额」用 15px 加粗墨色，明细行降一档。
- 【低】「来源：花众采购下单」读起来不顺。
  → 改成「采购员下单」或「供应商填报生成（YQ-…，可点）」。如果是填报生成的，应能点回原邀请。
- 底部按钮只有 2 个（取消采购单 / 修改采购单），符合规则。

### C5 采购单表单（pur-order-form，修改模式）
- 【低】步进器的「−」是空心圈，「+」是陶土红实心圈，一轻一重，看着像只能加不能减。
  → 两个按钮用同一种样式（都用细线圈），数量字放大一点。
- 【低】「修改原因」放在合计卡里面，和合计金额挤在一起。
  → 改成单独一组「修改原因」，放在合计下面。
- 【已知 bug】「最新缺口」为空出现在核对弹层里，这张截图看不到。

### C6 供应商填报（pur-invites）
- 【高】点卡片打开的详情弹层里有：信息、明细、跳去采购单的链接（poLink），以及「取消邀请 / 填报链接 / 修改」三个按钮。取消和分享还要在弹层里再切一层。这正好是「有记录、能跳别处、多个操作」的弹层。
  → 改成整页「填报详情」。底栏放「修改」，「发送填报链接」也放底栏，或者在顶部信息区放一个链接按钮。「取消邀请」收进「更多」。取消用原因弹层（只有一层）。
- 【中】同一件事有三种叫法：C2 按钮「邀请供应商」、首页入口和列表标题「供应商填报」、C7 标题和按钮「发出邀请」。
  → 交给叫法对照表那一路统一，建议统一成「填报邀请」。
- 【低】已提交那张卡第三行是「YQ-260928-001 · 周宁 · PO-260929-006 · 待收货」，四段内容挤在一行，后面的「待收货」容易被当成邀请自己的状态。
  → 第三行只写「YQ-… · 已生成 PO-…」。采购单状态放到详情页里看。

### C7 邀请表单（pur-invite-form）
- 【低】标题和底栏按钮都是「发出邀请」，重复了。
  → 标题改成「新建填报邀请」，按钮保留「发出邀请」。
- 【低】这张截图是空表单。实际从 C2 进来时供应商已经带好，用户看到的样子要以 C2 → C7 这条路的截图为准。

### C8 供应商（pur-suppliers）
- 【中】点卡片打开的编辑弹层有 7 个字段（名称、联系人、电话、地址、启用、开通供应商端账号、登录手机号），超出了「短表单」的量。
  → 改成整页「供应商资料」：上半部分是资料，下半部分可以链到「待收货 n 单」「填报邀请」。要不要做成供应商详情页，见第五节。
- 【低】卡片上的电话不能点，没法直接打。
  → 电话右边放一个电话图标，点了拨号。
- 【低】按规格，停用的供应商要写「已停用 · 待收货 n 单」。截图里没有停用的数据，无法验证。

## 二、仓库（待收货 → 收货 → 库存/花材 → 入库/出库/报损 → 盘点 → 流水）

### W1 仓库首页（wh-home）
- 【高】9 个入口排了 5 行，待办被挤到屏幕最下面，第一张待办只露出一半。最常用的「待收」排在第 7 格。
  → 改成待办行在上：「待收货 2 ›」（进 W2 并筛「待收货」）。入口压到 6 个以内，按常用程度排：采购收货、库存、手工入库单、手工出库单、报损、盘点。「出入库记录」放进库存页或花材详情里（规格 W12 本来就有「最近出入库记录 → 查看全部」）。「出库分类」放进手工出库单页面（新建出库表单里已经有「管理分类」）。「花材」并进库存（见 W11）。
- 【中】图标分不出来：手工入库单和手工出库单都是同一个 file-text 图标；报损用的是 rotate-ccw（和售后的图标一样）。
  → 入库用 arrow-down-to-line，出库用 arrow-up-from-line，报损用 trash 或 alert-triangle。
- 【中】入口叫法不统一：「手工入库单 / 手工出库单」带「单」，「报损 / 盘点」不带，「待收」只有半个词。
  → 交给对照表统一。常规 ERP 的说法是「采购收货、其他入库、其他出库、报损、盘点、库存、出入库流水」。

### W2 待收（wh-pending）
- 【中】标题是「待收」，但页面里有「全部 / 已收货 / 已拒收 / 已取消 / 已作废」，其实是收货记录全集。
  → 标题改成「采购收货」，默认停在「待收货」。标签收法和 C3 一样，只留 3 个。
- 【低】卡片和 C3 一样，合理。

### W3 收货（wh-receive）
- 【高】拒收没有入口。规则是「实收全填 0 就算拒收」，但页面上没有任何提示，仓库员不会知道。
  → 底栏改成两个按钮：「拒收」（次按钮，点了先确认，然后把实收清零提交）和「确认收货」（主按钮）。
- 【中】每行写「采购 150 枝」，下面的步进器默认也是 150，看不出哪个是实收。
  → 步进器前面加「实收」两个字。实收和采购数不一样时，在行上标「少收 n / 多收 n」（规格有这条，截图里数量相同所以看不到）。
- 【中】信息卡把「来源 花众采购下单」也显示出来了。对仓库没用。
  → 收货页只显示供应商、单号和下单日期。
- 【已知 bug】改价原因框不出：截图里没改价，所以无法印证。
- 收货后底部是 作废 / 退货 / 改单价，正好 3 个，符合规则。退货和改价弹层里只有明细和原因，没有记录，可以保留弹层。

### W11 库存（wh-stock）和 W14 花材（wh-materials）
- 【高】两个列表几乎一样：同样 5 种花材、同样的编码和分类。区别只有右边一个写库存数，一个写单位「枝」（单位单独占右侧没有信息量）。首页因此多了一个入口。
  → 合并成一个「库存」页：每行显示花材、编码 · 分类、库存数量。有管理权限的人底栏出现「管理分类 / 新建花材」。点行进花材详情，编辑资料也从详情进入。是否合并见第五节。
- 【中】库存页规格要求「左侧分类」，现在只有一个筛选按钮，按分类找花材要点两下。
  → 搜索框下面加一行分类标签（全部 / 玫瑰 / 主花 / 配花 / 叶材），可以横向滑动。
- 【低】库存为 0 和停用的花材怎么显示，现在没有数据，看不到。

### W12 花材详情（wh-material）
- 【中】规格要求的「最近出入库记录 + 查看全部」没做；信息卡里「库存 86 枝」和下面批次的合计重复；「状态 启用」没什么信息量。
  → 顶部写花材名，大字显示库存数，下面一行写「编码 · 分类 · 单位」。然后是「库存批次」（入库日期和剩余数量）。再下面是「最近出入库」三条加「查看全部 ›」（进 W13 并带上这种花材）。
- 【低】底栏是「手工入库 / 手工出库」，常用的「报损」不在里面。
  → 底栏用「手工出库」（主按钮）、「报损」，把「手工入库」放进「更多」，按钮还是 3 个以内。

### W4 手工入库单（wh-docs-in-empty）、W15 手工出库单、W7 报损
- 【低】三个列表结构一样，没问题。空状态「暂无入库单」配一条短红线，文字有字距。
  → 去掉字距（全局统一去）。

### W5 出入库表单（wh-doc-form，入库）
- 【中】入库表单先选供应商，再加明细，原因写「原因（选填）」。对入库来说，叫「备注」更通顺。另外 wxml 里入库多行合计那一行只有金额、没有「合计」二字。
  → 字段改叫「备注」。合计一行写成「合计 ¥… · 共 n 枝」，和采购单表单保持一致。
- 【中】出库表单的「管理分类」直接跳到另一个页面（`onManageCategories` 里用的是 navigateTo）。规格写的是弹层，维护完要回到表单、草稿还在。现在等于中途离开表单。
  → 改回半屏弹层，只做新增、改名、启用。这个弹层没有记录，符合「保留弹层」的条件。
- 【低】供应商下拉框占位写「请选择」，C5/C7 写的是「请选择供应商」。
  → 统一写「请选择供应商」。

### W8 盘点（wh-stocktakes）
- 【中】新建盘点的弹层用一排开关（hz-switch）来多选分类。开关的意思是「启用 / 停用」，拿来当多选不合适。
  → 改成可以点选的分类卡片或标签，选中后打勾。底部按钮写「开始盘点（n 类）」，并加一个「全选」。
- 【低】空页面上什么也没有，看不出盘点是做什么的。
  → 空状态下面加一句说明：「按分类清点实物，差异会自动调整库存」。

### W9 盘点表单（只看了代码，没有截图）
- 【中】每种花材单独一张卡，卡里有 4 行（名称、账面数、实盘输入框、差异）。花材一多要滚很久。
  → 一种花材压成一行：「名称 / 账面 86 / [实盘输入] / 差 −2」。有差异的行标琥珀色，差异原因放到最后。

### W13 出入库记录（wh-moves）
- 【中】只有一个孤零零的筛选按钮，找某种花材要点开筛选再选，很费劲。
  → 加一个搜索框（按花材或单号），筛选按钮放在搜索框右边，和库存页一样。
- 【低】第三行「PO-260928-004 · 09-29 入库 · 陈青」里，「09-29 入库」其实是批次，看着像在重复日期。
  → 写成「批次 09-29」。数量「+120 枝」是这张卡最重要的信息，应放大到 15px 加粗（入库绿、出库红，规格是这么定的）。
- 【低】数据疑点：库存页尤加利是 86 枝，流水里只有一条 +120，其他 4 种花材有库存却没有任何流水。可能是种子数据造成的，需要确认演示库里流水和库存是否对得上，不然验收时会被质疑。

## 三、财务（客户往来 → 登记收款 → 收付款记录 → 供应商往来/付款 → 收付款方式）

### F1 财务首页（fin-home）
- 【高】待办是两张混在一起的卡片：一张「未付款」采购单，一张「拾光花店 预收 ¥64.00」。「查看全部」统一跳到供应商对账，看不出有几类事要处理。另外，拾光花店的未收是 ¥0（截图 fin-customers 能看到），这笔预收没有可以核销的单子，作为待办处理不了。
  → 改成按类分的待办行：「待付款 1 笔 · ¥960.00 ›」（进 F5，只看有待付的供应商）、「客户未收 1 家 · ¥2,588.00 ›」（进 F2，只看有未收的客户）、「预收待核销 n 家 ›」。最后这一类只算「同时有预收和未收」的客户，见第五节。
- 【中】「供应商对账」和「客户对账」用的是同一个图标；入口顺序把供应商排在客户前面。
  → 客户对账排第一，图标分开（客户用 store 或 user，供应商用 truck 或 users）。「收付款方式」是不常用的设置，排到最后，或者移到「我的」里。
- 【低】待办卡上的状态写「未付款」，供应商对账页写的是「待付」。叫法不一样，交给对照表统一。

### F2 客户对账（fin-customers）
- 【中】最重要的数字「未收 ¥2,588.00」放在右上角，用的是灰色小字，和「未收 ¥0.00」看起来一样重。
  → 未收大于 0 时，金额用 15px 墨色加粗、靠右；等于 0 时写「已结清」并用灰色。列表按未收从多到少排。加一个筛选「全部 / 有未收」。
- 【低】第二行「发货 ¥3,588.00 · 已收 ¥1,000.00 · 预收 ¥64.00」，三段金额太长，有被截断的风险。
  → 只保留「已收」和「预收」。发货金额放到 F3 里看。

### F3 客户对账详情（fin-customer，-2 截图和第一张一样，说明页面不用滚动）
- 【高】点发货单卡片会打开弹层：先是发货单，点售后切到售后详情，点核销记录又打开收款详情（这是另一个弹层组件），收款详情里还能「撤回核销 / 登记退款 / 作废收款」，退款和作废又要再切一层。最深有三到四层，而且有记录、有多个操作。供应商那边的同类单据已经改成整页（payable 页面），客户这边还在用弹层，两边不一致。
  → 发货单应收详情改成整页（和供应商的 payable 页面对称）。收款详情也改成整页（见 F8）。弹层里只留作废原因、退款登记这种一层的表单。
- 【中】对账格有 5 个格子，最后一行只有 1 格，留了一个空洞；格子边框几乎看不见；「未收」那格用琥珀底高亮，但字号和其他格一样。
  → 改成一个主数字加一行次要数字：顶上大字「未收 ¥2,588.00」，下面一行小字「发货 3,588 · 售后 0 · 已收 1,000 · 预收 0」。
- 【中】卡片右下角的大金额是发货金额 ¥1,488，真正要收的「未收 ¥488」却放在第三行的小字里。
  → 财务看的是未收：右下角显示「未收 ¥488.00」，第三行写「SO-… · 发货 ¥1,488」。已收清的单子显示「已收清」。
- 【低】「退款记录」每行是一整行拼起来的文字「号 · 日期 · ¥金额 · 状态」。
  → 改成和其他卡片一样的两行格式（第一行号和金额，第二行日期和状态）。
- 【低】「预收（未核销）」这个说法太专业。
  → 改成「预收余额」，并和供应商那边的「可用预付」统一成「预收余额 / 预付余额」。

### F4 登记收款（fin-receive、fin-receive-2）
- 【中】核销明细每行右边只写一个金额（¥2,100.00 或 ¥488.00），没有说明是什么。对照 F3 可以看出这是「未收」，不是发货金额。
  → 写成「未收 ¥488.00」，第二行小字写出货日期。
- 【中】每张单子是一张卡：上面是单号，下面左边半宽输入框、右边一个「填入」文字按钮，右侧空了很大一块。两张单子就占了半屏。
  → 一张单子压成一行：「SO-… · 未收 ¥488 / [本次核销输入框] / 全额」。输入框靠右对齐。
- 【中】「本次核销 ¥0.00 / 转为预收 ¥0.00」这条汇总在列表最下面，要滚到底才看得到。
  → 汇总固定在底栏按钮上方，或者合进底栏左边，写「核销 ¥… · 转预收 ¥…」，按钮放右边。
- 【低】从客户详情进来时客户已经定了，但客户下拉框还能改。「收款金额」框没有 ¥ 前缀，也没有占位提示。
  → 从客户详情进来时客户只读；金额框前面加「¥」。
- 【低】「填入」这个说法不直观。
  → 改成「全额」或「填满」。

### F8 收付款记录（fin-records）
- 【中】两排标签叠在一起（收款 / 付款，下面又是全部 / 有效 / 已作废），层级重。截图日志里这页的筛选栏也没找到（FILTER-FAIL）。
  → 收款和付款改成顶部的两段切换；「有效 / 已作废」收进筛选里，默认只看有效的。
- 【高】点一条记录打开的 payment-panel 弹层里有：信息、核销历史（每行带「撤回」按钮）、退款历史（每行带「作废退款」按钮）、「登记退款」、「作废收款」。还要切到退款或作废那一层。这是本模块最重的弹层。
  → 改成整页「收款详情 / 付款详情」。底栏放「登记退款」和「作废收款」（次按钮）。「撤回核销」留在每条核销记录上，点了用原因弹层确认（只有一层）。
- 【低】列表没有合计。
  → 筛选了日期之后，顶部加一行「本期收款合计 ¥…」。

### F5 供应商对账（fin-suppliers）
- 【中】和 F2 是同一类问题：「待付 ¥960.00」用灰色小字，¥0 的供应商也排在列表里，看起来一样重。
  → 和 F2 一样改：大于 0 时加粗，等于 0 时写「已结清」，按待付排序，加「有待付」筛选。

### F6 供应商对账详情（fin-supplier）
- 【中】状态标签有「无需付款」，但规则写明 0 元、全部赠送的单据不进对账，这个标签基本永远是空的。5 个标签也排得太满。
  → 去掉「无需付款」，只留「全部 / 未付 / 部分付 / 已付」。
- 【中】对账格写的是「应付 / 已付 / 待付 / 可用预付」，客户那边写的是「发货金额 / 已收 / 未收 / 预收（未核销）」，两边不对称。
  → 统一成常规叫法：客户用「应收 / 已收 / 未收 / 预收余额」，供应商用「应付 / 已付 / 未付 / 预付余额」。是否把「待付」改成「未付」交给对照表定。版式和 F3 一样，改成一个主数字加一行次要数字。
- 【中】点单据会进 payable 整页，方向对了。但那一页没有「登记付款」按钮，要付这一单还得退回上一页。
  → payable 页面底栏加「付这一单」，点了进 F7，并只勾选这张单据。
- 【低】春禾花材没有应付单据，空状态「暂无应付单据」上面还摆着一排 4 个 ¥0.00 的格子。
  → 全部为 0 时，对账格合成一行「暂无往来」。

### F9 收付款方式（fin-methods）
- 【低】只能新增、启用和停用，不能改名，也不能排序。所有开关都是陶土红，看着很重。
  → 点名字可以改名，排序先不做。开关打开时用墨色或绿色，陶土红只留给主按钮（规格写了陶土红不做大面积使用）。这个页面本身已经是「一份收付款方式」，符合已定的合并方向。
- 【低】这是不常用的设置，却在首页占了一个入口。
  → 见 F1，移到最后或放进「我的」。

## 四、跨页共性问题

1. **【高】弹层太重，弹层里套弹层。** 这类弹层有：C6 填报详情、F3 发货单（含售后、收款）、F8/F6 收付款详情（payment-panel）、C2 需求来源、C8 供应商编辑。统一规则：有记录、能跳到别处、有两个以上操作的，都改成整页；弹层里只留一层表单（原因、退款、选花材、选供应商）。F6 已经把单据改成整页了，F3 要跟着对齐。
2. **【高】模块首页结构。** 三个模块首页都是入口在上、待办卡在下；仓库首页的待办已经被挤到首屏外面。统一改成：身份行 → 按类分的待办行（图标 + 名称 + 数量 + 金额 + ›，点了进入已经筛好的列表）→ 入口格（每个模块不超过 6 个）。待办行的数据可以用现有 todos 接口按 kind 汇总。「查看全部」不要了，每一类各自是一个入口。
3. **【高】卡片透明，层次不够。** `--hz-card` 是 86% 不透明的亮格，铺在 #f6ebdf 的墙上，在列表页几乎和背景融成一片（各列表截图都能看到）。
   → 卡片改成实底 `--hz-paper`，墙色压深一档，或者给卡片加一条 hair 描边。首页入口格不动，按已定方向保留和背景融为一体的样子。
4. **【中】字距太宽。** 现在加了字距的地方：按钮 0.16em、入口名 0.2em、导航标题 0.1em、空状态 0.14em、添加按钮 0.1em、弹层标题 0.08em、hz-hub 0.3em。截图里「新 建 采 购 单」「确 认 收 款」字都是散开的。
   → 全部改成 0，只有 logo 字可以保留。
5. **【中】页面边距不统一。** 模块首页 20pt，列表和详情 16pt，底栏按钮约 14pt，所以首页卡片、列表卡片和底栏按钮左边对不齐（比较 pur-home 和 pur-orders 两张截图）。
   → 统一用 16pt，底栏左右也改成 16pt。
6. **【中】字号和金额样式太杂。** 同一页里，卡片金额用衬线约 20px，信息卡合计用无衬线 14px 常规，明细行金额又是衬线（C4 最明显）。
   → 字号收成 4 档：17 标题、15 重点（对象名、金额加粗）、14 正文、12 辅助。金额统一一种字体，「合计、未收、待付」这些关键数字最重。
7. **【中】关键数字没有放在关键位置。** 财务列表最该看的未收、待付用的是灰色小字；客户对账卡上最大的数字是发货金额；出入库记录的数量变化反而很弱。
   → 每张卡右侧的大数字必须是这个角色最关心的数：财务看未收或待付，仓库看数量，采购看金额。
8. **【中】状态标签太多。** C3、W2 有 6 个，F6 有 5 个，F8 叠了两排。
   → 一行最多 4 个：全部 + 待办类 + 完成类，结束类和作废类收进筛选。
9. **【中】选择操作。** C2 有勾选框和底栏，是对的；W8 用开关做多选，C2 邀请先弹一个选供应商的弹层。
   → 统一成点卡片选中、底栏按钮写清数量，选供应商这一步并到下一页去做。
10. **【低】图标重复，分不出功能。** 手工入库和手工出库同一个图标；供应商对账和客户对账同一个图标；报损用了售后的图标。
11. **【低】叫法问题（交给对照表）。** 「待收」和「采购收货」；「邀请供应商 / 供应商填报 / 发出邀请」；「未付款 / 待付 / 未付」；「预收（未核销）」和「可用预付」；「原因（选填）」用作入库备注；「填入」；「来源：花众采购下单」。
12. **已知 bug 的印证情况：** 没有下拉刷新和翻页加载提示，所有列表截图都看不到加载中或「已全部加载」（数据都只有一屏）；其他已知 bug 在这批截图里没有出现。

## 五、需要用户拍板的取舍

1. **采购单收货前要不要显示应付、已付、待付和财务状态**（C4/W3，记忆里的未决问题）。建议收货前只显示采购金额，现在的「财务 无需付款」会误导人。
2. **库存（W11）和花材（W14）要不要合并成一个页面。** 建议合并：一个列表同时显示库存数量；管理功能（新建、分类）给有权限的人放在同一页底栏。
3. **仓库首页入口怎么精简。** 「出入库记录」放进库存或花材详情，「出库分类」放进手工出库单，「待收」和待办行要不要重复保留入口。建议待办行代替「待收」入口；不想去掉的话就改名「采购收货」。
4. **采购首页要不要加「缺货花材 n」这一类待办。** 这要后端在 todos 里加一类。不加的话采购首页只有「待填报」一类，信息偏少。
5. **财务待办里的「预收」算不算待办。** 建议只算「既有预收余额又有未收」的客户，只有预收、没有未收的客户不进待办（拾光花店这种情况是处理不了的）。
6. **收货页要不要加明确的「拒收」按钮。** 规则是实收全 0 等于拒收，建议做成显式按钮，提交前确认一次。
7. **供应商（C8）要不要从编辑弹层升级成「供应商详情」整页**，并在里面链到在途采购单、填报邀请、对账。
8. **收付款方式放在财务首页入口，还是挪到「我的」或设置里。**
9. **需求来源（C2）是否改整页。** 它只是看一眼的内容，但里面有记录、能跳转。按已定规则应该改；如果想保留「快速看一眼」的体验，可以只把里面的跳转改成「先关弹层再进去」。
