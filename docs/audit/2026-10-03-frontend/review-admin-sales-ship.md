# 花众小程序设计审计：管理员 / 销售 / 发货

范围：u1-*、sales-*、ship-* 截图，加上对应 wxml/ts（只读）。优先级：**高** = 影响业务正确或主流程，**中** = 明显体验问题或与已定方向差距大，**低** = 打磨。
截图限制：u1-my-profile-sheet 没拍到弹层（和 u1-my 一样）；sales-order-confirm-sheet 叠在「待发货」单上，是截图脚本强行打开的，不代表真实状态；sales-order-detail-2 和 sales-order-detail、ship-ship-2 和 ship-ship 内容相同；「待确认」状态的订单详情（3 个按钮）没截到，按代码核对。

## 一、管理员（主包）

### M3 花众首页（u1-home）——保留现状，只做入口卡打磨
- 【中】入口格点下去没有任何反馈（`hz-entry-grid` 没有 `hover-class`，全项目都没有用 hover-class）→ 格子加按下态：底色换成 `--hz-paper` 50% 左右，100ms 内出现。
- 【低】模块名字距 0.2em（「销 售」「发 货」读着是散字）→ 改成 0～0.04em；名称 17px 可以保留。
- 【低】窗格线是墨色 20%，在背景亮的地方（右上窗光）几乎看不见 → 外框提到 28～30%，内线保持 20%，外框和内线分开调；格内左右留白 16px 和箭头右边距 14px 不一致，统一成 16px。

### M4 我的（u1-my / profile-sheet）
- 【中】「个人资料」弹层只放名字、岗位、手机号，身份格里已经有其中两项 → 去掉「个人资料」这一行，点身份格时显示完整手机号（或身份格直接写完整号码）。**待拍板**（规格 M4 写了这个弹层）。
- 【低】「组件总览」出现在入口里，只能在开发环境出现 → 发版前确认打包时去掉这一行（M9 规定）。
- 【低】「退出登录」字距 0.16em、撑满整行，看着和主按钮一样重 → 去字距；宽度保持，但作为全页最后一个元素，和窗格之间的间距从约 24px 加到 32px，避免误点。

### M6 操作日志（u1-logs）
- 【低】管理员看全部日志却是「暂无操作日志」，演示库里明明有订单、发货操作 → 核对演示数据或接口（不是视觉问题，但截图看着像坏了）。
- 【低】空状态「暂 无 操 作 日 志」字距 0.14em → 去字距。筛选按钮单独占一行靠右是规格写法，没问题。
- 日志详情弹层只读、内容只有一层 → 保持弹层，符合「弹层收紧」。

### M7 员工与岗位（u1-staff）
- 【中】编辑弹层里有两个操作：「保存员工」+「解绑微信」（解绑还要再确认一次），还有管理员开关、模块多选、启用 → 按「多个操作的弹层改整页」应该改成整页「员工资料」，底栏只放「保存员工」，「解绑微信」放进「微信 已绑定」那一行。**待拍板**：这是短表单，留在弹层也说得过去，看用户是否严格执行「多操作 = 整页」。
- 【低】底部按钮叫「新增员工」，其他页面都叫「新建订单 / 新建客户 / 新建产品」；分类叫「新增分类」→ 交给叫法对照表统一（新建 / 新增二选一）。
- 【低】岗位写在卡片右侧的「总数」位置（次要色 12px），多岗位「销售、仓库」挤在右边 → 岗位移到第 3 行，接在手机号后面（「137****0003 · 销售、仓库」），右侧留给「已停用」标记。

### M5 库存查询（u1-inventory）
- 【低】搜索框占位写「搜索花材」，规格是按名称、编码搜 → 改成「搜索花材名称、编码」。
- 【低】这一页的卡片不能点，但和能点的卡片长得一样 → 等全站能点的卡片加了按下态以后就能分开，这一页不加按下态即可，不用另外加标记。
- 其他层级（花材 + 库存加粗靠右 + 编码 · 分类）符合规格，不用改。

### M9 组件总览（u1-gallery）
- 只在开发环境用，不评业务。改造落地后同步更新：去字距、卡片不透明、新的模块首页「待办行 + 入口」样式要加进来，否则组件总览没法拿来验收。

## 二、销售（packages/sales）

主流程：看待办 → 开订单 → 确认 → 改单 → 取消 → 看售后 → 管客户 / 产品 / 目录。

### X1 销售首页（sales-home）
- 【高】「待办」把订单和售后混成一列卡片，但「查看全部」只跳 `orders?status=pending_confirm`（entries.ts `todoSpecs.sales.all`），**待处理售后从「查看全部」进不去** → 按已定方向改成按类分的待办行，放在入口上面：
  - 「待确认订单　1　›」→ 销售订单，状态筛「待确认」
  - 「待处理售后　1　›」→ 客户售后，状态筛「待处理」
  - （可选）「门店申请取消　n　›」→ 销售订单，筛「申请取消」。规格 X2 写了「申请取消不进首页待办」→ **待拍板**。
  每行：图标 + 名称 15px + 数字（墨色加粗，0 时次要色或整行隐藏）+ 箭头；不再放三行卡片，也不需要「查看全部」。
- 【中】入口顺序是 销售订单 / 客户门店 / 产品管理 / 订货目录 / 客户售后（通栏），最常用的「客户售后」被放成最后一格 → 改成 销售订单、客户售后 一排（业务），客户门店、产品管理、订货目录 放后面（资料，单数时最后一格通栏）。
- 【低】顶栏写「销售」，下面身份行又写「销售 · 李敏」，「销售」出现两次 → 模块首页身份行只写名字，或者单模块员工的身份行去掉岗位。
- 【低】售后待办卡片金额位置是一个大「—」→ 改成待办行以后这个问题就没了；如果保留卡片，金额为空时不显示。

### X2 销售订单（sales-orders）
- 【中】卡片里有两个日期且都没标：第 1 行「09-29」是下单日期，第 3 行「2026-09-29」是出货日期，格式还不一样（规格：卡片日期今年写月-日）→ 第 3 行写「出货 09-29」（待确认写「待销售安排」），第 1 行下单日期保留。
- 【低】规格 X2 的状态里有「申请取消」，代码 `statuses: orderStatuses` 没有这一项；而且 6 个标签已经把整行占满，加不下第 7 个 → 「已取消 / 已作废」两个结束类挪进筛选弹层，状态行只留 全部 / 待确认 / 待发货 / 申请取消 / 已发货。**待拍板**。
- 【低】底栏「新建订单」字距 0.16em → 去字距（全站按钮同样处理）。

### X3 订单详情（sales-order-detail / -shipped / 确认、取消弹层）
- 【中】同一页金额两种样子：明细行「¥1,560.00」是衬线加粗，「订单金额 / 发货金额」那一行是无衬线常规字（`info-card` 的 `u-sheet-row__value`），核销记录又是衬线 → 按 02 章第 6 节第 4 条，金额统一 15px 墨色加粗，同一种字体。
- 【中】只有一行明细时，下面再单独一张卡写「订单金额 ¥1,560.00」，两张卡写同一个数 → 规格定了只读详情不删金额，那就把金额行并进「产品明细」卡的最后一行（细线隔开），不单独成卡。
- 【中】信息卡把单号当主标题，客户门店只是普通一行，而销售找单子靠的是门店 → 卡片标题改成「拾光花店 · 文新店」，单号放第二行次要色；「来源 销售新建」放到最后一行。
- 【中】「核销记录」只有日期和金额，没写收了多少、还差多少，标题文字还是写死在 detail.wxml 里（没走 `shared/copy`）→ 改叫「收款记录」（交给对照表定），每行写「09-28　收款核销　¥1,000.00」，后面加一行「未收 ¥488.00」（琥珀浅底）；文字放进 copy。
- 【中】按钮：待确认 = 取消订单 / 修改并确认 / 确认订单（3 个），待发货 = 取消订单 / 修改订单，有申请取消时 = 拒绝取消 / 同意取消，已发货 = 作废订单 / 新建售后，都没超过 3 个。但有申请取消时代码里 `approveCancel` 是次按钮（规格 X3 写的是主按钮），结果底栏两个次按钮、没有主按钮 → 「同意取消」改成主按钮。
- 【低】「修改并确认」和「确认订单」同时出现，说的都是确认 → 按「重复合并」：底栏留「取消订单」（次）+「修改」（次，进表单，提交按钮叫「修改并确认」）+「确认订单」（主）。**待拍板**（等于把按钮名「修改并确认」改成「修改」）。
- 【低】取消弹层在 reasonRequired=false 时只有一句「确认取消这张订单吗？」，却用了半屏弹层，下面空出一大块 → 不需要填原因时改用居中的 `hz-confirm`（同微信 showModal），需要填原因时才用半屏弹层。
- 确认订单弹层（只有一个出货日期）保持弹层，符合方向。

### X4 订单表单（sales-order-form-new / -edit）
- 【中】「添加产品」一次只能加一个：点一行马上关弹层（order-form `onPick` 里直接 `pickSheet: false`），加 5 个产品要开 5 次 → 改成「点行选中（右侧对勾）+ 弹层底栏『添加 n 个产品』」，就是已定的「点卡片选中 + 底栏按钮」。
- 【中】新建时「备注」排在「产品明细」前面，主任务（加产品）被挤到首屏底部 → 顺序改成 客户 / 门店 / 出货日期 → 产品明细 → 备注（单独一张卡，不写组标题）。
- 【中】客户、门店是两个原生下拉，客户多了以后没法搜 → 合成一项「客户门店」，点开整页或弹层带搜索，先选客户再选门店（选门店只是切一层，符合「最多切一层」）。
- 【低】修改时「修改原因」是必填项，但输入框空白、没有提示 → 占位写「必填」；客户门店只读卡放在「订单信息」组外面、没有组标题，和下面的组对不齐 → 并进「订单信息」组，作为第一行只读项。
- 【低】明细行：「− 20 +」「×」「78.00 元」「垃圾桶」挤在一行，「×」只有 12px 很难看出是乘号 → 第 2 行改成「数量 [− 20 +]　单价 [78.00 元]」两段带小标签，垃圾桶移到第 1 行最右边、金额左边。

### X5 客户售后（sales-afters）
- 【高】「新建售后」点开是一个选订单的弹层（pick-sheet），只列订单名、不能搜、不能看订单内容，已发货订单一多就很难找 → 按「有记录的弹层改整页」改成整页「选择订单」：搜索 + 三行卡片，点卡片选中 + 底栏「下一步」进售后表单。另一种做法是去掉这个入口，只从订单详情「新建售后」进。**待拍板**（二选一）。
- 【中】卡片第 3 行「AS-260929-003 · SO-260927-026」是两个单号且都没标 → 写成「AS-260929-003 · 原单 SO-260927-026」；金额为空时写一个大「—」→ 不显示，或者写「待处理」次要色。
- 状态标签 + 行尾筛选按钮符合规格。

### X6 售后详情（sales-after-detail）
- 【中】「原订单 SO-260927-026」是普通文字，不能点 → 做成可点的链接行（墨色 + 箭头），跳到 X3。
- 【低】信息卡 5 行：原订单 / 客户门店 / 出货日期 / 提交日期 / 来源 → 客户门店当标题（同 X3），来源放最后。
- 底栏 关闭售后（次）+ 处理售后（主），处理进整页表单，符合方向。

### X8 客户门店（sales-customers）
- 【高】门店弹层太重：7 个字段（客户、名称、联系人、电话、地址、登录手机号、启用）+「解绑微信」（还有一次确认）+「生成邀请 / 分享」+「保存门店」，有 3～4 个操作，还能跳到微信分享 → 按方向改成整页「门店资料」：字段分组（门店信息 / 门店账号），「邀请下单」「解绑微信」放进「门店账号」组里当行内操作，底栏只放「保存门店」。客户弹层（名称 + 启用）保持弹层。
- 【低】右栏离左栏只有 6px（`u-split__main` 的左内边距用了 `--hz-line-gap`），卡片几乎贴着左栏；右栏抬头「晨曦花艺」和卡片里的文字没有对齐 → 左内边距改成 12px，抬头加上和卡片一样的 16px 内缩，或者让抬头左边和卡片左边对齐。
- 【低】联系人「陈女士」放在卡片右上的「总数」位置 → 改成第 3 行写「陈女士 · 138****8001」，右上留空或放「已停用」。

### X9 产品管理（sales-products）
- 【中】「管理分类」弹层里能改名（切一层）、上移、删除（再确认）、新增，是一个多操作的列表 → 按方向改成整页「产品分类」：一行一个分类，右侧上移 / 删除，底栏「新增分类」，点名称弹出只有名称的小弹层。订货目录的「管理分类」走同一个组件，一起改。**待拍板**（目前只切了一层，没超限，但操作多）。
- 【低】没图的产品是一块空的浅粉方块（70px），4 张卡片看着都像在加载 → 没图时方块中间加图片图标（02 章第 3 节规定的是加载失败时这样显示，没图也这样）。
- 【低】第 2 行「盆 · 配方 1 种花材」只写一个「盆」字看不懂 → 写「单位 盆 · 配方 1 种花材」，或者「按盆卖 · 1 种花材」，交给对照表定。

### X10 产品表单（sales-product-form）
- 【低】「展示」组里放了「产品图」和「启用」，启用不属于展示 → 「启用」挪到「基本信息」最后一行；「展示」组改叫「产品图」，或者不写组标题。
- 【低】「名称」「单位」输入框是空的，没有占位提示 → 名称写「例如 粉玫瑰日常花束」，单位写「束、盆、枝」。

### X11 订货目录（sales-directory）
- 【高】目录项弹层太重：订货信息（编码、分类、订货价、可订开关）+ 配方明细（步进器、垃圾桶、添加花材要切一层）+ 保存时还要再确认；「添加产品」还是先开选产品弹层、再开目录项弹层，等于弹层套弹层 → 改成整页「目录项」：两组卡片（订货信息 / 配方明细 + 琥珀提示），底栏「保存目录项」；「添加产品」改成整页选择（点卡片选中 + 底栏「下一步」）。
- 【中】右栏是 `scroll-view`，右边露出一条灰色滚动条，盖在卡片右边上 → 加 `show-scrollbar="{{false}}"`（同时打开 `enhanced`），右边留出 16px 页边距。
- 【中】「复制目录」放在底栏，和「管理分类」「添加产品」挤成 3 个按钮；规格 X11 说的是「没有目录时，空状态下面放次按钮『从其他客户复制』」。复制弹层里的文案（「复制其他客户目录」「来源客户」「重新预览」「确认复制」「可复制 n 项…」）全写死在 wxml 里，和规格叫法（「从其他客户复制 / 复制目录」）也对不上 → 按钮挪回空状态，文案放进 copy，叫法按规格统一。
- 【低】左栏选中的客户只有亮底和短线，右栏顶部没写当前是哪个客户（客户门店页有）→ 右栏顶部加客户名抬头，两页统一。

## 三、发货（packages/shipping）

主流程：看待发 → 发货 → 看已发。

### H1 发货首页（ship-home）
- 【高】**待办卡片显示了金额（¥1,560.00、¥1,200.00）和「改价」标记**。规格 H3 写明「发货端对所有账号都不显示单价和金额」，要用无金额的数据。原因是 `shippingTodos` 返回的是完整的 `OrderCard`（server/src/modules/sales/sales.service.ts），前端 `salesTodo` 又直接用了 `orderRowOf`（components/hz-module-home/entries.ts）→ 后端发货待办改用无金额的数据（同 H2 列表），前端发货待办不传 `amount` 和 `tags`。同一张单在发货单列表里没有「改价」，首页却有，两边也对不上。
- 【中】按已定方向：页面上没有入口，只有待办卡片 +「查看全部」，没有待办时又换成「发货记录」，入口一会儿有一会儿没有 → 改成
  - 待办行：「今日应发　2　›」→ 发货单筛「待发货」（如果后端分得出逾期，再加一行「已过出货日期　n　›」）
  - 入口：「发货单」「发货记录」两格（「发货记录」= 发货单筛「已发货」），一直显示。
- 【低】标题「待办」对发货人来说太泛 → 用待办行以后，行名直接写「今日应发」。

### H2 发货单（ship-list / ship-list-shipped）
- 【中】发货人最关心出货日期，但卡片第 1 行是下单日期「09-28」，出货日期「2026-09-29」放在第 3 行而且没标 → 第 1 行改成「出货 09-29」+ 状态，第 3 行只留单号；待发货里出货日期还没到的单，第 1 行用次要色写「10-05 出货」，和今天就该发的分开。
- 【低】搜索框只能搜「客户、门店」，发货人常拿单号对 → 加上单号（「搜索单号、客户、门店」，和销售订单一致）。
- 【低】页面叫「发货单」，列的其实是销售订单（SO 号），点进去标题又叫「发货」→ 交给对照表统一（例如列表叫「发货单」，详情叫「发货单详情 / 确认发货」）。

### H3 发货（ship-ship）

## 四、几页共有的问题

1. 【高】**能点的地方都没有按下反馈**：全项目没有一处 `hover-class`，入口格、列表卡片、「我的」入口行、选择行点下去都没反应 → `hz-card`（能点时）、`hz-entry-grid`、`hz-profile` 行、`u-pick-row`、`u-rows__item` 统一加一个按下态 class（底色变深一档，约 100ms）。也正好用来区分能点的卡片和不能点的卡片（库存查询）。
2. 【中】**字距太宽**：按钮 0.16em、入口名 0.2em / 0.14em、空状态 0.14em、顶栏标题 0.1em、弹层标题 0.08em、hub 0.3em → 正文和按钮一律 0；只给衬线顶栏标题留 0.04em。改 `hz-button`、`hz-entry-grid`、`hz-state`、`hz-navbar`、`hz-sheet`、`hz-hub`、`hz-add-button`、`hz-profile` 这 8 处。
3. 【中】**卡片半透明、颜色层次弱**：`--hz-card: #fffbf6db`，墙色 `#f6ebdf`，卡片和墙的对比大约 1.07:1，列表看着像一片 → 卡片改成不透明的 `--hz-paper`；再拉开层次，二选一：(a) 墙色加深一档（大约 `#f1e3d4`）；(b) 墙色不动，卡片加 1px `--hz-hair` 描边。**待拍板**（a 会连带首页背景图的色调）。
4. 【中】**页边距三套**：列表 / 详情 / 表单 16px，模块首页 / 首页 20px，底栏按钮 14px（`hz-action-bar` 的 `9px 14px`），截图里底部按钮左边比上面的卡片多出 2px，从模块首页点进列表，卡片会往外跳 4px → 统一 16px（花众首页、「我的」整屏背景的页面要不要例外留 20px，**待拍板**）。
5. 【中】**字号档太多**：token 有 10/11/12/13/14/15/16/17/18/22 十档，截图里一张卡就用了 12、15 两种，加上详情里的 13、14 → 收成 5 档：11（胶囊、角标）/ 12（次要）/ 14（正文、字段值、标签行）/ 16（卡片主信息、按钮、弹层标题）/ 18（顶栏标题），22 只给门店 / 供应商首页主格。15→16、13→12 或 14 的映射交给开发统一替换。
6. 【中】**金额样式不统一**：明细、卡片的金额用衬线，信息行（订单金额、发货金额）用无衬线常规字 → 一律 15（或收档后 16）墨色加粗，字体二选一（建议都用衬线数字，和首页统一）。
7. 【中】**卡片两个日期没标**：订单 / 发货 / 售后卡片第 1 行是下单 / 提交日期，第 3 行是出货日期，格式也不一样 → 第 3 行的日期一律加「出货」前缀、用月-日格式。
8. 【中】**弹层收紧清单**（按已定方向）：改整页 = 门店资料（X8）、目录项（X11）、新建售后选订单（X5）、添加目录产品（X11）、管理分类（X9/X11，待拍板）、员工资料（M7，待拍板）；保留弹层 = 确认订单、日志详情、客户资料、个人资料（如果保留的话）；只需一句确认的取消 / 关闭改用居中确认框。
9. 【低】**写死的文案**：detail.wxml「核销记录」，directory 的「复制目录 / 复制其他客户目录 / 来源客户 / 重新预览 / 确认复制 / 可复制…」没走 `shared/copy`，违反 02 章第 8 节。
10. 【低】**叫法要交给对照表**：新建 / 新增（员工、分类）；出货日期 / 发货时间；发货单 / 发货 / 订单详情；核销记录 / 收款记录；「客户门店」在表单里拆成「客户」「门店」两个字段，在详情里合成一个。

## 五、需要用户拍板

1. 销售首页要不要加「门店申请取消 n」待办行（规格 X2 目前写的是不进首页待办）。
2. 销售订单状态行放不下「申请取消」：已取消、已作废要不要挪进筛选弹层。
3. 订单详情「修改并确认」按钮要不要改叫「修改」（进表单后提交按钮仍叫「修改并确认」）。
4. 客户售后「新建售后」：改成整页选订单，还是去掉这个入口、只从订单详情进。
5. 管理分类（产品 / 订货目录）、员工编辑这两个弹层要不要改整页（只切了一层，但操作多）。
6. 「我的」里的「个人资料」要不要去掉，并进身份格。
7. 颜色层次：墙色加深一档，还是卡片加描边。
8. 页边距统一 16px 时，铺满背景图的页面（花众首页、「我的」）要不要例外保留 20px。
9. 「已发货」订单的卡片 / 详情是否给销售显示「未收 ¥…」（牵涉 C4/W3 那种金额显隐的老问题，规格没写）。
