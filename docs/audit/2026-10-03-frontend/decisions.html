需要用户拍板

  1. 新建还是新增：按钮里「新建」有 12 处，「新增」有 3 处，日志全写「新增」。建议统一用「新建 + 对象」（档案和单据都这样写，日志跟着改）。也可以全部改成「新增」（金蝶、用友这类 PC 端 ERP 的习惯）。
  2. 编辑还是修改：建议全部用「修改」（日志和单据已经是修改，改动最小）。另一种做法是档案用「编辑」、单据用「修改」，这样有两种规则要记。
  3. 销售新建订单的提交按钮：规格定的是「确认订单」（销售新建的单直接就是待发货，叫确认也说得通），但和详情里定出货日期的「确认订单」同名。另一种做法是改成和门店一样的「提交订单」。采购单的「确认下单」要不要一起改，也请一并定。
  4. 门店端的「结算 / 去结算」：门店端不在线付钱，「结算」容易让人以为要付款。可以保持现状，因为这是微信商城的常见叫法。也可以改成「去下单 → 确认订单页 → 提交订单」。如果门店底栏按已定方向改成「首页 / 订货 / 我的」，这条要一起定。
  5. 填报邀请还是询价 / 报价：规格叫「填报邀请 / 填报」，常规采购叫法是采购发「询价单」、供应商「报价」。不过这里供应商填的是供货数量和单价，结果会直接生成采购单，比单纯报价多一步。建议保留规格叫法，按表一第 1 条统一。
  6. 财务的「客户对账 / 供应商对账」：可以保留（门店、供应商端也都叫「对账」，三端一个词）。也可以改成 ERP 常见的「应收 / 应付」或「客户往来 / 供应商往来」。建议保留「对账」。
  7. 手工入库单 / 手工出库单还是其他入库单 / 其他出库单：后一种是金蝶、用友的标准叫法，前一种是规格书现在的叫法。建议保留「手工」，仓库员工更容易懂。
  8. 目录项还是目录产品：02 §8 已经定了「保存目录项」，但弹层标题和空状态用的是「目录产品」。建议统一成「目录产品」（销售员想的是产品），按钮相应改成「保存目录产品」。如果维持「目录项」，那弹层标题和空状态要跟着改。
  9. 采购单的留痕叫「变更记录」还是「改单记录」：03 章和 02 章写的是「改单记录」，06 章 C4、P2 写的是「变更记录」。建议和订单统一成「变更记录」（卡片标记仍叫「改单」），需要改 03 章多处。
  10. 「改单价」还是「改价」：按钮和日志用「改单价」，标记、记录、原因、确认按钮都用「改价」。建议统一成「改价」。如果觉得「改单价」更清楚（不会误以为是改总价），那就把标记、记录、原因、确认按钮都改成「改单价」。

四、跨页共性问题

  1. 【高】弹层太重，弹层里套弹层。 这类弹层有：C6 填报详情、F3 发货单（含售后、收款）、F8/F6 收付款详情（payment-panel）、C2 需求来源、C8 供应商编辑。统一规则：有记录、能跳到别处、有两个以上操作的，都改成整页；弹层里只留一层表单（原因、退款、选花材、选供应商）。F6 已经把单据改成整页了，F3 要跟着对齐。
  2. 【高】模块首页结构。 三个模块首页都是入口在上、待办卡在下；仓库首页的待办已经被挤到首屏外面。统一改成：身份行 → 按类分的待办行（图标 + 名称 + 数量 + 金额 + ›，点了进入已经筛好的列表）→ 入口格（每个模块不超过 6 个）。待办行的数据可以用现有 todos 接口按 kind 汇总。「查看全部」不要了，每一类各自是一个入口。
  3. 【高】卡片透明，层次不够。 --hz-card 是 86% 不透明的亮格，铺在 #f6ebdf 的墙上，在列表页几乎和背景融成一片（各列表截图都能看到）。 → 卡片改成实底 --hz-paper，墙色压深一档，或者给卡片加一条 hair 描边。首页入口格不动，按已定方向保留和背景融为一体的样子。
  4. 【中】字距太宽。 现在加了字距的地方：按钮 0.16em、入口名 0.2em、导航标题 0.1em、空状态 0.14em、添加按钮 0.1em、弹层标题 0.08em、hz-hub 0.3em。截图里「新 建 采 购 单」「确 认 收 款」字都是散开的。 → 全部改成 0，只有 logo 字可以保留。
  5. 【中】页面边距不统一。 模块首页 20pt，列表和详情 16pt，底栏按钮约 14pt，所以首页卡片、列表卡片和底栏按钮左边对不齐（比较 pur-home 和 pur-orders 两张截图）。 → 统一用 16pt，底栏左右也改成 16pt。
  6. 【中】字号和金额样式太杂。 同一页里，卡片金额用衬线约 20px，信息卡合计用无衬线 14px 常规，明细行金额又是衬线（C4 最明显）。 → 字号收成 4 档：17 标题、15 重点（对象名、金额加粗）、14 正文、12 辅助。金额统一一种字体，「合计、未收、待付」这些关键数字最重。
  7. 【中】关键数字没有放在关键位置。 财务列表最该看的未收、待付用的是灰色小字；客户对账卡上最大的数字是发货金额；出入库记录的数量变化反而很弱。 → 每张卡右侧的大数字必须是这个角色最关心的数：财务看未收或待付，仓库看数量，采购看金额。
  8. 【中】状态标签太多。 C3、W2 有 6 个，F6 有 5 个，F8 叠了两排。 → 一行最多 4 个：全部 + 待办类 + 完成类，结束类和作废类收进筛选。
  9. 【中】选择操作。 C2 有勾选框和底栏，是对的；W8 用开关做多选，C2 邀请先弹一个选供应商的弹层。 → 统一成点卡片选中、底栏按钮写清数量，选供应商这一步并到下一页去做。
  10. 【低】图标重复，分不出功能。 手工入库和手工出库同一个图标；供应商对账和客户对账同一个图标；报损用了售后的图标。
  11. 【低】叫法问题（交给对照表）。 「待收」和「采购收货」；「邀请供应商 / 供应商填报 / 发出邀请」；「未付款 / 待付 / 未付」；「预收（未核销）」和「可用预付」；「原因（选填）」用作入库备注；「填入」；「来源：花众采购下单」。
  12. 已知 bug 的印证情况： 没有下拉刷新和翻页加载提示，所有列表截图都看不到加载中或「已全部加载」（数据都只有一屏）；其他已知 bug 在这批截图里没有出现。

五、需要用户拍板的取舍

  1. 采购单收货前要不要显示应付、已付、待付和财务状态（C4/W3，记忆里的未决问题）。建议收货前只显示采购金额，现在的「财务 无需付款」会误导人。
  2. 库存（W11）和花材（W14）要不要合并成一个页面。 建议合并：一个列表同时显示库存数量；管理功能（新建、分类）给有权限的人放在同一页底栏。
  3. 仓库首页入口怎么精简。 「出入库记录」放进库存或花材详情，「出库分类」放进手工出库单，「待收」和待办行要不要重复保留入口。建议待办行代替「待收」入口；不想去掉的话就改名「采购收货」。
  4. 采购首页要不要加「缺货花材 n」这一类待办。 这要后端在 todos 里加一类。不加的话采购首页只有「待填报」一类，信息偏少。
  5. 财务待办里的「预收」算不算待办。 建议只算「既有预收余额又有未收」的客户，只有预收、没有未收的客户不进待办（拾光花店这种情况是处理不了的）。
  6. 收货页要不要加明确的「拒收」按钮。 规则是实收全 0 等于拒收，建议做成显式按钮，提交前确认一次。
  7. 供应商（C8）要不要从编辑弹层升级成「供应商详情」整页，并在里面链到在途采购单、填报邀请、对账。
  8. 收付款方式放在财务首页入口，还是挪到「我的」或设置里。
  9. 需求来源（C2）是否改整页。 它只是看一眼的内容，但里面有记录、能跳转。按已定规则应该改；如果想保留「快速看一眼」的体验，可以只把里面的跳转改成「先关弹层再进去」。

三、跨页共性问题

  1. 卡片半透明，层次不分【高】：--hz-card 是亮格 86%，放在 #f6ebdf 墙上，订单、采购单、对账卡和墙面几乎同色；对账格的内格又是亮格放在卡片上，完全看不出分格。→ u-card 改成不透明的 --hz-paper，加 1px --hz-hair 描边，或者把墙色再压深一档；卡内的二级格子（对账格、结算条）用墙色或 --hz-tint，形成「墙 → 卡 → 格」三层。首页窗格保持透明，不受影响。
  2. 宽字距【中】：hz-button 0.16em、hz-hub 名称 0.3em / 0.12em、hz-navbar 0.1em、hz-state 0.14em、hz-add-button 0.1em、hz-sheet 0.08em、hz-profile 0.06em、hz-entry-grid 0.2em / 0.14em → 全部改成 0（衬线标题最多 0.02em）。
