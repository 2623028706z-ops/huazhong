## 修复结果

| 审计项 | 实现与关键决定 |
|---|---|
| 全账通知超限导致业务回滚 | `common/changes.ts` 按 UTF-8 字节拆分主题及过大作用域，每包不超过 7,999 字节；`WriteService.finish` 在同一事务内发送全部包。保留主题、版本及接收者范围，提交失败不投递任何包，不截断历史详情刷新。 |
| 日志写入与读取契约不一致 | `LogEntry.before/after` 收紧为显示字符串记录；付款、退款、分类、目录复制、收货、改价、退货、手工仓库单及盘点均构造显示值。读取端规范化当前库中已产生的字符串、数组和嵌套对象，不迁移旧系统。 |
| 采购复核与确认之间发生变化 | 所有公共业务写事务先取得共享 advisory 事务锁；采购单和邀请新建先取得同一锁的独占模式，覆盖复核至提交。普通写入仍并发，确认窗口会暂时阻挡其他写入，读接口不受影响；不先持有行锁或共享锁再升级。允许超缺口购买的规则不变。 |
| 售后处理与作废反向锁序 | 先读取归属指针，统一客户 → 订单 → 售后行锁，锁定后复查可见性、版本及动作。处理、关闭、作废共用同一路径，不因旧请求反向等待客户锁。 |
| 门店改单 STALE 无法恢复 | 保留数量和备注，提供显式「重新核对」，读取最新订单、动作和目录；仍可编辑才更新草稿版本和价格，保留并标出停用产品。普通重载不升级版本，重核后不会自动提交，需再次确认。 |
| 数值契约超出存储及计算范围 | 保持当前 INTEGER 表结构，以 `STORED_INT_MAX` 统一持久化金额、单价、数量及售后保存总额的技术上限，越界返回字段错误。账款、库存、盘点、需求及单位汇总检查精确整数；SQL 先扩宽乘法，金额汇总不再强转 INTEGER。派生值可超过单列上限，但不可超出 JS 安全整数。复核差额用 BigInt 计算后检查，避免中间加减舍入。 |

同步说明位于 `04-data-model.md`、`05-api.md`、`06-pages.md`。新增文案已重新生成小程序字体；没有增加数据库迁移或业务额度。
